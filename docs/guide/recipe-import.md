# Импорт техкарт из Excel — инструкция технолога

«Производство → Технолог → Техкарты» → **«Импортировать технологические карты из Excel»**. Импортирует технолог (право «Производство:
рецептуры»). Импорт ничего не утверждает и не меняет склад: он создаёт **черновики техкарт**, дальше — обычный маршрут: распределение по
этапам, «На утверждение», утверждает другой технолог или начальник производства.

## Какой файл подходит

Лист с рецептурами устроен так:

- **Строка-заголовок:** «Артикул | Наименование сырья | Ед.изм.».
  - Правее — продукты, по столбцу на продукт.
  - Над названием продукта — его артикул.
- **Сырьё — по строкам**, норма — в ячейке на пересечении строки сырья и столбца продукта.
- **База норм** — подпись выше заголовка «1 тонна учун кг»: нормы на 1 тонну, то есть на 1 000 кг выхода. Нет подписи — база не
  определена, карта не создаётся.

Учитываются все листы. Листы без такого заголовка (выгрузки остатков и продаж, скрытые служебные) пропускаются — это видно в сводке. Продукт
левее колонки «НАХР», столбец «Итого», пустые строки внизу листа — тоже учтены.

## Шаги

1. **Загрузить файл .xlsx** (до 25 МБ).
   - Тот же файл второй раз открывает прежнюю загрузку, новая не создаётся.
   - Изменённый файл — новая загрузка: в ней видно, что изменилось.
2. **Сводка:**
   - рецептур с составом, готовы, нужна проверка, черновики созданы;
   - норм в Excel, нулей, отрицательных;
   - найдено на складе, ошибки и текст в нормах, полуфабрикаты.
3. **Отборы:** «Готовы», «Нужна проверка», «Без изменений», «Дубли и пустые», «Черновики созданы», «Исключены». У рецептуры видна первая
   причина, почему она не готова.
4. **Рецептура — построчная сверка «Excel → техкарта»:**
   - ячейка, сырьё и единица как в Excel;
   - значение как в Excel (формула — под значением);
   - позиция склада и как найдена;
   - что уйдёт в техкарту;
   - итог строки и замечания.
5. **Решения технолога** (кто и почему — в истории загрузки):
   - **«Сопоставить»** — выбрать позицию склада для строки без позиции. Запоминается: следующие загрузки найдут её сами.
   - **«Норма вручную»** — для ячейки с ошибкой, текстом вместо числа или больше 6 знаков после запятой. Только с причиной, до 6 знаков.
   - **«Не переносить»** — с причиной.
   - **«Подтвердить единицу»** — если в Excel единица не указана.
   - Код техкарты — для продукта без артикула. Товар Linko — подтвердить предложенный или выбрать. «Создавать техкарту» — снять, чтобы
     исключить столбец.
6. **«Артикулы, которых нет в каталоге склада»** — список с числом рецептур. Сопоставить артикул с позицией — сразу во всех строках
   загрузки. Новые позиции заводят в каталоге склада — сами они не создаются. Потом — «Проверить заново».
7. **«Создать черновики готовых»** (или отмеченных) → подтверждение → черновики.
   - **Новая техкарта** — если кода ещё нет.
   - **Черновик новой версии** — если у кода есть утверждённая версия с другим составом. Утверждённая не меняется.
   - Двойное нажатие и второе окно не создают второй черновик.

## Что переносится и как

| В Excel | В техкарте |
|---|---|
| Норма больше нуля | Строка «на выход рецептуры» с той же нормой — без округления (число как показывает Excel, до 15 значащих цифр) |
| База «1 тонна учун кг» | Выход 1 000 кг; название и выход — название продукта из Excel |
| Единица сырья | Та же. Не совпадает с единицей позиции и не переводится (кг ↔ г ↔ т, единица закупки) — ручная проверка |
| 0 | Не входит в состав |
| Отрицательная норма (возвратные отходы) | Не переносится (в техкарте норма больше нуля) — предупреждение, перечислено в комментарии карты |
| Ошибка формулы (#REF!, #DIV/0!, #N/A…), текст вместо числа («25,542»), ИСТИНА/ЛОЖЬ | Не подставляется — ручная проверка |
| Больше 6 знаков после запятой | Не округляется — ручная проверка (техкарта хранит 6 знаков) |
| Компонент дважды в одной рецептуре | Не складывается — ручная проверка |
| Этапы | В Excel их нет: карта без этапов, с пометкой «Требуется распределение по этапам технологом». Этапы, выход, влажность, брак не придумываются |
| Продукт, который входит в другие рецептуры (глазурь, начинка, киём…) | Полуфабрикат: позиция склада выхода — позиция с тем же артикулом. Её нет в каталоге — ручная проверка. В других картах он — обычная позиция склада, его сырьё дважды не списывается |
| Тот же артикул в двух столбцах с тем же составом | Дубль — карта одна |
| Тот же артикул с другим составом или названием | Ручная проверка: оставьте один столбец |

Проверка, не меняющая норм:
- **Сумма сырья «Вес» и итог листа.** Сырьё с отметкой «Вес» (1 или ИСТИНА) складывается и сравнивается с итогом «1 тонна учун кг».
  Расхождение — предупреждение; ни норма, ни итог не исправляются.
- **Нет сырья, входящего в массу**, — предупреждение «проверьте, заполнен ли столбец».

**Сопоставление со складом:**
1. Точный артикул.
2. Сопоставление, запомненное сотрудником.
3. Ручное.

Похожие названия не объединяются. Если по артикулу в каталоге другое название, это показывается «для сведения».

**Товар Linko:** точный код — сразу. Совпадение по номеру без буквенного префикса («K-304» → «304») — только предложение, подтверждает
технолог.

## После создания

Черновик открывается из списка «Созданы» или из «Техкарт»:
1. В карточке — пометка «Импортирована из Excel: состав без этапов».
2. Технолог распределяет компоненты по этапам (или оставляет нормы на выход) и отправляет на утверждение.
3. Утверждает другой технолог или начальник производства.

Утверждённая карта работает как любая другая:
- задания и потребность в сырье;
- выдача годных партий по FEFO, смены, возврат, закрытие и сверка нормы и факта;
- оприходование выхода полуфабриката партией.

## API

`/api/production/recipe-imports`:

| Запрос | Что делает |
|---|---|
| `GET` | Список загрузок |
| `POST` (multipart `file`) | Загрузить; тот же файл (SHA-256) — `existing: true` |
| `GET {id}` | Сводка и рецептуры |
| `GET {id}/recipes/{rid}` | Сверка рецептуры, что изменится в карте, что изменилось в файле |
| `PUT {id}/recipes/{rid}` | Код, товар Linko, «создавать техкарту» |
| `PUT {id}/lines/{lineId}` | Позиция склада, решение (`Exclude`, `ManualValue`, `UnitConfirmed`, `None`), норма, причина |
| `POST {id}/map` | Артикул → позиция склада во всей загрузке (запоминается) |
| `GET {id}/missing` | Артикулы без позиции склада |
| `POST {id}/rematch` | «Проверить заново» |
| `POST {id}/apply` | Создать черновики (`recipeIds` — выбранные, пусто — все готовые) |

## База данных

Миграция `RecipeImport` — только новые таблицы схемы `production`:
- `RecipeImports` — загрузка: имя, SHA-256 (уникальный), размер, листы;
- `RecipeImportRecipes` — рецептура файла: ключ «лист | артикул», столбец, база, итог и потери как в файле, код, Linko, позиция выхода,
  статус, замечания, отпечаток состава, созданная техкарта;
- `RecipeImportLines` — ячейки: значение точно (`numeric`), исходная запись, формула, позиция склада, решение технолога;
- `RecipeImportItemMaps` — запомненные сопоставления «артикул и название → позиция склада».

Таблицы техкарт, склада и Linko не меняются. Черновики создаются существующими `ProductionRecipeService.CreateAsync` и новой версией с
составом — с теми же проверками и историей.
