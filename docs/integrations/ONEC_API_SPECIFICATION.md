# API 1С:Бухгалтерии для OneBase — спецификация (проект v1)

Документ для **VENKON GROUP**: какой HTTP-сервис нужен в 1С:Бухгалтерии для Узбекистана, чтобы OneBase забирал бухгалтерские
данные. Это **предложение OneBase**, а не описание уже существующего API. Адреса, имена параметров и формат можно поменять
по согласованию — OneBase подстроит свой адаптер (`OneCHttpDataProvider`).

Вопросы, на которые нужен ответ VENKON, — в [ONEC_VENKON_QUESTIONS.md](ONEC_VENKON_QUESTIONS.md).

---

## 1. Принципы

| Правило | Что это значит для 1С |
|---|---|
| Только чтение | Все методы — `GET`. OneBase ничего не записывает, не проводит и не меняет в 1С. |
| Направление 1С → OneBase | Обмен инициирует OneBase (сервер 192.168.9.168) по расписанию, раз в 30 минут. 1С сама ничего не отправляет. |
| Стабильные идентификаторы | У каждой записи — `id`: уникальный идентификатор ссылки 1С (UUID). Он не меняется при правке и перепроведении. |
| Изменения с прошлого раза | Метод `GET /changes` отдаёт всё, что изменилось после прошлой выгрузки, включая удаления и отмену проведения (рекомендуем план обмена 1С). |
| Пакеты | Списки отдаются страницами до 1 000 записей, с курсором следующей страницы. |
| Полная аналитика | Проводки отдаются со всеми субконто (вид, ссылка, код, наименование), валютой, валютной суммой и количеством. |
| Без пересчёта | Суммы и курсы — как в 1С. OneBase не пересчитывает исторические операции по текущему курсу. |

## 2. Подключение

### 2.1. Адрес

HTTP-сервис 1С, опубликованный на веб-сервере (IIS или Apache) **только во внутренней сети**:

```
https://<адрес сервера 1С>/<имя публикации>/hs/onebase/v1/<метод>
```

Пример (не подтверждён): `https://192.168.9.141/buh/hs/onebase/v1/ping`. Точный адрес, порт и имя публикации сообщает VENKON.

### 2.2. Безопасность сети

- Доступ к публикации — только с адреса OneBase **192.168.9.168** (правило брандмауэра Windows и/или веб-сервера).
- Публикация не выводится в интернет.
- Только HTTPS (TLS 1.2+). Сертификат: выданный внутренним центром сертификации или самоподписанный — тогда его файл
  (`.crt`, PEM) передаётся администратору OneBase, и OneBase доверяет ему явно. Проверка сертификата в OneBase **не отключается**.

### 2.3. Авторизация

Основной вариант — **HTTP Basic** отдельного пользователя информационной базы, например `OneBase_ReadOnly`:

- права только на чтение нужных справочников, документов и регистров и на вызов HTTP-сервиса `onebase`;
- без интерактивного входа, без права записи и проведения;
- пароль передаётся администратору OneBase отдельно (не в переписке с этим документом).

Допустим и токен: заголовок `Authorization: Bearer <токен>` — если VENKON удобнее так. OneBase поддерживает оба варианта.

### 2.4. Версия API

- Версия в адресе: `/v1/`. Несовместимые изменения — только в `/v2/`; `/v1/` работает до согласованной даты отключения.
- Совместимые изменения (новые необязательные поля, новые методы) — без смены версии. OneBase игнорирует неизвестные поля.
- `GET /ping` возвращает `apiVersion` — полную версию (`1.0`, `1.1`…).

### 2.5. Ограничения нагрузки

| Параметр | Значение (предложение) |
|---|---|
| Одновременных запросов от OneBase | не больше 2 |
| Запросов в секунду | не больше 5 |
| Размер страницы | по умолчанию 500, максимум 1 000 |
| Время ответа | до 60 секунд на страницу; дольше — OneBase считает запрос неудачным и повторит его |

Если 1С перегружена или идёт регламентная операция (закрытие месяца, обновление конфигурации), сервис отвечает
`503` или `429` с заголовком `Retry-After: <секунды>` — OneBase подождёт и повторит.

## 3. Общие правила формата

- Кодировка UTF-8, `Content-Type: application/json; charset=utf-8`.
- Даты без времени — `"2026-10-15"`. Дата и время — ISO 8601 **с часовым поясом**: `"2026-10-15T14:30:00+05:00"`.
- Суммы — числа JSON с точкой (`1250000.00`), не строки; не больше 2 знаков после запятой. Количество — до 3 знаков,
  курс — до 4 знаков.
- Пустые значения — `null` или поле отсутствует. Пустая ссылка 1С — `null`, а не `"00000000-0000-0000-0000-000000000000"`.
- Строковые значения перечислений 1С отдаются как есть (например, `"Активный"`), а для полей, где OneBase ждёт код
  (`kind`, `type`), — согласованным кодом из этого документа.

### 3.1. Общие поля объектов

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | string (UUID) | да | Уникальный идентификатор ссылки 1С. |
| `version` | string | да | `ВерсияДанных` объекта: меняется при любой записи объекта. По нему OneBase понимает, что запись изменилась. |
| `modifiedAt` | string (дата-время) | желательно | Когда объект записан последний раз. Если 1С этого не хранит — поле не отдаётся, изменения берутся из `/changes`. |
| `deletionMark` | bool | да | Пометка удаления. |
| `code` | string | для справочников | Код справочника. |
| `name` | string | для справочников | Наименование. |

### 3.2. Страницы

Запрос: `?limit=500&cursor=<курсор>`. Ответ:

```json
{
  "apiVersion": "1.0",
  "items": [ ... ],
  "page": { "limit": 500, "nextCursor": "eyJkIjoiMjAyNi0xMC0xNSIsImkiOiI0ZjIy...\"}", "hasMore": true },
  "totals": { "count": 12840, "amount": 9876543210.55 }
}
```

- `nextCursor` — непрозрачная строка: OneBase передаёт её без изменений в следующий запрос. `hasMore=false` — страниц больше нет.
- Порядок строк стабилен между страницами (например, по дате и `id`) — строка не пропадает и не повторяется при листании.
- `totals` — по запросу `includeTotals=true`: число записей и сумма за весь отбор (для документов — сумма документов,
  для проводок — сумма проводок в валюте учёта). OneBase сверяет с загруженным — это контроль полноты загрузки.

### 3.3. Общие фильтры

| Параметр | Тип | Где | Описание |
|---|---|---|---|
| `organizationId` | UUID | документы, проводки, остатки | Одна организация. Без параметра — все организации базы. |
| `from`, `to` | дата | документы, проводки, курсы | Период по дате документа / периоду проводки, обе границы включительно. |
| `modifiedSince` | дата-время | справочники, документы | Только изменённые после момента (если 1С хранит `modifiedAt`). |
| `includeTotals` | bool | списки | Добавить `totals`. |

### 3.4. Ошибки

Любой ответ с кодом 4xx/5xx — JSON:

```json
{ "error": { "code": "invalid_parameter", "message": "Параметр from: дата должна быть в формате ГГГГ-ММ-ДД", "field": "from" } }
```

| HTTP | `code` | Когда | Что делает OneBase |
|---|---|---|---|
| 400 | `invalid_parameter` | неверный параметр | не повторяет, записывает ошибку |
| 401 | `unauthorized` | нет или неверная авторизация | останавливает обмен, показывает «Ошибка авторизации» |
| 403 | `forbidden` | у пользователя нет прав на объект | записывает ошибку по сущности, остальное продолжает |
| 404 | `not_found` | нет объекта или метода | записывает ошибку |
| 409 | `cursor_expired` | курсор `/changes` устарел (изменения уже удалены) | переходит на полную сверку по периоду |
| 429 | `rate_limited` | превышен лимит | ждёт `Retry-After` |
| 500 | `internal_error` | ошибка 1С | повторяет с нарастающей паузой |
| 503 | `unavailable` | регламент, обновление, база заблокирована | ждёт `Retry-After` и повторяет |

Текст `message` не должен содержать паролей и персональных данных.

```json

  "apiVersion": "1.0",

  "infobaseName": "Бухгалтерия (рабочая)",
```

### 4.7. `GET /warehouses`, `GET /departments`, `GET /references`

Склад и подразделение: общие поля, `code`, `name`, `parentId`, `isGroup`, `organizationId` (если склад привязан
к организации), для склада — `kind` (`wholesale` / `retail` / `production` / `other`, если есть).

`GET /references?kind=<вид>` — прочие справочники, которые встречаются в субконто: `cash_flow_items` (статьи ДДС),
`cost_items` (статьи затрат), `bank_accounts`, `cash_desks`, `batches` (партии), `fixed_assets`, `other_income_expense`.
Поля: общие, `code`, `name`, `parentId`, `isGroup`, `attributes` (объект с прочими реквизитами, необязательно).

### 4.10. `GET /entries` — проводки

Проводки отдаются **наборами по документу-регистратору**: один элемент `items[]` — все проводки одного документа.
Страница никогда не разрывает набор. Если документ перепровели — набор приходит целиком заново, и OneBase заменяет
прежние проводки этого документа. Если проведение отменено — набор приходит пустым (`entries: []`).

Отбор: `?organizationId=…&from=2026-10-01&to=2026-10-31&limit=500`.

### 4.11. `GET /balances` — остатки и обороты

Оборотно-сальдовая ведомость за месяц по счетам с разворотом по субконто:
`?organizationId=…&period=2026-10&accounts=4010,6010,5110&subconto=true&limit=500`.

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `period` | string `ГГГГ-ММ` | да | Месяц |
| `organizationId` | UUID | да | |
| `account` | string | да | Счёт |
| `subconto` | array | да (может быть пустым) | Как в проводках |
| `currency` | string | нет | Валюта (для валютных счетов — отдельная строка на валюту) |
| `opening`, `turnover`, `closing` | object | да | `{ "debit": 0, "credit": 0, "currencyDebit": 0, "currencyCredit": 0, "quantityDebit": 0, "quantityCredit": 0 }` (`turnover` — обороты за месяц) |

перезапросит остатки с этого месяца по текущий.

### 4.12. `GET /changes` — изменения

Рекомендуемая реализация — **план обмена 1С** (например, `OneBase`) с одним узлом для OneBase: регистрация изменений
справочников, документов (включая перепроведение и отмену проведения), курсов валют и удалений объектов.

Запрос: `?cursor=<номер>&limit=500`. Первый запрос — без `cursor`: 1С отдаёт текущий номер и пустой список (дальше
OneBase загружает историю отдельно, по периодам).

```json
{
  "apiVersion": "1.0",
  "items": [
    { "seq": 10231, "entityType": "document", "id": "e7c1…", "organizationId": "5b9e…", "deleted": false,
      "data": { …документ как в /documents…, "entries": [ …проводки как в /entries… ] } },
    { "seq": 10232, "entityType": "counterparty", "id": "c42…", "deleted": false, "data": { … } },
    { "seq": 10233, "entityType": "document", "id": "f90…", "organizationId": "5b9e…", "deleted": true, "data": null },
    { "seq": 10234, "entityType": "exchange_rate", "id": "USD:2026-10-16", "deleted": false, "data": { … } }
  ],
  "page": { "limit": 500, "nextCursor": "10234", "hasMore": false }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `seq` | int | Сквозной номер изменения, возрастает |
| `entityType` | string | `organization`, `account`, `counterparty`, `contract`, `currency`, `exchange_rate`, `warehouse`, `item`, `department`, `reference`, `document` |
| `id` | string | Идентификатор объекта (для курса — `ВАЛЮТА:ДАТА`) |
| `deleted` | bool | Объект удалён из базы (не пометка — физическое удаление) |
| `data` | object | Объект целиком, как в методе сущности; у документа — с проводками (`entries`) |

**Подтверждение приёма.** Запрос с `cursor=N` означает, что OneBase сохранил всё до `seq = N` включительно. 1С может
после этого очищать зарегистрированные изменения до `N`. Если OneBase повторит запрос с тем же курсором (например, после
сбоя), 1С отдаёт те же изменения ещё раз — повтор безопасен.

Если план обмена сделать нельзя — допустим вариант `modifiedSince` во всех методах. Тогда 1С должна хранить момент
изменения (`modifiedAt`) и отдельно журнал удалений (`GET /deletions?since=`).

## 5. Как OneBase загружает данные

| Этап | Методы | Порядок |
|---|---|---|
| Проверка | `/ping` | при каждом запуске; смена `infobaseId` останавливает загрузку |
| Справочники | `/organizations`, `/accounts`, `/currencies`, `/counterparties`, `/contracts`, `/warehouses`, `/departments`, `/items`, `/references` | целиком при первой загрузке, дальше — по `/changes` |
| История | `/exchange-rates`, `/documents`, `/entries`, `/balances` | по месяцам выбранного периода, страницами по 500 (размер настраивается); после каждого месяца — сверка с `totals` |
| Изменения | `/changes` | каждые 30 минут; курсор сохраняется только после записи пакета в OneBase |
| Остатки | `/balances` | текущий месяц — при каждом обмене; прошлые — если в них были изменения |

Повторная загрузка того же периода или той же страницы не создаёт дублей: OneBase узнаёт запись по `id` (у проводки —
`registrar.id` + `lineNumber`) и `version`.

## 6. Что OneBase делает с удалением и отменой

| Событие в 1С | Что приходит | Что делает OneBase |
|---|---|---|
| Документ исправлен и перепроведён | документ и набор проводок с новой `version` | обновляет документ, заменяет проводки, пишет изменение в журнал |
| Отмена проведения | документ `posted=false`, `entries: []` | документ «не проведён», проводки помечаются удалёнными (история сохраняется) |
| Пометка удаления | `deletionMark=true` | запись помечается, в отчётах не участвует, история сохраняется |
| Физическое удаление | `/changes`: `deleted=true` | запись помечается удалённой, история сохраняется |
| Снятие пометки, повторное проведение | новые данные | запись восстанавливается |

## 7. Что не нужно отдавать

- Пароли, ключи ЭЦП, настройки обмена с банками и налоговой.
- Персональные данные сотрудников (ПИНФЛ, паспорта, начисления по сотрудникам) — если не будет отдельного решения.
  Проводки по зарплате достаточно отдавать без субконто «Сотрудники/Физлица».
