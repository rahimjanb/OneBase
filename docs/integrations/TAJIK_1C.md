# 1С Таджикистан → OneBase (продажи дилера)

Продажи дилера в Таджикистане и остаток его склада из его 1С. Только чтение: OneBase делает два GET-запроса и в 1С ничего не пишет.
В отчётах — «Продажи → Экспорт и опт» (карточка сверху) и «Продажи → Экспорт → Таджикистан» (`/sales/export/tajikistan`).

## API дилера (документ «API (1).pdf», 26.11.2026)

| Метод | Что отдаёт |
|---|---|
| `GET /sales?token=…&from=ДД-ММ-ГГГГ` | строки расходных накладных с даты: `number`, `date` (ДД-ММ-ГГГГ), `customer` (точка), `manager` (ТП), `code`, `name`, `qty`, `price`, `amount`, `discount`, `discountPercent` |
| `GET /sklad?token=…` | остаток: `code`, `name`, `warehouse`, `qty` |

Ответ — `{"status":"ok","count":N,"items":[…]}`; неверный ключ — `403 {"status":"error","error":"Access denied…"}`.
Что выяснилось на реальном API:

- данные — с 03.11.2026; `from` в неверном формате API молча заменяет на 01.11.2026 (поэтому строки раньше окна отбрасываются);
- региона и идентификаторов строк в ответе нет; накладная — номер + дата, строка — порядок в ответе;
- адрес — `http://`, ключ — в адресе запроса: он идёт по интернету открытым текстом (на странице интеграции — предупреждение).

## Настройка

«Настройки → Интеграции → Продажи → 1С Таджикистан»: адрес (по умолчанию `http://62.60.246.93`), ключ доступа (шифруется Data Protection,
наружу — только последние 2 символа), интервал (30 мин), дата начала истории (01.11.2026). Запасной вариант — переменные `TajikSales__BaseUrl`,
`TajikSales__Token` (сохранённое на странице главнее). `TajikSales__WorkerEnabled=false` — без загрузки по расписанию (стенды, тесты).
У HttpClient этого API журнал запросов выключен (`RemoveAllLoggers`) — иначе адрес с ключом попал бы в логи.

## Загрузка (`TajikSyncService`)

- Окно — с 1-го числа прошлого месяца (не раньше даты начала истории); первая загрузка и раз в сутки после 02:00 (Душанбе) — вся история.
- Новая накладная — добавляется; изменённая — прежние строки получают `RemovedAt`, новые добавляются; пропавшая из окна — `RemovedAt`.
  Ничего не удаляется. В отчётах — только строки без `RemovedAt`.
- Защита от неполного ответа: `count` ≠ числу строк — ошибка; накладных меньше половины от сохранённых в окне — ошибка, ничего не меняется;
  есть нечитаемые строки — пропавшие не помечаются.
- Остаток — снимок дня (`tajik.StockItems`, ключ — дата, товар, склад): сегодняшний заменяется, прошлые дни остаются. Не загрузился остаток —
  запуск «частичный», продажи сохранены.
- Схема `tajik`: `SaleLines`, `StockItems`, `Regions`, `RegionAssignments`, `SyncRuns` (миграция `TajikSales`, только добавление).

## Расчёты (`TajikSalesService`)

- **Категория** — по товару Linko с тем же номером в начале названия (`183 Азалия…` → Linko `183` → тип → категория отчёта `Sales:Categories`);
  номера нет — по слову в названии (`PlanIndicatorCategories`).
- **Вес** — количество × вес единицы 1С (`TajikWeights`). «1,5 кг», «4кг» — из названия. «420гр*8шт», «200г*20шт» двояки: у помадки единица
  1С — коробка (128 сомони за 8 × 420 г), у Twizos — пачка (15,1 сомони за 200 г). Выбирает цена: сомони за кг ÷ сумы за кг того же товара в
  Linko (заказы за 180 дней) у верного варианта близко к медиане этого отношения у товаров с однозначным весом. Цены Linko нет — штука
  («штука — проверить»).
- **Суммы** — сомони, без пересчёта (курса в данных нет). Во вторичку и «Завод» не входят.
- **Регион точки**: закреплена вручную → слово в названии (целым словом, без учёта регистра и таджикских букв; ближе к концу названия —
  главнее) → регион ТП по умолчанию → «Регион не определён». Начальные 19 регионов — города и районы, встреченные в названиях точек
  (Кулоб, Шахритуз, Дангара, Бохтар…). Рынки «Фаровон», «Хочи Шариф», «Садбарг» и номера рядов в регион не превращаются — их точки
  закрепляют на странице «Регионы и точки» (регион ТП или точка вручную, право `sales.manage`).
- **К прошлому месяцу** — за те же дни прошлого месяца; данных за прошлый месяц нет — сравнения нет.

## API OneBase

| | |
|---|---|
| `GET /api/sales/tajik?year&month` | итоги, категории, все регионы, ТП, товары, остаток |
| `GET /api/sales/tajik/regions/{id}?category=` | регион (`none` — без региона): точки, товары с точками, ТП |
| `GET /api/sales/tajik/stores/{id}` | точка: накладные со строками, по месяцам |
| `GET/PUT /api/sales/tajik/setup…` | регионы, ТП и точки (PUT — `sales.manage`) |
| `GET/PUT /api/integrations/tj1c`, `POST …/test`, `POST …/sync {full}` | страница интеграции (`integrations.manage`) |

Страницы продаж — только охват «вся организация», как экспорт «Завода».
