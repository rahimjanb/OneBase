# Пользователи, роли и разделы

«Настройки → Пользователи и роли» (право `users.manage`). Добавление и изменение пользователя — в отдельном окне
(`UserDialog`): слева профиль и вход, справа доступ — роль и разделы галочками. В таблице у каждого видны роль, открытые
разделы (метка «вручную» — отмечены не как у роли) и статус; на телефоне таблица становится карточками.

## Роль и разделы

- **Роль** задаёт отдел, права на управление и настройки (пользователи, интеграции, настройки AI, журнал аудита, подтверждения,
  Telegram) и **разделы по умолчанию**.
- **Разделы** отмечаются пользователю галочками (`User.Sections`, `text[]`). `null` — как у роли: пользователь следует за ролью,
  и изменение роли меняет его разделы. Если отмеченные разделы совпадают с разделами роли, сервер тоже хранит `null`.
- При смене роли в окне галочки становятся такими, как у новой роли; кнопка «Как у роли» возвращает разделы роли.

| Раздел | Ключ | Права раздела | Выдаётся, если у роли его нет |
|---|---|---|---|
| Продажи | `sales` | `sales.read`, `sales.manage` | `sales.read` |
| Финансы | `finance` | `finance.read` | `finance.read` |
| HR | `hr` | `hr.read` | `hr.read` |
| Задачи | `tasks` | `work.tasks` | `work.tasks` |
| Файлы | `files` | `files.read`, `files.write`, `files.read.all`, `files.manage` | `files.read`, `files.write` (свой отдел) |
| AI-консультант | `consultant` | `ai.agents.run` | `ai.agents.run` |
| Sales Base | `field` | `field.plan`, `field.use`, `field.manage` | `field.plan` |
| AI Data Manager | `data` | `ai.data.manage` | `ai.data.manage` |
| Рассылки | `campaigns` | `telegram.campaigns` | `telegram.campaigns` |

**Итоговые права** (`UserSections.Effective`): права роли без прав всех разделов, плюс по каждому отмеченному разделу — права
роли в этом разделе, а если у роли их нет — права из последнего столбца. Так у администратора «Файлы» остаются со всеми отделами,
а сотрудник, которому раздел добавили, получает файлы своего отдела. Раздел открыт, если есть хоть одно его право.

Итоговые права используются везде одинаково:

- в токене при входе и в проверке прав на каждом запросе (`UserAccessCache`);
- в меню и на страницах (`navigation.ts`);
- в API: например, `WorkController` требует `work.tasks`;
- в AI (`IUserPermissions`);
- в файлах отделов, AI Data Manager и Telegram-агенте;
- в выборе исполнителя задач.

## AI отвечает по отмеченным разделам

AI работает с итоговыми правами того, кто спрашивает:

- AI-сотрудник с правом снятого раздела не привлекается;
- инструмент раздела не выполняется (`ToolExecutor` — `no_permission`);
- источник знаний раздела закрыт.

Пример: роль «Продажи», разделы «HR» и «AI-консультант» — консультант отвечает по сотрудникам и посещаемости (HR AI). На вопросы по
продажам и задачам он не отвечает: этих данных у пользователя нет. Без раздела «AI-консультант» не работают чат с ИИ и
Telegram-агент от имени пользователя. Окно пользователя показывает, по каким данным ответят AI-сотрудники и по каким — нет.

## Задачи

Раздел «Задачи» — отдельное право `work.tasks`: страница `/tasks`, API `api/work/*`, инструмент `get_department_tasks` и источник
знаний `work.tasks`. Системные роли его получают; кроме «Админа 2», «Супервайзера» и «Агента», у которых своих разделов
Sales Base достаточно. Исполнитель задачи — действующий пользователь с открытым разделом «Задачи». Других нет в выборе, и
назначить им задачу нельзя: они бы её не увидели. Без раздела «Задачи» карточки дедлайнов на «Обзоре» нет.

## Недоступное не показывается

Чего у пользователя нет, того нет на экране: ни замков, ни надписей «нет доступа».

- **Отделы.** Отдел доступен, если открывается его раздел («Продажи» — `sales.read`, HR, «Снабжение», «Производство») или его
  задачи: свой отдел, отдел, которым пользователь руководит, у руководства (`users.manage`) — все, у полевой команды Sales Base —
  «Продажи» (`WorkTaskService.CanOpenDepartment`). Коды таких отделов — `departments` в `GET /api/auth/me` (без раздела «Задачи» —
  пусто), правило на фронте — `departmentOpen` в `navigation.ts`.
- **«Отделы»** показывают только доступные отделы. Пункт меню виден, если доступен хоть один (признак `departments.open` в
  `screenPermissions`). Если показатели отдела закрыты правами, карточка есть, но без числа.
- **«Задачи»**: кнопки только тех отделов, задачи которых открываются; в «Продажах» вкладки полевой команды — только при доступе к
  Sales Base.
- **«Обзор»**: в фильтрах — только доступные отделы, сотрудники — только с доступом к HR. «Фокус дня» и AI-отчёт видны с
  AI-консультантом, дедлайны — с «Задачами», «Лидеры месяца» — с доступом к HR. Сообщения в этих блоках остались только о сбоях
  загрузки.
- **Поиск на телефоне**: в «Отделах» — только доступные.
- **AI Dashboard**: `GET /api/ai/agents` не отдаёт агентов отделов, к данным которых у пользователя нет права; в сводке находок
  (`GET /api/ai/alerts` → `byCategory`) нет отделов, AI-сотруднику которых нужно право, которого у пользователя нет.
- **Цифровой двойник**: закрытые правами сигналы, строки и разделы карточки здания не показываются.
- **KPI продаж**: без права «Финансы» плиток с премиями и фондом оплаты нет.
- **Меню**: карточка «Еженедельный AI-отчёт» — только с AI-консультантом (и без выдуманных чисел).
- **Настройки → Telegram**: ссылки на автоматические и PDF-отчёты — только с правом «Продажи» (отчёты строятся по его данным); по
  прямому адресу без права — обратно в настройки Telegram.
- **Настройки → Источники данных**: без права «AI Data Manager» нет кнопок «Импорт настроек», «Привязать Google Sheets»,
  «Синхронизировать сейчас» и «Изменить» (а не неактивных кнопок с пояснением).
- **Окно пользователя**: не показываются разделы, которых у пользователя нет и которые редактор выдать не может.

## Охват продаж: роли «РМ» и «Супервайзер продаж»

В разделе «Продажи» у пользователя есть **охват** — какую часть оргструктуры он видит. Его задаёт роль:

| Роль | Что видно в «Продажах» | Своя страница |
|---|---|---|
| «РМ» | свои регионы (выбираются в окне пользователя): их СВР, ТП, магазины, продажи, планы, KPI, проблемные агенты, ассортимент; страница направления — если у РМ все его регионы | направление (если все его регионы у РМ), иначе первый регион |
| «Супервайзер продаж» | свои регионы и их ТП (в Linko ТП к СВР не привязан — команда СВР = ТП региона) | первый регион |
| остальные роли с разделом «Продажи» (директор, «Продажи», финансы…) | вся организация, как раньше | «Продажи» |

**Регионы в окне пользователя.** При создании и правке, если выбрана роль «РМ» или «Супервайзер продаж», сразу появляется выбор его
регионов (обязательно, можно несколько). Регионы — филиалы Linko из «Настройки → Продажи: оргструктура» (подсказка — направление).
Сохраняются вместе с пользователем, действуют сразу, без повторного входа, и пишутся в журнал аудита (`users.sales_scope`: было → стало).
Роль сменили на другую — ограничение по регионам снимается. Свои роль и регионы не меняет никто сам себе.

Роли Sales Base («РМ (Sales Base)», «Супервайзер», «Агент») к этому не относятся: «РМ (Sales Base)» раздел «Продажи» OneBase больше не
открывает (миграция `SalesRmRoles`).

Охват считает сервер на каждом запросе из роли, регионов и оргструктуры, а не из адреса или тела запроса:

- **Чужой объект — 404.** Направление, регион, ТП, магазин, категория или товар вне охвата — «не найдено», даже по прямому id в адресе
  или запросе к API. Списки «Агенты», «Планы», «KPI», «Проблемные агенты» считаются сразу по людям охвата, итоги — по ним же.
- **Страницы всей страны — 403** («Нет доступа» с объяснением и кнопкой «Мои продажи»):
  - обзор и республика;
  - первичка, экспорт «Завода»;
  - остатки, аутсток, продажи по SKU;
  - акции, ДМП, «Система»;
  - P&L дилеров, акт сверки, DSO;
  - настройки продаж и синхронизация.
- **Меню:** вкладки раздела, крошки и «Назад» показывают только открытое охвату; «Продажи» ведут сразу на свою страницу.
- **Выгрузки Excel** (остатки, акт автозаказа, обзор первички) — право «Выгрузки Excel» (`sales.export`, галочка в группе «Продажи») и
  охват «вся организация». Без права кнопки нет, сервер отвечает 403.
- **AI** (консультант, AI-сотрудники, Telegram-агент от имени пользователя, оповещения, «Мой день») и **«Цифровой двойник»** считают
  по всей стране и охват не применяют. Поэтому у РМ и супервайзера продаж данных продаж и финансов в них нет (`IUserPermissions` без
  `sales.read`, `finance.read`). Свои цифры — на страницах раздела.
- **Регион перевели в другое направление** в оргструктуре — страница направления пересчитывается сразу. Исторические продажи остаются за
  теми ТП, филиалами и месяцами, как в Linko.
- Охват не трогает Sales Base (`/field`, sales.1base.uz): там своя изоляция по участникам и командам ([sales-base.md](sales-base.md)).
- Сервер умеет и охват «ТП — только он сам» (`level = Agent`, через API назначения), в окне пользователя его нет.

API:
- `POST` / `PUT /api/users` — `salesRegionIds`: регионы для роли «РМ» / «Супервайзер продаж» (без них — 400 «Выберите регионы …»).
- `GET /api/sales/access` — мой охват: уровень, подпись, регионы, своя страница, можно ли выгружать.
- `GET /api/users/sales-scope/options` — направления, регионы, ТП Linko; `GET` / `PUT /api/users/{id}/sales-scope` — охват пользователя
  (право `users.manage`).
- `/api/auth/me` → `salesScope`: `level`, `home`; `departments` — коды доступных отделов (см. «Недоступное не показывается»).

Данные: таблица `sales.UserScopes` (миграция `SalesUserScopes`, только новая таблица; права, отмеченные галочками у тех, у кого есть
раздел «Продажи», дополнены `sales.export`, чтобы выгрузки не пропали). Роли «РМ» и «Супервайзер продаж» создаются при запуске. Тесты:
`SalesAccessDbTests`, `SalesScopeApiDbTests` (каждое действие «Продаж» обязано объявить охват — тест проверяет все),
`frontend/src/lib/sales-access.test.mjs`.

## Ограничения

- Выдать роль или раздел можно, только если у вас самих есть эти права. Раздел, которого у вас нет, в окне не показывается (если
  он уже есть у пользователя — виден, его можно снять). Поэтому администраторов меняет только администратор.
- Свои роль и разделы изменить нельзя — их меняет другой администратор.
- Удаления нет: отключённый пользователь не входит в OneBase и в Telegram-агент, история сохраняется.
- Руководитель отдела (`work.DepartmentHeads`) на странице HR видит сотрудников своих подразделений Verifix и без раздела «HR».
  HR AI и полный HR — только с разделом.

## API

`GET /api/users` возвращает:

- `users[]` — у каждого `sections` (открытые разделы) и `sectionsCustom`;
- `roles[]` — у каждой `sections` (разделы роли);
- `sections[]` — каталог разделов: `key`, `title`, `description`, `grantable` (у вас есть права раздела).

`POST /api/users` и `PUT /api/users/{id}` принимают `sections` — массив ключей. Если `sections` не передан, разделы будут как у роли.

Ошибки:

- неизвестный ключ;
- раздел, которого нет у вас;
- свои разделы.

Каждое изменение пишется в журнал аудита вместе с разделами. Миграция `UserSections` добавляет колонку и ничего не удаляет; откат
убирает колонку.
