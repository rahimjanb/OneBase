# Маршрутизация моделей AI-консультанта

Модель выбирается отдельно для каждого назначения вызова: маршрутизатор, AI-сотрудник отдела, итоговый ответ, перепроверка. Всё решается
в двух местах: `AiTaskRouting` (модель маршрутизатора, режимы off / shadow / on) и `AiModelRouting` (сотрудники, итоговый ответ, переход
при перепроверке). Отдельного вызова модели ради выбора модели нет: сложность считают правила по уже полученным данным.

## До и после

| Вызов | Было | Стало (режим «Включено») |
|---|---|---|
| Маршрутизатор (`consultant.route`) | «Модель маршрутизации», если включены модели задач и режим `on`; иначе основная | без изменений — тот же `AiTaskRouting` |
| Сотрудник (`agent`) | модель канала → модель сотрудника в «Агентах» → основная | модель канала → модель сотрудника → **модель сотрудников** → модель стандартных ответов → основная |
| Итоговый ответ (`consultant.answer`) | модель канала → модель консультанта → основная | модель канала → модель консультанта → **по сложности**: стандартных или сложных ответов |
| Исправление (`consultant.revise`) | та же модель, одна попытка | та же модель; в review — затем **один** переход на модель сложных ответов (`consultant.review`) |
| Сбой провайдера | один повтор, затем резервная модель | без изменений (`AiGateway`) |

Явный выбор человека всегда важнее правил: модель канала (Telegram) и модель, заданная сотруднику или консультанту в «Агентах».

## Настройки (`ai.Settings`, «Настройки → AI → Общие → Модели по назначению»)

| Настройка | По умолчанию | Целевое значение | Что делает |
|---|---|---|---|
| `ModelRoutingMode` | `off` | `on` (сначала `shadow`) | off — как раньше; shadow — ответ как раньше, выбор правил и прогноз стоимости в журнал сравнения; on — правила |
| `RouterModel` + `TaskRoutingEnabled` + `RouterMode` | пусто, выкл, `off` | Sonnet 5.5, вкл, `on` | модель маршрутизатора (существующие настройки «Простые задачи») |
| `AgentModel` | пусто | Sonnet 5.5 | модель сотрудников отделов без своей модели |
| `FinalAnswerMode` | `fixed` | `dynamic` | fixed — всегда стандартная; dynamic — по сложности |
| `FinalDefaultModel` | пусто | Sonnet 5.5 | итоговый ответ на стандартные вопросы |
| `FinalComplexModel` | пусто | Opus 5.5 | сложные ответы и переход при перепроверке |
| `FallbackMode` | `standard` | `review` | standard — одно исправление той же моделью; review — по причине проблемы |
| `ComplexityThreshold` | 3 | 3 | с какого балла (1–10) — модель сложных ответов |
| `ReviewMaxAttempts` | 2 | 2 | дополнительных попыток на ответ (0–3), общий счётчик сотрудников и итога |
| `QuestionBudgetUsd` | пусто | например 1.00 | вызовы ответа стоят столько — новых нет; перепроверка не начинается после 75 % |

Идентификаторы моделей — из каталога «Модели» (`ai.Models`): `claude-sonnet-5-5`, `claude-opus-5-5`. Сохранение проверяет, что модель есть
в каталоге; в режимах `on` и `shadow` модель сотрудников и модель стандартных ответов обязательны, при `dynamic` — и модель сложных ответов:
пустое поле не должно молча означать основную (самую дорогую) модель. Неизвестные значения при чтении становятся безопасными (`off`,
`fixed`, `standard`, порог и попытки в пределах). Миграция `AiModelRouting` только добавляет колонки; существующая строка получает значения по
умолчанию — поведение не меняется, пока администратор не включит режим.

## Сложность (Dynamic)

`AnswerComplexityRules.Assess` — по вопросу, истории и результатам сотрудников:

| Признак | Балл |
|---|---|
| поиск причин («почему», «из-за чего», «что повлияло», «объясни»…) при данных сотрудников | +3 |
| рекомендации («что сделать», «как увеличить», «приоритет»…) | +1, из данных нескольких отделов — ещё +1 |
| несколько отделов | +1 (одно это до порога 3 не доводит) |
| много данных: больше 8 вызовов инструментов или 3+ источника | +1 |
| 3+ точных расчёта | +1 |
| ошибки и нехватка доказательств: сбой сотрудника, неподтверждённые числа, ошибки инструментов | +2 |
| только частичный результат сотрудника (обычно идущий месяц) | +1 |
| возражение к прошлому ответу | +1 |
| неоднозначность: сотрудники выбраны по ключевым словам | +1 |

Длина вопроса и токены в балл не входят. Короткое уточнение («а по Хоразму?», «а за сентябрь?», «только помадка») наследует намерение
прошлого вопроса пользователя.

Примеры (порог 3): «Как продажи за октябрь?» — 0, Sonnet; «Как продажи и задолженность дилеров по Хорезму?» — 1, Sonnet; «Почему упали
продажи в Самарканде?» — 3, Opus; «Что происходит в компании и что улучшить в первую очередь?» — 3, Opus; «А в Бухаре?» после «Почему упали
продажи?» — 3, Opus; продажи и долги с частичным результатом сотрудника — 3, Opus.

## Review (`FallbackMode = review`)

| Причина (`AiReviewCauses`) | Действие |
|---|---|
| `tool_failed` — инструмент упал | повтор без вызова модели в новой области DI; упал и он — ошибка инструмента модели («данных нет — не угадывай»), а не сбой сотрудника |
| `wrong_tool` — нет такого инструмента, гранта или доступа к инструменту | повтор сотрудника с исправленной задачей (ошибки инструментов, «выбери подходящие, если данных нет — no_data») |
| `incomplete` — сотрудник не уложился в шаги или ответ оборван лимитом | повтор сотрудника / переписать ответ короче |
| `unsupported_numbers` — число не прошло EvidenceCheck | исправление той же моделью, затем один переход на модель сложных ответов; неподтверждённое — с пометкой в тексте |
| `no_data` | без повторов: ответ прямо говорит, каких данных нет |
| `budget`, `attempts` | новых вызовов нет, ответ — из уже полученного (или понятная ошибка, если бюджет кончился до ответа) |

Ограничения: попыток — `ReviewMaxAttempts` на весь ответ; переход — один и только вверх (цикла «Sonnet → Opus → Sonnet» нет); повтор сотрудника
— один и только если лучше; отказ по правам (`forbidden`), выключенный сотрудник, сбой модели не повторяются. EvidenceCheck, CorrectionGuard,
проверки прав и аудит не отключаются: каждая попытка проходит проверку чисел.

## Стоимость и токены

Каждый вызов (`ai.Usage`): назначение, модель, причина выбора (`ModelReason`), токены — вход, кэш-чтение, кэш-запись, выход; время провайдера
(`DurationMs`, из него очередь — `QueueWaitMs`), попытка (`Attempt`), резервная модель (`UsedFallback`), стоимость (`CostUsd`, расчётная
по ценам `ai.Models`; провайдер стоимость не возвращает; `PriceBasis` — какие цены применены; нет цены — `null`, не ноль) и `TurnId` — общий
идентификатор вызовов одного ответа. Фоновые сравнения в стоимость ответа не входят.

Ответ (`ai.AuditLogs`): `TurnId`, токены и `CostUsd` (null, если у части вызовов нет цены), `Timings` (этапы, вызовы, инструменты, первый
текст) и `Routing`: режим, сложность и признаки, модели и причины, перепроверки, итог по вызовам — всего, по моделям и назначениям, токены,
стоимость (`costIncomplete`), время этапов (маршрутизация, сотрудники, итог, перепроверка), полное время и первый текст, число исправлений,
проверка чисел, полнота (статусы сотрудников, неподтверждённые числа).

Расход на один ответ:

```sql
select "Purpose", "Model", "ModelReason", "InputTokens", "CacheReadTokens", "CacheWriteTokens", "OutputTokens", "CostUsd", "DurationMs", "Attempt", "UsedFallback"
from ai."Usage" where "TurnId" = (select "TurnId" from ai."AuditLogs" where "MessageId" = '<id ответа>') order by "CreatedAt";

select "Routing"::jsonb -> 'total', "Routing"::jsonb -> 'byModel', "Routing"::jsonb -> 'complexity' from ai."AuditLogs" where "MessageId" = '<id ответа>';
```

## Режим «Сравнение» (shadow)

Ответ — как раньше; после него правила считают, какую модель выбрали бы для сотрудников и итога, и пишут в `ai.ModelComparisons`
(категория `answer`, строки `agent` и `final`): фактическая и выбранная правилами модель, сложность, стоимость фактическая и прогноз — те же
токены по ценам выбранной модели (оценка: у другой модели токены были бы другими). Второго ответа модели нет — сравнение ничего не тратит.
Итоги — «Настройки → AI → Модели по задачам». Маршрутизатор сравнивается своим режимом «Сравнение» (дешёвый фоновый вызов Sonnet).

## Защита от платных вызовов (конфигурация процесса, не база)

| Ключ | Что делает |
|---|---|
| `Ai:Safety:EmulatorUrl` | все провайдеры — на этот адрес с ключом-заглушкой; настоящий ключ (из OneBase или окружения) не читается; сбой эмулятора — ошибка, не настоящий API; неверный адрес — блокировка всех вызовов |
| `Ai:Safety:BlockPaidCalls` | провайдеры выключены: ни одного вызова модели |
| `Ai:Safety:MaxCalls`, `Ai:Safety:MaxCostUsd` | сколько вызовов и долларов может потратить процесс (для разрешённых платных проверок); дошли — вызовы отклоняются |

Приоритет ключа без защиты: сохранённый в OneBase → из окружения (`ANTHROPIC_API_KEY`); адрес — из OneBase, иначе адрес провайдера. Поэтому
ключ в окружении не уводит вызовы на эмулятор, если в OneBase сохранён настоящий ключ, — для эмулятора нужен `Ai:Safety:EmulatorUrl`.

## Платная проверка (30.10.2026, по разрешению; харнесс — `PaidModelRoutingEval`, лимит процесса)

Маршрутизатор на 34 вопросах: Opus — 34 верно, Sonnet — 32 (лишний маркетинг в «ТП не выполняют план», никого — в «просроченные
задачи»), совпало 30; среднее 3,6 → 2,9 с, P95 6,4 → 4,6 с. Полные ответы (A — всё Opus, B — целевая): «Как продажи за октябрь?» $0,59 / 162 с
→ $0,23 / 62 с, одинаковые ключевые числа; «Почему упали продажи в регионе?» $0,44 / 107 с → $0,24 / 82 с, но выводы разные (варианты сравнили с разными
периодами). Неподтверждённых чисел в ответах нет. Выборка — 2 пары: качество не доказано. Порог
«частичный результат» откалиброван после проверки (было +2 — простой вопрос уходил в Opus); эффект не перемерен.

## План полной платной проверки (нужно подтверждение)

Вопросы — эталонный набор `RouteEvalCases`, 34: продажи (месяц, падение региона, визиты, план категории, ушедшие клиенты ×2, ТП без плана,
рост SKU, прогноз), финансы (задолженность, P&L дилеров, падение прибыли), рост продаж, склад (заканчивающиеся товары, поставщики, закупки к
сезону), производство, отгрузки завода, экспорт, маркетинг, HR (нагрузка, просрочки, опоздания, табель), «что происходит в компании»,
приветствие, благодарность, уточнения («А по Самарканду?», «А что было в сентябре?», «А задолженность там какая?»), возражение («Это
неправильно, проверь ещё раз»), межотдельные (продажи и долги, остатки и план, опоздания и продажи).

1. **Маршрутизатор** (`POST /api/ai/routing/evaluate`): 34 вопроса × (Opus 5.5 и Sonnet 5.5) = 68 вызовов, около $0,2.
2. **Полные ответы парой** на одних данных, тем же пользователем, в новых чатах: вариант A — как сейчас (всё Opus 5.5), вариант B — целевая
   конфигурация (маршрутизатор и сотрудники Sonnet 5.5, итог dynamic Sonnet/Opus, review, бюджет вопроса $1). По реальным замерам ответ A —
   6–8 вызовов и около $0,27; ожидаемо 34 × 2 ответа ≈ 500 вызовов, около $14 (A ≈ $9, B ≈ $5 — оценка, не измерение).
3. **Блокировка сверх лимита**: отдельный процесс проверки с `Ai:Safety:MaxCalls=600` и `Ai:Safety:MaxCostUsd=20` (дошли — вызовы
   отклоняются), бюджет вопроса $1, настройки вариантов подставляются в процессе проверки — рабочая конфигурация в базе не меняется.
4. **Сравнение**: совпадение отделов, сохранение уточнений (`TaskMustContain`), неверные числа (EvidenceCheck, ручная сверка спорных),
   полнота (статусы сотрудников), задержка P50/P95, вызовы, токены и стоимость по `ai.AuditLogs.Routing`.
