# OneBase Mobile — архитектура

Один бэкенд, одна бизнес-логика, одна база. Веб (Next.js) и мобильное приложение (Flutter) — два независимых интерфейса к
одному `OneBase.Api`. Мобильный клиент ничего не считает за сервер: показывает то, что вернул API, и хранит последний успешный
ответ, чтобы работать при плохой сети.

```
┌──────────────┐   /bff/api/* (cookie)   ┌───────────┐
│ Web (Next.js) │ ──────────────────────▶ │           │
└──────────────┘                          │ OneBase   │   PostgreSQL, MinIO, Redis,
┌──────────────┐   /api/* (Bearer JWT)    │ .NET API  │ ─ Qdrant, Linko, 1С, Verifix,
│ Mobile        │ ──────────────────────▶ │           │   Claude (AiGateway)
│ (Flutter)     │ ◀── SSE (консультант) ─ │           │
└──────────────┘ ◀── FCM push (этап 11) ─ └───────────┘
```

## Расположение

Проект — `mobile/` в корне репозитория (рядом с `backend/` и `frontend/`), пакет `onebase_mobile`, bundle id `uz.onebase.mobile`.

## Стек

Версии — актуальные стабильные на 19.11.2026, точные — в `mobile/pubspec.yaml`.

| Задача | Библиотека | Зачем именно она |
|---|---|---|
| Состояние | `flutter_riverpod` | Провайдер на каждый блок: независимая загрузка, отмена при уходе с экрана, точечные перестройки |
| Навигация | `go_router` | `StatefulShellRoute` для нижней панели (у каждой вкладки свой стек), редирект по сеансу |
| Сеть | `dio` | Перехватчики (токен, язык, повтор, журнал), `CancelToken`, поток SSE |
| Модели | `freezed` + `json_serializable` | Неизменяемые DTO, `fromJson` без ручного разбора |
| Локальные данные | `drift` (SQLite) | Кэш последних ответов, время синхронизации, позже — очередь операций |
| Токен | `flutter_secure_storage` | Keychain (iOS) / Keystore (Android) |
| Графики | `fl_chart` | Столбцы и линии Dashboard и аналитики. Два ряда — `series1` / `series2` в токенах; пара проверена валидатором палитры (различимость при дальтонизме, контраст ≥ 3:1 в обеих темах); статусные цвета рядами не служат |
| Сеть онлайн/офлайн | `connectivity_plus` | Плашка «Нет сети», обновление при возвращении сети |
| Локализация | `flutter_localizations` + `intl` (gen-l10n, ARB) | Русский и узбекский (латиница), форматы чисел и дат |
| Push | `firebase_messaging` | Этап 11 (нужен проект Firebase) |

Лишних библиотек нет: журнал — свой тонкий слой над `dart:developer`, повтор запросов и устранение дублей — свои перехватчик и
реестр, фейки в тестах — вручную.

## Структура (feature-first + clean architecture)

```
mobile/lib/
  main.dart                    точка входа → bootstrap
  app/
    app.dart                   MaterialApp.router, темы, локали
    bootstrap.dart             конфиг окружения, БД, журнал, обработка ошибок, ProviderScope
    router.dart                GoRouter: /login, оболочка с 5 вкладками, редиректы по сеансу и правам
    theme/                     токены OneBase (цвета, радиусы, тени, типографика), светлая и тёмная темы
  core/
    config/                    AppConfig: окружение, базовый URL API (--dart-define-from-file)
    api/                       ApiClient (Dio), перехватчики, ApiException, реестр одинаковых запросов
    auth/                      TokenStorage, Session, AuthRepository, AuthController, права (Perm)
    cache/                     CacheStore (Drift), CachedResource — «сначала кэш, потом сеть»
    database/                  AppDatabase (Drift): таблица cache_entries
    errors/                    AppFailure — понятные тексты ошибок для экрана
    network/                   Connectivity: онлайн / офлайн
    storage/                   настройки (язык, тема)
    synchronization/           SyncStamp — когда блок последний раз обновился
    localization/              LocaleController, форматы чисел и дат (сум, кг, %, «12 мин назад»)
    logging/                   Log (dart:developer), без токенов и персональных данных
  shared/
    widgets/                   ObCard, ObButton, ObTextField, KpiTile, Skeleton, EmptyState, ErrorState, SectionHeader,
                               OfflineBanner, SyncLabel, ObAppBar
    extensions/                BuildContext (тема, l10n), форматирование
  features/
    auth/                      экран входа
    dashboard/  data/ domain/ presentation/
    analytics/  ai_consultant/  sales/  finance/  production/  warehouse/  hr/  tasks/  notifications/  profile/  settings/
```

Внутри модуля:
- `data/` — DTO (freezed), `*Api` (запросы через ApiClient), `*Repository` (кэш + сеть);
- `domain/` — то, что нужно экрану (период, сводки), без Flutter;
- `presentation/` — провайдеры Riverpod, экраны, виджеты.

Модули не импортируют друг друга. Общее лежит в `core/` и `shared/`.

## Ключевые механизмы

### Сеанс

0. Свежая установка (в базе приложения нет отметки `installed_at`): токен, оставшийся в Keychain от удалённого приложения, удаляется —
   на iOS Keychain переживает удаление приложения, и без этого после переустановки подхватился бы старый вход.
1. Старт: токен из Keychain/Keystore → `GET /api/auth/me`.
   - Есть ответ → сеанс, права, кэш `/me` обновлён.
   - Нет сети → сеанс из кэша `/me` (офлайн-режим).
   - 401 → токен и кэш удаляются → экран входа.
2. Вход: `POST /api/auth/login` → токен в хранилище → `/me`.
3. Любой 401 во время работы → `AuthController.expire()`: сеанс закрыт, кэш очищен, экран входа с причиной.
4. Возврат приложения из фона → `/me` перечитывается (права меняются без повторного входа — так же устроен сервер).
5. Выход: `POST /api/auth/logout` (если не вышло — всё равно выходим локально), удаление токена и всего кэша.

Refresh-токена нет: у OneBase токен долгий, а отзыв серверный (`UserSession`). Новую систему авторизации не делаем.

### Данные блока: сначала кэш, потом сеть

```
Provider блока ──▶ Repository.watch(key)
                     1. кэш (Drift) ─▶ показать сразу с «обновлено 12 мин назад»
                     2. сеть (Dio, отмена при уходе, повтор GET при сбое сети)
                        ├─ успех ─▶ сохранить срез в кэш ─▶ показать свежие данные
                        └─ ошибка ─▶ оставить данные кэша + плашка ошибки;
                                     без кэша — ErrorState с «Повторить»
```

Каждый блок Dashboard — свой провайдер и свой запрос (`CachedBlock` в `core/cache/cached_block.dart`). Медленный или упавший
блок не держит остальные.

- Нет права (403) — блок скрывается.
- Сеть вернулась — блок обновляется сам.
- Повторный `refresh` во время запроса не создаёт второй запрос.
- Блоки живут, пока открыт экран, а не пока секция видна (`keepBlocksAlive` через `ref.listen`): иначе ленивый список закрывал бы
  ушедшую за край секцию, и прокрутка запускала бы повторную загрузку.
- `persist = false` — блок не сохраняется на телефоне: события ленты содержат имена сотрудников и кандидатов.

### Сеть

- **Перехватчики:** `Authorization: Bearer`, `Accept-Language`, `User-Agent`; повтор GET (2 раза: 0,5 с и 1,5 с) при обрыве,
  таймауте, 502/503/504; журнал в debug — без тела ответа и без токена.
- **Ошибки** превращаются в `ApiException` (вид, код, текст сервера), а на экране — в `AppFailure` с понятным текстом.
- **Одинаковые GET** во время выполнения не дублируются: второй вызов получает тот же Future.
- **Отмена:** `CancelToken` провайдера отменяется в `ref.onDispose`.
- **Тяжёлый JSON** (больше 64 КБ) разбирается в фоновом изоляте (`Isolate.run`).
- POST/PUT/DELETE не повторяются автоматически. Финансовые и складские операции идут без оптимистичного интерфейса (этапы 8–9).

### Права

`Perm` — константы кодов с сервера (`sales.read`, `finance.read`, `work.tasks`, `ai.agents.run`, …).

- **Нижняя панель:** «Главная» и «Профиль» видны всем. «Аналитика» — при `sales.read`, `finance.read`, `analytik.use` или
  `production.read`. «Задачи» — при `work.tasks`. «AI» — при `ai.agents.run`.
- **Блоки Dashboard** без права не запрашиваются. Если сервер всё же ответил 403, блок просто скрывается.

### Окружения

`--dart-define-from-file=env/<name>.json`:

| Окружение | `API_BASE_URL` | Назначение |
|---|---|---|
| development | `http://localhost:5081` (iOS-симулятор), `http://10.0.2.2:5081` (Android-эмулятор) | локальный API |
| staging | задаётся при сборке | тестовый сервер |
| production | `https://<домен OneBase>` — задаётся при сборке | прод |

HTTP без TLS разрешён только в development: iOS — `NSAllowsLocalNetworking`, Android — `network_security_config` в
debug-манифесте.

### Безопасность

- Токен хранится только в защищённом хранилище; в iOS — `first_unlock_this_device`, без переноса в резервные копии на другие устройства.
- Кэш — агрегаты Dashboard и профиль. Он привязан к пользователю и удаляется при выходе и смене пользователя.
- Персональные данные сотрудников и кандидатов, тексты диалогов AI и пароли не кешируются.
- Журнал не пишет токены, тела ответов и персональные данные.

- главное действие — в нижней трети экрана (управление одной рукой);
