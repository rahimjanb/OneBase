## Отчёты по этапам

### Этап 0 — аудит OneBase

- **Изучено:**
  - бэкенд: 61 контроллер, 853 эндпоинта;
  - аутентификация (JWT, сеансы `UserSession`, права из БД на каждом запросе);
  - BFF веба;
  - nginx: `/api/` открыт наружу;
  - разделы Dashboard, продаж, финансов, HR, задач, уведомлений, AI, производства и склада;
  - push (только VAPID); realtime (нет SignalR/WebSocket, у консультанта SSE);
  - лимиты частоты; токены дизайна веба.
- **Замеры:** образцы ответов dev API, только GET.
- **Создано:**
  - [API_AUDIT.md](API_AUDIT.md);
  - [API_ENDPOINTS.md](API_ENDPOINTS.md) — сгенерирован из контроллеров;
  - [ARCHITECTURE.md](ARCHITECTURE.md);
  - [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md).
- **Изменено:** ничего.
- **Бэкенд:** не менялся.
- **Выводы:**
  - отдельный бэкенд не нужен;
  - refresh-токена нет по замыслу, отзыв сеанса серверный;
  - арендаторов нет: «организация» — фильтр 1С в финансах;
  - тяжёлый запрос один — `/api/sales/republic`, 234 КБ;
  - для push нужен FCM (P1);
  - компактные ряды (P2/P3) — по желанию.
