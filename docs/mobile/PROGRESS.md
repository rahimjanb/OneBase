### Этап 2 — авторизация

- **Изучено:** `AuthController` (вход, `/me`, выход), `AuthSetup` (сеанс в токене, права из БД на каждом запросе), лимит входа.
- **Реализовано:**
  - вход под существующей учётной записью (`POST /api/auth/login`) — логин или почта и пароль, автозаполнение паролей iOS/Android;
  - тексты ошибок:
    - 401 — «Неверный логин или пароль»;
    - 429 — «Слишком много попыток»;
    - сеть — «Нет соединения с сервером»;
  - токен — только в Keychain (`first_unlock_this_device`) / Keystore; в памяти — для перехватчика; в журнал не пишется;
  - восстановление сеанса при запуске:
    - токен → `GET /api/auth/me`;
    - без сети — профиль из кэша (по `sub` токена);
    - без сети и без кэша — «Не удалось проверить вход» с «Повторить» и «Выйти»;
  - «сеанс закрыт»: любой 401 на запросе с токеном → токен и кэш удаляются → экран входа с причиной;
  - выход: подтверждение → `POST /api/auth/logout` (закрывает сеанс на сервере) → удаление токена и всего кэша; без сети — выход
    только на телефоне;
  - права:
    - вкладки по правам: «Аналитика» — продажи/финансы/аналитик/производство, «Задачи» — `work.tasks`, «AI» — `ai.agents.run`;
    - в закрытый раздел роутер не пускает;
    - профиль и права перечитываются при возврате в приложение (не чаще раза в минуту);
  - вход другого пользователя удаляет чужой кэш с телефона;
  - профиль: карточка пользователя (инициалы, имя, должность и отдел, роли, пометка «нет связи — профиль сохранён»), выход;
  - Android: резервное копирование выключено (`allowBackup=false`, `data_extraction_rules`) — токен и кэш данных компании не
    уходят в облако и на другое устройство.
- **Refresh-токен:** не делался — у OneBase его нет по замыслу (токен на 10 лет, отзыв на сервере). Новая система авторизации не
  создавалась.
- **Выбор организации:** арендаторов в бэкенде нет. Организации 1С — фильтр финансовых блоков Dashboard (этап 3).
- **Тесты (71, все проходят):**
  - контроллер входа: без входа; восстановление; 401 при запуске; без сети с кэшем и без кэша; истёкший токен; вход; чужой кэш;
    неверный пароль; 429; 401 во время работы; выход; выход без сети; обновление прав не чаще минуты; `sub` из токена;
  - редиректы и вкладки по правам;
  - экран входа через интерфейс: пустые поля; неверный и верный пароль; вкладки по правам; «сеанс закрыт»; выход с подтверждением;
    «Повторить» после сбоя.
- **Проверено на настоящем API** (iOS-симулятор, локальный dev API :5081, тестовый администратор, только чтение) — integration-тест
  `integration_test/auth_flow_test.dart` через `flutter drive`; учётные данные — `--dart-define`:
  - экран входа → вход → главная с 5 вкладками → профиль с данными из `/api/auth/me`;
  - перезапуск приложения — сеанс восстановлен из Keychain без входа.

- **Бэкенд:** не менялся. Компактные ряды (P2/P3 из аудита) остаются предложением.
- **12 блоков ТЗ → что на экране:**

| Блок ТЗ | Источник | Как показано |
|---|---|---|
| 1. Общая выручка | `sales/overview` → `kpi.revenue` | Плитка «Выручка», данные по дату |
| 2. Общие расходы | `finance/overview` → `months[последний].expenses` (1С) | Финансы · 1С; данных 1С нет → пояснение сервера |
| 3. Чистая прибыль | `finance/overview` → `pnl.net_profit` | То же, изменение к прошлому периоду (сервер) |
| 4. Количество продаж | `kpi.factKg` (+ прогноз) | Плитка «Продано», т/кг; визиты и визиты без заказа — в детализации |
| 5. Количество клиентов | `kpi.akb` + АКБ на ТП к цели | Плитка «Клиенты (АКБ)» |
| 6. Выполнение плана | `kpi.execution`, уровень цвета сервера | Плитка «План месяца»; плана нет → «План не задан» |
| 7. Динамика продаж | срез `republic`: кг по дням, «те же дни» | Столбцы по дням, к тем же дням прошлого месяца |
| 8. Финансовая динамика | `finance/overview` → 12 месяцев | Линии «Чистая выручка» / «Расходы» с легендой |
| 9. Показатели подразделений | `hr/overview` | Явка сегодня, опоздали/нет/отпуск, крупнейшие подразделения, все — в детализации |
| 10. Последние события | `notifications?take=20` | 5 последних, все — в детализации |
| 11. Активные задачи | `work/overview` | Счётчики, мои ближайшие, отделы с просрочкой; «Открыть» → вкладка «Задачи» |
| 12. AI Insights | `ai/alerts` (модель не вызывается) | «Фокус дня»: критично/проблемы/возможности, три главные, все с рекомендациями |

- **Функции:**
  - период: «Последние данные» (как сайт) или месяц из `/api/sales/months` (без продаж — 12 последних);
  - организация 1С — фильтр финансов, если организаций больше одной;
  - pull-to-refresh обновляет все блоки параллельно;
  - детализация (нижний лист поверх панели): продажи — все показатели с целями и уровнями сервера, таблица по дням (таблица к
    графику); финансы — P&L с прошлым периодом, деньги и долги, по месяцам; подразделения; все находки AI; все события;
  - сравнение периодов — то, что даёт сервер: к тем же дням прошлого месяца (продажи), к прошлому периоду (P&L), к прошлому
    рабочему дню (явка);
  - блоки по правам: без права блок не запрашивается; продажи — уровень организации (РМ/СВ/ТП — этап 5); без разделов на главной
    только события и пояснение.
- **Независимость и кэш:** `CachedBlock` — «сначала кэш, потом сеть»; ошибка одного блока — ошибка и «Повторить» внутри него;
  старые данные — с временем синхронизации и причиной; сеть вернулась — обновление; тяжёлый `republic` — в фоновом изоляте, в кэш
  идёт только ряд по дням; события на телефоне не сохраняются (имена людей).
- **Графики:** fl_chart по правилам dataviz:
  - тонкие столбики со скруглением от нуля, бледная сетка;
  - 2 ряда — легенда со значениями, палитра проверена валидатором в обеих темах;
  - подсказка по касанию, таблица значений в детализации.
- **Тесты (98, все проходят):**

### Этап 4 — Mobile Performance Engine

- **Реализовано:**
  - SQLite-кэш и кэш на уровне репозитория (`core/cache/repo_cache.dart`): память + SQLite со сроком годности, одинаковые запросы
    одним, сброс по началу ключа (`home/live/…` — текущие данные, закрытые месяцы остаются); привязка к пользователю;
  - очередь операций при плохой сети (`core/synchronization/outbox.dart`, таблица `pending_ops`, миграция БД 1 → 2 только добавляет
    таблицу): операция сначала пишется, потом отправляется; нет сети — уходит при возвращении сети и при открытии приложения; новая
    операция над той же сущностью заменяет старую; отказ сервера не повторяется и показывается в профиле; только идемпотентные операции,
    финансы и склад — только онлайн;
  - оптимистичный интерфейс для безопасных операций (`CachedBlock.setOptimistic` + откат при отказе) — «Что присылать» в профиле;
  - постраничные ленивые списки (`core/cache/paged.dart`: подгрузка, курсор, без двойных запросов, отмена, refresh);
  - debounce поиска (`core/utils/debouncer.dart`);
  - кэш картинок в памяти (`core/cache/memory_bytes_cache.dart`, LRU по объёму) — вложения задач на диск не пишутся (сервер отдаёт
    `no-store`); фото сотрудников и аватаров в OneBase нет — инициалы;
  - синхронизация при возврате из фона (профиль и права, очередь операций), очистка кэша старше 30 дней при запуске;
  - уже были: дедупликация запросов, отмена, повтор GET, мониторинг сети, тяжёлый JSON в изоляте, время синхронизации, точечные
    перестройки (`select`), блоки живут, пока открыт экран.
- **Найдено и исправлено:** очистка реестра запросов возвращала удалённый Future в `Future.microtask` — ошибка запроса становилась
  необработанной (поймано тестом).
- **Тесты:** 103, все проходят — кэш репозитория (ошибка доходит до обоих ожидающих, срок годности, сброс live, пользователь),
  очередь (сразу / без сети / замена / отказ / чужой пользователь), список с подгрузкой, debounce, навигация по правам, раскладка
  веера, расчёты главной (недели, явка, находки, шкала), экран главной на синтетических ответах (блоки, порядок находок, офлайн, права).
