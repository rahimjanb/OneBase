# Источники данных: Linko и Google Sheets

«Настройки → Источники данных» (`/settings/data-sources`, право `integrations.manage`; сохранять и запускать привязки —
ещё и `ai.data.manage`). Одна страница: откуда каждый раздел продаж берёт данные и как часто они обновляются.

## Подключения

- **Linko** — факт: заказы, возвраты, визиты, точки, остатки, перемещения, планы ТП. Только чтение, настройка — в
  «Интеграции → Продажи → Linko» ([sales-linko.md](sales-linko.md)). Здесь — статус, сервер и время последней синхронизации.
- **Google Sheets** — таблицы с данными, которые ведёт сам OneBase. Добавляются ссылкой на таблицу, доступ:
  - **по ссылке** — таблица открыта «Все, у кого есть ссылка → Читатель»; OneBase скачивает её как xlsx
    (`docs.google.com/spreadsheets/d/{id}/export?format=xlsx`);
  - **сервисным аккаунтом Google** — для закрытых таблиц: JSON-ключ (Google Cloud → IAM → Сервисные аккаунты, включён Google Drive
    API), таблицей делятся с почтой аккаунта. Токен OAuth — JWT RS256, scope `drive.readonly`; таблица — Drive API `files.export`
    (загруженный файл .xlsx — `files.get?alt=media`). Ключ хранится зашифрованным (ASP.NET Data Protection), в браузер не отдаётся.
- При сохранении и по кнопке «Проверить» таблица читается: статус, текст ошибки («Таблица закрыта…», «не найдена…», «поделитесь
  таблицей с …») и список листов. Чтение — тем же разбором, что отчёты AI Data Manager (значения ячеек, до 20 000 строк на лист, до 20 МБ).

## Разделы и поля

Факт всех разделов — из Linko. Из Google Sheets обновляются только данные, которые ведёт OneBase (`DataSourceCatalog`):

| Раздел | Поля из Google Sheets |
|---|---|
| Вторичка | План РОП, План «Завод», СВР региона, Дилер региона |
| Первичка | План первички, Дилер региона |
| Планы | План РОП, План «Завод», План первички |
| P&L дилеров | P&L дилеров |
| Ассортимент, Продажи по SKU, Рек. остаток, Аутсток, Проблемные агенты | — (только Linko) |

**Одно поле — одна привязка**: план РОП можно привязать во «Вторичке» или в «Планах», но не в обоих — две таблицы перезаписывали
бы друг друга. В другом разделе видно, где поле уже обновляется.

## Привязка

Раздел → «Привязать Google Sheets»: таблица, **листы**, строка заголовков (с предпросмотром — переключатель между выбранными листами),
**какие поля обновлять** — и у каждого поля своё сопоставление столбцов (столбец — по заголовку или букве).

**Несколько листов.** В привязке можно отметить несколько листов с одинаковой разметкой (те же столбцы и строка заголовков) или «Все листы» —
тогда и новые листы, добавленные позже, читаются сами. Строки всех листов собираются в одну операцию: одна и та же строка плана на двух
листах с разными значениями — ошибка строки; дилер одного региона на листах разный — ошибка поля. Пропавший из таблицы лист — ошибка
синхронизации со списком листов. Для планов и P&L месяц можно брать **из названия листа** («Сентябрь 2026», «09.2026», «2026-09»; без
года — год из привязки): лист на месяц, столбца месяца нет. Лист без месяца в названии (например «Справка» при «Все листы») — ошибка поля.

Сопоставление полей:

- **планы** — регион (дилер), категории (столбцом, каждая категория — свой столбец или без категорий — итог), месяц (столбцом:
  «сентябрь», «09.2026», «2026-09» — или один месяц для листа), год, единицы (кг или тонны), режим: «лист полный за свои месяцы»
  (строки этих месяцев, которых нет в листе, удаляются) или только добавлять и обновлять;
- **дилер, СВР** — столбец региона и столбец значения; пустая ячейка не стирает записанное;
- **P&L** — контрагент, статья (как в OneBase), сумма, месяц, год.

**Время синхронизации**: вручную, каждые 15 мин … 24 ч или ежедневно в ЧЧ:ММ (Ташкент); фоновая служба раз в минуту запускает
привязки, у которых подошло время. «Синхронизировать сейчас» работает при любом расписании; выключенная привязка по расписанию не идёт.

## Смена месяца

- **Факт Linko** приходит сам: синхронизация непрерывная (изменения по `last_tm`), страницы продаж и первички открываются на месяце
  последних данных — 1-го числа (данные «по вчера») это прошлый месяц целиком, со 2-го — новый. Планы ТП — из API планов Linko, тоже сами.
- **Данные OneBase** (планы РОП, «Завод», первички, P&L) на новый месяц нужно загрузить. Привязка Google Sheets подхватывает новый месяц сама,
  если месяц в таблице: столбцом, названием листа («Ноябрь 2026» при «Все листы») или режимом **«текущий месяц»** — лист «План» всегда про
  текущий месяц по Ташкенту, с 1-го числа значения идут в новый месяц. «Один месяц для всех строк» — только для разовой загрузки.
- **Защита «текущего месяца»**: у каждого записанного поля в журнале — месяц и отпечаток значений (без месяца). В новом месяце, если в листе
  те же цифры, что записаны за прошлый, синхронизация **по расписанию** ничего не пишет (статус «Ждёт новый месяц»): иначе в ноябрь
  скопировался бы октябрьский план, пока таблицу не обновили. Обновили таблицу — следующая синхронизация пишет в новый месяц. План
  действительно тот же — «Синхронизировать сейчас» записывает его как есть.
- **Напоминание**: фоновая служба раз в час (1–10-е число) проверяет планы по видам — был в прошлом месяце, а на текущий нет — уведомление
  в колокольчике и push всем с правом «AI Data Manager», одно на вид и месяц («Ноябрь 2026: «План первички» ещё не загружен», ссылка на
  «Источники данных»). На странице — полоса «Планы на <месяц>»: какой план загружен, какого нет.

## Как пишутся данные

Синхронизация (`DataSourceService.RunAsync`) читает таблицу и по каждому **отмеченному** полю готовит план изменений AI Data Manager
теми же планировщиками, что для загруженного отчёта; неотмеченные поля не трогаются. Дальше:

- **строки с ошибками** (регион не найден, не число, нет месяца) — поле не записывается совсем: план изменений отменяется, в журнале —
  первые ошибки («Ташкентская обл. · …: регион не найден»). Так опечатка в таблице не стирает план региона;
- **без изменений** — план отменяется, статус «Без изменений»;
- **иначе** — применяется одной транзакцией с проверкой «данные не изменились после подготовки» и сверкой после записи.

Каждая запись — операция в журнале AI Data Manager («Планы регионов: план первички · … · Google Sheets «План 2026» / План») от имени того,
кто настроил привязку (по кнопке — того, кто нажал), с откатом там же. Итог по полям — в «Журнале» привязки (таблицы
`DataSourceConnections`, `DataSourceBindings`, `DataSourceSyncRuns`, миграция DataSources). Одна привязка не запускается дважды
одновременно.

## API

| Метод | Путь | |
|---|---|---|
| GET | `/api/settings/data-sources` | Linko, таблицы, разделы с привязками |
| POST, PUT, DELETE | `/api/settings/data-sources/connections[/{id}]` | таблица Google (проверяется при сохранении) |
| POST | `/api/settings/data-sources/connections/{id}/test` | проверить таблицу |
| POST | `/api/settings/data-sources/preview` `{ connectionId, sheet }` | первые 15 строк листа |
| POST, PUT, DELETE | `/api/settings/data-sources/bindings[/{id}]` | привязка (нужно ещё `ai.data.manage`) |
| POST | `/api/settings/data-sources/bindings/{id}/sync` | синхронизировать сейчас |
| GET | `/api/settings/data-sources/bindings/{id}/runs` | журнал (последние 30) |
