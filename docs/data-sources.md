# Источники данных: Linko и Google Sheets

«Настройки → Источники данных» (`/settings/data-sources`, право `integrations.manage`; сохранять и запускать привязки —
ещё и `ai.data.manage`). Одна страница: откуда каждый раздел продаж берёт данные и как часто они обновляются.

## Подключения

- **Linko** — факт: заказы, возвраты, визиты, точки, остатки, перемещения, планы ТП. Только чтение, настройка — в
  «Интеграции → Продажи → Linko» ([sales-linko.md](sales-linko.md)). Здесь — статус, сервер и время последней синхронизации.
- **Google Sheets** — таблицы с данными, которые ведёт сам OneBase. Добавляются ссылкой на таблицу, доступ:
  - **по ссылке** — таблица открыта «Все, у кого есть ссылка → Читатель»; OneBase скачивает её как xlsx
    (`docs.google.com/spreadsheets/d/{id}/export?format=xlsx`);
  - **сервисным аккаунтом Google** — для закрытых и больших таблиц: JSON-ключ (Google Cloud → IAM → Сервисные аккаунты, включены
    Google Sheets API и Google Drive API), таблицей делятся с почтой аккаунта (читатель). Токен OAuth — JWT RS256, scope
    `drive.readonly`. Таблица читается **Google Sheets API по листам**: список листов — `spreadsheets.get` (без значений), значения —
    `values:batchGet` только выбранных листов (дважды: даты числом и даты строкой — так видно, какие ячейки даты). Большая книга
    целиком не скачивается. Файл Excel, загруженный в Drive (не таблица Google), или выключенный Sheets API — файлом xlsx через Drive API:
    `files.export` (до 10 МБ; больше — выгрузка `docs.google.com/…/export?format=xlsx` с тем же токеном), файл Excel —
    `files.get?alt=media`. Ключ хранится зашифрованным (ASP.NET Data Protection), в браузер не отдаётся.
- При сохранении и по кнопке «Проверить» читается список листов: статус и текст ошибки («Таблица закрыта…», «не найдена…»,
  «поделитесь таблицей с …» — вместе с ответом Google). Значения — в записи разбора отчётов AI Data Manager (числа инвариантно, даты
  ГГГГ-ММ-ДД): все строки листа (предел 20 000 строк загрузок AI Data Manager здесь не действует), до 60 столбцов. Пределы, чтобы
  не уронить сервер: файл xlsx — до 20 МБ и до 50 МБ листов в распакованном виде (книгу больше читает только сервисный аккаунт),
  через Sheets API — до 5 млн ячеек за одно чтение. Предпросмотр кэширует только показываемые строки и размер листа.
  Предпросмотр и синхронизация читают только свои листы.

## Разделы и поля

Факт всех разделов — из Linko. Из Google Sheets обновляются только данные, которые ведёт OneBase (`DataSourceCatalog`):

| Раздел | Поля из Google Sheets |
|---|---|
| Вторичка | План РОП, План «Завод», СВР региона, Дилер региона |
| Первичка | План первички, Дилер региона |
| Планы | План РОП, План «Завод», План первички |
| P&L дилеров | P&L дилеров |
| Акт сверки, DSO | Оплаты дилеров, Расходы по дилерам, Нормы оплаты дилеров, Остатки дилеров на дату |
| Ассортимент, Продажи по SKU, Рек. остаток, Аутсток, Проблемные агенты, Акции, KPI | — (только Linko) |

Оплат дилеров заводу, их расходов, сроков оплаты и остатков по акту бухгалтерии в Linko нет (`linko.Contracts` пуст, `payments/` —
платежи магазинов), поэтому акт сверки и DSO берут их из таблиц. Отгрузки и возвраты обоих разделов — первичка Linko.

Поля взаиморасчётов — **реестры**, а не планы:

| Поле | Вид | Что читается | Таблица |
|---|---|---|---|
| Оплаты дилеров | `ledger` | дата, контрагент, сумма, кошелёк («Нақд» — касса, иначе банк), отбор статей по началу («101», «103»), комментарий, «строки с даты» | «План первички» → «Kassa Bank» (там и статья 103 — оплаты сетей) |
| Расходы по дилерам | `ledger` | дата, контрагент, сумма, статья («601-Дилер бонуслари» → код 601), комментарий | «DSO» → «Прочие расходы 1» |
| Нормы оплаты дилеров | `terms` | контрагент, срок оплаты в днях (пусто — договор без нормы), остаток долга на дату | «DSO» → «Ostatka» |
| Остатки дилеров на дату | `balance` | контрагент, остаток на начало месяца; дата — из ячейки листа (`F1` у «АКТ-СВЕРКА»: лист каждый месяц переходит на новый месяц) | «План первички» → «АКТ-СВЕРКА» |

«Строки с даты» в реестре оплат — 01.08.2025: в «Kassa Bank» «Плана первички» строки от 31.07.2025 — остатки на начало, записанные
расходом (47 строк, −9,4 млрд); оплатами они не являются и задвоили бы остаток «Ostatka». Без них строки статьи 101 совпадают с «Kassa
Bank» таблицы «DSO» до сума (2196 строк, 157 124 265 835 на 22.10.2026). В листе акта строки-заголовки групп («Диллер», «Ритейл») и
«Итого» — не контрагенты: заголовок задаёт группу строк ниже (`Category`), по ней «Акт сверки» делит строки, как бухгалтерия.

**План первички** — «План первички» → «План Первичка данный» (строка заголовков 5): «Год», «Месяц», «Контрагент» (дилер) и столбец на
категорию в кг — ТРУБОЧКА → Трубочки, КЕКС, БАМБУК, МОГУЛЬ → Помадка, Придзел, ПЕЧЕНЬЕ, ПЕСОЧНЫЙ, ШОКОЛАД, ИМПОРТ («ИТОГО» не берётся);
период — текущий год, лист полный за свои месяцы. Регион находится по «Контрагенту»: название региона, дилер региона или **другое имя дилера**
(ниже). Листы «ПЛАН / ФАКТ» и «ПЛАН / ФАКТ Первичка» — сводки (текущий месяц и итоги 2025 года по категориям), для привязки не подходят.

**Другие имена дилера** (`sales.Regions.DealerAliases`, «Настройки продаж → Регионы», строка под дилером): прежние дилеры и второй дилер того
же склада Linko. По ним строки планов и отчётов (Google Sheets, AI Data Manager) находят регион; подпись строк — по-прежнему дилер региона.
Сменили дилера — прежнее имя добавляется само (в «Настройках продаж», переносом настроек или привязкой «Дилер региона»). Пример: у Ташкента с 14.10.2026
второй дилер на том же складе — в плане октябрь записан на него, январь–сентябрь на прежнего. Дилера региона не переименовываем: по его
имени акт сверки и DSO сопоставляют оплаты «Kassa Bank», а их ведёт прежний контрагент; новый записан другим именем.

**Одно поле — одна привязка**: план РОП можно привязать во «Вторичке» или в «Планах», но не в обоих — две таблицы перезаписывали
бы друг друга. В другом разделе видно, где поле уже обновляется.

## Владение данными

У каждого показателя один владелец (Source of Truth). «Последняя запись победила» между источниками не действует.

| Данные | Владелец | Кто пишет |
|---|---|---|
| Заказы, возвраты, визиты, точки, остатки, перемещения, оплаты, планы ТП | **Linko** | синхронизация Linko — своя копия данных (схема `linko`) и `sales.StaffPlans`; по ID Linko, повтор обновляет, а не дублирует |
| План РОП, «Завод», первички; дилер и СВР региона; P&L дилеров | **Google Sheets** — если поле ведёт включённая привязка | только синхронизация этой привязки |
| те же поля без привязки; цели | **OneBase** | AI Data Manager (чат, файлы), «Настройки продаж» |
| Выполнение, отклонение, прогноз; валовая прибыль, EBIT | **Расчёт** | никто: считается при показе из плана и факта, не хранится |

Как это обеспечено:

- **Linko не пишет данные OneBase.** Синхронизация Linko трогает только свою копию и планы ТП; регионы она создаёт по новым филиалам и
  переименовывает по названию филиала, а направление, СВР, дилер и планы регионов не меняет (тесты `LinkoPurgeTests`).
- **Google Sheets не пишет факт.** В каталоге полей (`DataSourceCatalog`) фактов нет: колонку «Фактические продажи» нельзя привязать к
  факту Linko.
- **Поле, которое ведёт привязка Google Sheets, меняет только она** (`FieldOwnership`, проверка на бэкенде):
  - чат AI Data Manager не готовит для него план изменений — ответ «поле ведёт Google Sheets «…» — меняйте значения в таблице или
    отключите привязку»;
  - план, подготовленный раньше (пока привязки не было или она была выключена), не применяется: владелец проверяется и при применении
    (`DataChangeSet.SourceBindingId` — какая привязка подготовила план);
  - «Настройки продаж → Регионы»: дилер и СВР из таблицы показаны только для просмотра (пометка «Google Sheets»), API отклоняет их правку.

  Каждая такая попытка — запись в журнале конфликтов. Выключенная или удалённая привязка поле больше не ведёт — его снова можно править
  в OneBase.
- **Сопоставление сущностей**: регион — по названию или дилеру, ID филиала Linko или старому филиалу «(эски)» (`DataMatcher`).
  Неоднозначно («подходит к нескольким регионам»: два филиала Linko с одинаковым названием — это два региона, они не склеиваются) или
  не найдено — строка не записывается и попадает в журнал конфликтов. Новые регионы создаёт только Linko — по ID филиала.

На странице «Источники данных» — блок **«Кто ведёт данные»**: по каждой группе данных владелец, откуда именно (таблица, листы, раздел,
расписание) и когда источник последний раз успешно обновил или подтвердил данные (Linko — по самой давней из своих сущностей группы,
Google Sheets — последняя синхронизация, прочитавшая поле без ошибок, OneBase — последнее применённое изменение). Устаревшие данные
не выдаются за свежие: время видно всегда.

## Журнал конфликтов

Таблица `DataSourceConflicts` (миграция DataSourceOwnership), блок **«Конфликты источников»**: источник, поле, что затронуто (регион,
категория, месяц), период, тип, причина, ячейка таблицы, правило владения, решение, нужно ли вмешательство, когда впервые и последний
раз, сколько раз.

- **Строка таблицы** (регион не найден или неоднозначен, не число, у региона на листах разные значения) — поле не записывается, прежние
  значения OneBase остаются. Конфликт открыт и ждёт исправления таблицы; та же ошибка при следующих синхронизациях — та же запись
  (счётчик), исправили строку — следующая синхронизация закрывает его сама («строка исправлена в таблице»).
- **Чужое поле** (чат, ручная правка, план прошлых дней) — отклонено, значение источника-владельца осталось. Событие: закрыто сразу,
  вмешательство не нужно.
- Удалили привязку или убрали из неё поле — её открытые конфликты закрываются, история остаётся. Можно закрыть и вручную: если строка
  всё ещё с ошибкой, синхронизация откроет конфликт снова.

## Привязка

Раздел → «Привязать Google Sheets»: таблица, **листы**, строка заголовков (с предпросмотром — переключатель между выбранными листами),
**какие поля обновлять** — и у каждого поля своё сопоставление столбцов (столбец — по заголовку или букве).

**Несколько листов.** В привязке можно отметить несколько листов с одинаковой разметкой (те же столбцы и строка заголовков) или «Все листы» —
тогда и новые листы, добавленные позже, читаются сами. Строки всех листов собираются в одну операцию: одна и та же строка плана на двух
листах с разными значениями — ошибка строки; дилер одного региона на листах разный — тоже ошибка строки (в журнале конфликтов). Пропавший из таблицы лист — ошибка
синхронизации со списком листов. Для планов и P&L месяц можно брать **из названия листа** («Сентябрь 2026», «09.2026», «2026-09»; без
года — год из привязки): лист на месяц, столбца месяца нет. Лист без месяца в названии (например «Справка» при «Все листы») — ошибка поля.

**Период** (планы и P&L, когда месяц — столбцом или в названиях листов): какие месяцы листа брать — **текущий год** (по умолчанию у
новых полей; с 1 января — новый год), текущий месяц, последние N месяцев (с текущим), диапазон «с … по …» или все месяцы листа (за раз —
не больше 24). «Текущий» — по Ташкенту на момент синхронизации, период сдвигается сам. Строки других месяцев не пишутся и **не удаляются**:
режим «лист полный за свои месяцы» действует только в пределах периода. Листы «месяц в названии» вне периода не читаются; листа за период
ещё нет — статус «ждёт». Лист с историей больше 24 месяцев без периода — понятная ошибка «выберите период».

Сопоставление полей:

- **планы** — регион (дилер), категории (столбцом, каждая категория — свой столбец или без категорий — итог), месяц (столбцом:
  «сентябрь», «09.2026», «2026-09» — или один месяц для листа), год, единицы (кг или тонны), режим: «лист полный за свои месяцы»
  (строки этих месяцев, которых нет в листе, удаляются) или только добавлять и обновлять;
- **дилер, СВР** — столбец региона и столбец значения; пустая ячейка не стирает записанное;
- **P&L** — контрагент, статья (как в OneBase), сумма, месяц, год.

**Время синхронизации**: вручную, каждые 15 мин … 24 ч или ежедневно в ЧЧ:ММ (Ташкент); у новой привязки по умолчанию — **каждые
30 минут**. Фоновая служба раз в минуту запускает привязки, у которых подошло время. «Синхронизировать сейчас» работает при любом
расписании; выключенная привязка по расписанию не идёт. Ошибка по расписанию (Google недоступен, сеть, лист пропал) — **один повтор
через 5 минут**, вторая ошибка подряд — уже по расписанию; записанные раньше данные при ошибке не удаляются. Синхронизации Linko
(своё расписание в «Интеграции → Linko») и Google Sheets независимы: сбой одной не останавливает другую.

## ИИ-сопоставление столбцов

В окне привязки — кнопка **«Сопоставить с помощью ИИ»** (после предпросмотра листа). Ручной режим остаётся: любое предложение можно
поправить или сопоставить всё самому.

1. **Анализ** (`POST /api/settings/data-sources/auto-map`, ничего не записывает): бэкенд читает лист (заголовки и до 12 строк значений,
   до 40 столбцов) и отправляет модели ИИ проекта — через AI Gateway, основная модель из «Настройки → AI» (с резервной при сбое и
   учётом токенов): название таблицы и листа, столбцы, **допустимые цели раздела** (`plan_primary.region`, `plan_primary.value`,
   `plan_primary.category_value`, `plan_primary.month`, `dealer.value`, `pnl.amount`…), категории OneBase, поля, которые уже ведут
   другие привязки, и что ведёт Linko. Модель отвечает JSON: `sourceColumn`, `targetField`, `confidence`, `reason`,
   `transformType` (`tons_to_kg`, `month_text`, `date`), `category`, `requiresConfirmation`, `warnings` и месяц полей (`column`,
   `sheet`, `current`, `fixed`).
2. **Проверка ответа на бэкенде** (`SheetMapping.Validate`) — модель только предлагает:
   - цель не из списка раздела (в том числе факт Linko) — **отклонено**: ИИ не создаёт поля;
   - столбца нет в листе, неизвестная категория — отклонено;
   - поле ведёт другая привязка — **поле занято**, не сохраняется ни по предложению, ни по решению человека;
   - уверенность от `DataSources:AutoMap:AcceptConfidence` (0,85) — **выбрано сразу**; от `ReviewConfidence` (0,5) — **проверьте**; ниже —
     не сопоставлено;
   - всегда «проверьте»: P&L (финансы), заголовок похож на факт («Фактические продажи» → план), несколько столбцов на одну роль,
     общий план рядом со столбцами-категориями (задвоил бы план), поле, которому среди выбранного не хватает региона, плана или месяца.
3. **Предпросмотр**: таблица «столбец → поле OneBase», уверенность, причина, предупреждения; каждое соответствие можно принять,
   изменить или отклонить, «Принять все предложения ИИ» — одним нажатием. Месяц полей без столбца месяца выбирается там же. Панель
   сразу показывает, чего не хватает полю, — неполное не подтвердить.
4. **Подтверждение** (`POST /api/settings/data-sources/auto-map/confirm`): те же проверки ещё раз → обычная привязка
   (`DataSourceFieldBinding` — та же модель, что у ручного редактора) через `SaveBindingAsync`; поля существующей привязки, которых
   сопоставление не касалось, остаются. «В ручной редактор» (`dryRun`) — собрать поля без сохранения и поправить вручную.

ИИ вызывается только по кнопке: синхронизация (каждые 30 минут) читает сохранённое сопоставление. ИИ недоступен (нет ключа, сбой,
ответ не JSON) — понятная ошибка, ручной режим работает.

**Снимок заголовков.** Сопоставление хранит столбец по заголовку (по букве — если заголовок пуст или повторяется) и снимок заголовков
(`headers`: столбец → заголовок), у ИИ и у ручного редактора. Перед записью синхронизация сверяет лист со снимком
(`DataSourceRules.StructureError`): столбцы переставили — по заголовку всё на месте; заголовок переименовали или в букве теперь другой
столбец — поле не пишется («структура листа изменилась — сопоставьте заново»), а не читает не тот столбец. Повторный анализ
существующей привязки показывает, какие сохранённые сопоставления устарели. Старые привязки без снимка работают как раньше.

## Смена месяца

- **Факт Linko** приходит сам: синхронизация непрерывная (изменения по `last_tm`), страницы продаж и первички открываются на месяце
  последних данных — 1-го числа (данные «по вчера») это прошлый месяц целиком, со 2-го — новый. Планы ТП — из API планов Linko, тоже сами.
- **Данные OneBase** (планы РОП, «Завод», первички, P&L) на новый месяц нужно загрузить. Привязка Google Sheets подхватывает новый месяц сама,
  если месяц в таблице: столбцом, названием листа («Ноябрь 2026» при «Все листы») или режимом **«текущий месяц»** — лист «План» всегда про
  текущий месяц по Ташкенту, с 1-го числа значения идут в новый месяц. «Один месяц для всех строк» — только для разовой загрузки.
- **Защита «текущего месяца»**: у каждого записанного поля в журнале — месяц и отпечаток значений (без месяца). В новом месяце, если в листе
  те же цифры, что записаны за прошлый, синхронизация **по расписанию** ничего не пишет (статус «Ждёт новый месяц»): иначе в ноябрь
  скопировался бы октябрьский план, пока таблицу не обновили. Обновили таблицу — следующая синхронизация пишет в новый месяц. План
  действительно тот же — «Синхронизировать сейчас» записывает его как есть.
- **Напоминание**: фоновая служба раз в час (1–10-е число) проверяет планы по видам — был в прошлом месяце, а на текущий нет — уведомление
  в колокольчике и push всем с правом «AI Data Manager», одно на вид и месяц («Ноябрь 2026: «План первички» ещё не загружен», ссылка на
  «Источники данных»). На странице — полоса «Планы на <месяц>»: какой план загружен, какого нет.

## Как пишутся данные

Синхронизация (`DataSourceService.RunAsync`) читает таблицу и по каждому **отмеченному** полю готовит план изменений AI Data Manager
теми же планировщиками, что для загруженного отчёта; неотмеченные поля не трогаются. Дальше:

- **строки с ошибками** (регион не найден, не число, нет месяца) — поле не записывается совсем: план изменений отменяется, в журнале
  синхронизации — первые ошибки («Ташкентская обл. · …: регион не найден»), все строки — в журнале конфликтов. Так опечатка в таблице не
  стирает план региона;
- **пустой лист или недоступная таблица** — ошибка синхронизации, ничего не удаляется (режим «лист полный за свои месяцы» удаляет только
  строки месяцев, которые есть в листе);
- **без изменений** — план отменяется, статус «Без изменений»;
- **иначе** — применяется одной транзакцией с проверкой «данные не изменились после подготовки» и сверкой после записи.

**Реестры** (`ledger`, `terms`, `balance`) идут мимо AI Data Manager: это тысячи операций кассы и расходов, а не планы, и править
их в OneBase нельзя — только в таблице. Синхронизация заменяет копию поля целиком (`sales."DealerLedger"`, `sales."DealerTerms"`,
`DataSourceRegisters`): без изменений — «Без изменений», иначе одна транзакция и сброс кэша продаж. Пустой лист, нет даты в ячейке
`F1`, нет столбца — ошибка синхронизации, копия не трогается.

Каждая запись — операция в журнале AI Data Manager («Планы регионов: план первички · … · Google Sheets «План 2026» / План») от имени того,
кто настроил привязку (по кнопке — того, кто нажал), с откатом там же. Итог по полям — в «Журнале» привязки (таблицы
`DataSourceConnections`, `DataSourceBindings`, `DataSourceSyncRuns`, миграция DataSources). Одна привязка не запускается дважды
одновременно.

## Перенос настроек на сервер

«Экспорт настроек» (над подключениями) — файл `onebase-data-sources-ГГГГ-ММ-ДД.json`: таблицы Google **без ключей** (название, ссылка,
доступ, почта сервисного аккаунта), привязки (листы, строка заголовков, поля и сопоставление, расписание) и дилеры регионов с другими именами
(регион — по id филиала Linko). «Импорт настроек» на другом OneBase (право «AI Data Manager»): файл и, для закрытых таблиц, которых там ещё
нет, ключ JSON сервисного аккаунта. Сначала «Проверить» — что добавится и обновится, без записи; затем «Перенести»:

- таблица с тем же ID уже подключена — остаётся как есть, со своим ключом; новая — подключается и проверяется (без ключа — строка с ошибкой);
- дилеры — до привязок (по ним план находит регион); дилер, которого ведёт привязка «Дилер региона», не меняется;
- привязка с той же таблицей, разделом и набором полей — обновляется, иначе создаётся; правило «одно поле — один источник» то же;
- данные не синхронизируются сразу — привязки идут по своему расписанию или по «Синхронизировать сейчас».

Импорт пишется в журнал аудита (`datasource.imported`). Действующий набор (28.10.2026): «План первички» — «Kassa Bank» (оплаты, статьи 101
и 103, с 01.08.2025), «АКТ-СВЕРКА» (остатки), «План Первичка данный» (план первички); «DSO» — «Прочие расходы 1» (расходы), «Ostatka»
(нормы); 22 дилера регионов, у Ташкента — другое имя (второй дилер склада). Сверка с рабочим компьютером: план — 1155 строк, расхождение 1,2 кг
в 14 строках «Придзела» за август (в таблице дробные кг, в загруженном ранее файле — округлённые).

`SourceOwnershipTests` (PostgreSQL, Linko — подставной сервер `FakeLinko`, Google — `FakeSheets`):

- план из Google Sheets и факт Linko — в любом порядке и одновременно: оба сохраняются, повтор Linko не создаёт дублей заказов,
  повтор Google Sheets — «без изменений», выполнение (факт ÷ план) пересчитывается без двойного учёта;
- Linko недоступен — данные Google Sheets на месте и Google Sheets работает; Google недоступен по расписанию — данные на месте, повтор
  через 5 минут, вторая ошибка — по расписанию; Linko в это время работает; пустой лист ничего не удаляет;
- чат и ручная правка не меняют поле, которое ведёт таблица (и при применении плана, подготовленного раньше); поля без привязки
  меняются как раньше; карта владения;
- строки с ошибками — в журнале до исправления таблицы; одинаковое название при разных ID Linko — два региона, строка неоднозначна;
  удаление привязки закрывает её конфликты.

`SheetMappingTests` и `SheetAutoMapTests` (ИИ — подставной AI Gateway, остальное настоящее): модель получает заголовки, примеры и

## Ограничения

- В OneBase одна организация: разделения данных по организациям (tenant) нет.
- Сопоставление сотрудников и торговых точек из Google Sheets не нужно: таблицы ведут планы по регионам и дилерам, а не по агентам и
  точкам (планы ТП — из Linko). Отдельного справочника соответствий внешних кодов нет — регионы сопоставляются по названию, дилеру
  или ID филиала Linko, неоднозначное не склеивается.
- Откат операции в журнале AI Data Manager владельца не проверяет: возврат прежних значений — осознанное действие администратора;
  следующая синхронизация привязки снова запишет значения таблицы.
- Устаревание видно по времени обновления в «Кто ведёт данные»; страницы продаж время обновления плана пока не показывают.
- За одну запись — не больше 24 месяцев (предел AI Data Manager): лист с историей за годы берите с периодом поля.
- ИИ видит до 40 столбцов и 12 строк значений. Категории — только категории OneBase (`Sales:Categories`), с синонимами: тип товара
  Linko или основа слова («МОГУЛЬ» → Помадка, «ТРУБОЧКА» → Трубочки, «ИМПОРТ» → Импорт); столбец без такой категории остаётся
  несопоставленным.
