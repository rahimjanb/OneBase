# Цифровой двойник (Operational Twin)

Раздел «Цифровой двойник» (`/twin`, пункт меню после «Обзора») — 3D-модель территории завода (перенос `factory-3d.html`), где каждое здание
привязано к отделам и складам OneBase и показывает их операционные показатели из модулей. Своих данных и расчётов у двойника нет.

## Как устроено

| Часть | Где |
|---|---|
| Здания модели: ключи `A`…`J`, названия по умолчанию | `backend/src/OneBase.Application/Twin/TwinModels.cs` (`TwinSite`), геометрия — `frontend/src/lib/twin-site.ts` (те же ключи) |
| Привязки по постоянным идентификаторам | схема `twin`: `Objects` (ключ, название в компании), `ObjectLinks` (`DepartmentId` → `Departments`, `WarehouseId` → `procurement.Warehouses` или `LinkoStockId` — склад готовой продукции Linko; ровно одно в строке) |
| Снимок предприятия | `TwinService.SnapshotAsync` → `GET /api/twin` |
| Вид: слои, цвета, KPI, карточка, проблемы | `frontend/src/lib/twin.ts` (чистые функции, тесты — `twin.test.mjs`) |
| 3D-сцена | `frontend/src/components/twin/TwinScene.tsx` (npm `three`, только в браузере) |
| Страница, панель, редактор привязок | `frontend/src/components/twin/TwinView.tsx`, `TwinPanel.tsx`, `frontend/src/app/(app)/twin/page.tsx` |

**Данные — только из сервисов разделов, с контекстом пользователя.** `TwinService` вызывает те же методы, что и контроллеры разделов:
`WorkTaskService` (задачи отделов), `HrService` (явка; по отделу — подразделения Verifix с привязкой к отделу и их дочерние),
`ProcurementRequestService` / `ProcurementPurchaseService` / `ProcurementInsightService` / `ProcurementStockService` (заявки, просрочка закупки,
закупки месяца, склад), `SalesDataLoader` (вторичка), `PrimaryService` (первичка), `StockService` (склад «Завод»), `SettlementsService` + `DsoCompute`
(дебиторка), `PromoService` (акции), `AiAlerts` (находки AI, категория — код отдела). Что пользователь не видит в разделе — того нет и в двойнике.

Каждый блок снимка — `{ state, data }`: `ok`, `noaccess` (нет права — в интерфейсе «Нет доступа»), `nodata` (в OneBase данных нет — «Нет данных»),
`error` (источник не ответил — остальные блоки работают). Источники собираются параллельно в своих scope; расчёты продаж — по очереди:
без кэша это тяжёлые запросы к зеркалу Linko, пять сразу упираются в общую память PostgreSQL. С кэшем снимок — ~0,15 с, без кэша — секунды:
страница ждёт его на сервере не дольше 2,5 с, иначе открывается сразу и догружает показатели в браузере.

## Права

- Раздел — с общими правами компании (как «Обзор»).
- Привязки и названия зданий — право «Пользователи» (`users.manage`), как руководители отделов; каждое изменение — в журнал аудита
  (`twin.object.updated`, было/стало). Отдел или склад, привязанный к зданию, удалить нельзя (внешний ключ) — сначала снять привязку.

## Чего в OneBase нет (показывается «Нет данных»)

Производство: план и факт выпуска, выполнение плана, загрузка. Бюджеты отделов. Маркетинг: кампании, лиды, рекламные расходы. Стоимость складских
запасов (склад снабжения ведётся в количестве). Дебиторка без реестра оплат дилеров (как раздел DSO). «Расходы» отдела — только закупки через снабжение.
Первичка показывается рядом с производством и подписана «это отгрузки, не выпуск».

## Слои и цвета

Цвет здания — худший статус привязанных к нему отделов и складов по показателю слоя; серый — нет данных или доступа, приглушённый — здание вне
слоя, синий — данные есть, нормы нет.

| Слой | Правило |
|---|---|
| Производство | выпуска нет — серый |
| Склад | снабжение: нет в наличии — красный, ниже минимума — жёлтый; «Завод»: SKU с дефицитом (< 15 дней продаж) — жёлтый |
| Снабжение | заявки отдела: просрочена дата закупки — красный, срочные открытые — жёлтый; здание отдела снабжения — путь закупки всей компании |
| Финансы | финотдел: ПДЗ — красный; остальные отделы — закупки месяца (сведения) |
| HR | явка сегодня: от 80% — зелёный, 70–79% — жёлтый, ниже — красный (правило HR) |
| Продажи | выполнение плана (в идущем месяце — прогноз): от 90% — зелёный, от 60% — жёлтый (`ExecutionLevelOf` раздела «Продажи») |
| Маркетинг | акции (сведения); кампаний и лидов нет |
| Задачи | просроченные задачи отдела — жёлтый; просрочено от 25% открытых — красный (порог двойника, в легенде) |

## Автообновление

Снимок обновляется раз в минуту, пока вкладка видна, сразу при возвращении на вкладку и по кнопке; камера, слой и выбранное здание не сбрасываются.
Слой и здание — в адресе (`/twin?layer=hr&b=J`).

## Дальше

AI-аналитика, прогнозирование и симуляция сценариев — следующий этап. Новые данные (модуль производства, бюджеты, маркетинг) добавляются в
