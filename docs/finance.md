# Финансы: 1С:Бухгалтерия → OneBase

Раздел «Финансы» (`/finance`) показывает **факт из 1С:Бухгалтерии для Узбекистана** (VENKON GROUP): доходы и расходы, деньги,
дебиторку и кредиторку, оборотно-сальдовую ведомость, проводки и документы, продажи, закупки, себестоимость, запасы, курсы валют,
отклонения. Данные приходят **только из 1С в OneBase**: OneBase ничего не записывает в 1С.

Контракт API — [integrations/ONEC_API_SPECIFICATION.md](integrations/ONEC_API_SPECIFICATION.md) (v1.1), вопросы к VENKON —
[integrations/ONEC_VENKON_QUESTIONS.md](integrations/ONEC_VENKON_QUESTIONS.md). Готовый HTTP-сервис для 1С по этому контракту — расширение
[`integrations/1c/OneBaseExchange`](../integrations/1c/OneBaseExchange/README.md) (устанавливает 1С-программист; в 1С ничего не пишется).

## Как устроено

```
1С:Бухгалтерия (192.168.9.141, HTTPS, только GET)
        │  пакеты по 500, курсор изменений
        ▼
onec-worker — служба интеграции (отдельный контейнер)
        │  проверка и нормализация, повторы, POST /api/internal/onec/* с ключом службы
        ▼
api — внутренний API OneBase (сеть docker; снаружи закрыт nginx)
        │  запись пакета, журнал изменений и курсор — одной транзакцией
        ▼
PostgreSQL, схема onec ──► «Финансы», AI-консультант (finance_*), Аналитик
```

- **Служба** (`backend/src/OneBase.Finance.Integration.Worker`) — без состояния: подключение к 1С — её переменные окружения или страница
  «1С» в OneBase (`SwitchableOneCDataProvider`: меняется без перезапуска; переменные службы главнее), всё остальное (курсоры, запуски,
  ошибки, история) — в OneBase. После перезапуска продолжает с последнего записанного пакета.
- **Источник данных** — `IOneCDataProvider`: `OneCHttpDataProvider` (API 1С по спецификации) или `OneCMockDataProvider` (тестовый
  источник с демо-данными: две организации, план счетов НСБУ №21, UZS/USD/EUR/RUB, реализация, закупки, касса, банк, производство,
  зарплата, кредит, дивиденды, закрытие месяца).
- **Внутренний API** (`/api/internal/onec`): вход только по ключу службы (`X-OneBase-Integration-Token`, в базе — SHA-256), запрос через
  nginx получает 404. Если подключение задано на странице «1С», пароль и API Secret хранятся в OneBase зашифрованными (ASP.NET Data
  Protection) и отдаются только службе методом `GET connection` по её ключу внутри сети docker.
- **Данные** — схема `onec`: организации, план счетов с видами субконто, контрагенты, договоры, валюты и курсы, склады, подразделения и
  прочие справочники, номенклатура, документы со строками, проводки (все субконто — jsonb, контрагент/номенклатура/склад — колонками),
  остатки и обороты по месяцам (оборотно-сальдовая ведомость 1С), журнал изменений. Служебные таблицы: запуски, курсоры, записанные
  пакеты (ключи идемпотентности), очередь ошибок, исторические загрузки, команды службе, состояние службы.

### Ключ записи и дубли

У каждой записи 1С — `SourceSystem` («1C»), `SourceOrganizationId` (организация; у общих справочников — пусто), `SourceEntityType`,
`SourceEntityId` (UUID ссылки 1С; у проводки — регистратор:строка; у курса — ВАЛЮТА:ДАТА), `SourceVersion`, `SourceUpdatedAt`,
`ImportedAt`, `UpdatedAt`, отпечаток содержимого. Уникальный индекс по ключу источника: повторная загрузка обновляет запись, а не
добавляет. Пакет записи данных одной организации не может изменить данные другой (такие записи отклоняются).

### Изменения, отмены, удаления

| В 1С | В OneBase |
|---|---|
| Исправили документ | новая версия; изменённые поля «было → стало» — в журнале изменений |
| Перепровели | набор проводок документа заменяется целиком; в журнале — «перепроведено» со старой и новой суммой |
| Отменили проведение | документ «не проведён», проводки помечены удалёнными; в журнале — «отмена проведения» |
| Пометка удаления / удалили | запись помечена удалённой, в отчётах не участвует, история остаётся |

Факты 1С меняет **только** загрузка из 1С: в разделе «Финансы» нет кнопок правки, расчёты OneBase в схему `onec` не пишут. Планы,
бюджеты и прогнозы OneBase хранятся в своих модулях и в отчётах финансов не смешиваются с фактом 1С.

### Валюта

Хранится как в 1С: сумма и валюта документа, курс и кратность, дата и источник курса, сумма в валюте учёта; у проводок — валютная
сумма и количество. Исторические суммы по текущему курсу не пересчитываются.

## Синхронизация

Каждые 30 минут (настраивается на странице 1С):

1. Проверка соединения и авторизации (`/ping`); другая база 1С (сменился `infobaseId`) — загрузка останавливается до решения
   администратора.
2. Запуск в OneBase — не больше одного (уникальный индекс по запуску со статусом Running; зависший без пульса 15 минут закрывается).
3. Справочники, которые ещё не загружены целиком.
4. Изменения 1С. **Сверка версий (только чтение, по умолчанию)**: `/versions` — идентификаторы и `ВерсияДанных` справочников и
   документов текущего и двух прошлых месяцев сравниваются с записями OneBase; новые и изменённые дочитываются по `ids=` (документы — с
   проводками), пропавшие перед пометкой удаления запрашиваются ещё раз (документ мог «переехать» в другой месяц). Раз в сутки после 2:00
   по Ташкенту сверяются все загруженные месяцы. Если 1С объявила план обмена (`changeTracking: "changes"` в `/ping`) — `/changes` с
   последнего курсора, курсор сохраняется в той же транзакции, что и пакет. Выбор: `ONEC_CHANGE_TRACKING` = auto / versions / changes.
5. Курсы за неделю; остатки и обороты — за текущий месяц и месяцы, где были изменения (если включён модуль «Бухгалтерия»).

**Организации и модули** (страница «1С», «Что загружать»): загружаются выбранные организации (пусто — все) и документы включённых модулей —
«Продажи», «Закупки», «Склад», «Деньги», «Производство», «Бухгалтерия» (проводки всех загружаемых документов, ручные операции, ведомость),
«Прочие». Справочники и курсы — всегда. Уже загруженные документы выключенного модуля остаются, но не обновляются. «Синхронизировать
модуль» — только документы этого модуля (проводки — если включена «Бухгалтерия»).
6. Повтор неуспешных операций, у которых подошло время.

Повторы: временные ошибки (сеть, тайм-аут, 429, 5xx, 503 с Retry-After) — до 5 попыток с паузой 2, 4, 8… с; авторизация, TLS и
ошибки запроса — сразу ошибка. Сбой запуска — следующий через 5 минут (до трёх раз подряд), дальше по расписанию. Пауза администратора
останавливает запуск на границе пакета.

**Очередь ошибок** («Ошибки» на странице 1С): страница 1С не получена (повтор — заново запросить ту же страницу), пакет не записан
(хранится целиком, повтор — тот же пакет с тем же ключом), запись отклонена (хранится целиком; повтор — по кнопке после исправления
в 1С). Данные не теряются.

**Историческая загрузка** (кнопка на странице 1С, с подтверждением): по месяцам, по организациям — курсы, документы, проводки, остатки.
Положение сохраняется с каждым пакетом; порция — до 15 минут, дальше продолжение. По каждому месяцу — сверка количества и сумм с
итогами 1С (`totals`). Повтор того же периода не создаёт дублей.

## Страница «Настройки → Интеграции → Финансы → 1С»

Право «Интеграции» (`integrations.manage`). Состояние службы и подключения по шагам (сеть → TLS и сертификат → авторизация → API),
последняя и следующая синхронизация, счётчики, загруженные данные; действия — проверить соединение, тестовая синхронизация (без
записи), синхронизировать сейчас и синхронизировать модуль, пауза и продолжение, историческая загрузка (дата начала — из настроек), повтор
ошибок; журнал запусков с шагами и отбором по дням, статусу и виду; ошибки с отбором по потоку; журнал изменений; **подключение к 1С**
(адрес HTTP API, пользователь, пароль и API Secret — только запись, сертификат PEM; откуда служба взяла подключение и как отслеживает
изменения); **что загружать** (организации, модули, начало истории); ключ службы (показывается один раз); «Подключить другую базу 1С»
(удаляет загруженные данные прежней базы — с вводом слова ОЧИСТИТЬ). Все действия — в аудите (`integration.onec.*`; пароль и секрет —
только «задан / убран»).

## Раздел «Финансы»

Право «Финансы» (`finance.read`). Обзор, доходы и расходы (форма №2 по счетам 90–98 без закрытия на 9910), деньги (поступления и
выплаты по корреспондирующим счетам без переводов между своими счетами и курсовых разниц), расчёты (счета 40 и 60 по контрагентам,
просрочка — оценка FIFO по документам и срокам оплаты), счета (оборотно-сальдовая ведомость, карточка счёта с аналитикой),
проводки и документы, продажи и склад, отклонения. Отбор — организация 1С, период и (во всех отчётах) **контрагент, номенклатура, склад,
подразделение** (подбор по названию, коду или ИНН; применённые отборы — плашками с крестиком): проводки — где значение в Дт или Кт,
документы — с ним (номенклатура — содержащие её), ведомость — по своим колонкам (подразделения в ведомости нет). На обзоре — **«День, месяц,
год»**: продажи (чистая выручка), валовая прибыль, закупки (поступления минус возвраты), затраты на производство (Дт 20) за день, с начала
месяца и с начала года на дату конца периода (не позже последних проводок). В каждом отчёте — источник, период, время синхронизации,
отборы и пометка демо-данных.

## AI

Инструменты `finance_overview`, `finance_pnl`, `finance_compare`, `finance_cash_flow`, `finance_settlements`, `finance_accounts`,
`finance_operations`, `finance_anomalies`, `finance_entries` (источник знаний «Бухгалтерия 1С»): только чтение, только пользователям с
правом «Финансы» и **только если администратор включил «AI-консультант может отвечать по данным 1С»** (по умолчанию выключено: итоги
и документы уходят во внешнюю модель). Субконто сотрудников и физлиц модель не получает. В каждом ответе — период, источник, время
синхронизации, отбор и ссылка в «Финансы». Изменять данные AI не может.

## Запуск

### Стенд с тестовым источником

```bash
# 1. OneBase с миграцией Finance1_OneCImport (применяется при старте API).
# 2. Ключ службы: «Настройки → Интеграции → Финансы → 1С» → «Создать ключ».
# 3. В .env стенда:
ONEC_INTEGRATION_TOKEN=<ключ>
ONEC_PROVIDER=mock
ONEC_ENABLED=true
ONEC_ALLOW_MOCK=true          # только на стенде: демо-данные не для рабочей базы
# 4. Служба:
docker compose --profile onec up -d --build onec-worker
docker compose logs -f onec-worker
# 5. Страница 1С: «Подключено к тестовому источнику» → «Запустить историческую загрузку».
```

### Рабочий сервер (192.168.9.168) — после установки HTTP-сервиса в 1С

1. 1С-программист устанавливает расширение `OneBaseExchange` (на копии базы, потом на рабочей — по
   [README](../integrations/1c/OneBaseExchange/README.md) и [CHECKLIST](../integrations/1c/OneBaseExchange/CHECKLIST.md)), публикует
   HTTP-сервис по HTTPS, открывает доступ **только** с 192.168.9.168, создаёт пользователя только для чтения и передаёт адрес, сертификат
   (если внутренний ЦС), пользователя, пароль и API Secret.
2. Проверка сети с сервера OneBase (ничего не меняет): `curl -sv --max-time 10 https://<адрес 1С>/<публикация>/hs/onebase/v1/ping`
   (без `-k`; при внутреннем ЦС — `--cacert deploy/onec/onec-ca.crt`).
3. Миграция уже применена с обновлением OneBase (`deploy/update.sh`). Резервная копия — `deploy/backup.sh` до обновления.
4. Ключ службы — на странице 1С.
5. В `.env` (добавить, ничего не заменяя): `ONEC_INTEGRATION_TOKEN`, `ONEC_ENABLED=false`. Подключение — на странице «1С» («Подключение
   к 1С»: адрес, пользователь, пароль, API Secret, сертификат) **или** в `.env`: `ONEC_BASE_URL`, `ONEC_USERNAME`, `ONEC_PASSWORD`,
   `ONEC_API_SECRET` (или `ONEC_TOKEN`), при внутреннем ЦС — файл в `deploy/onec/` и `ONEC_CA_CERT_PATH=/etc/onebase/onec/onec-ca.crt`
   (заданное в `.env` главнее страницы).
6. `docker compose --profile onec up -d --build onec-worker` — служба на связи, проверяет подключение, но не загружает. Страница 1С:
   все шаги диагностики зелёные → «Тестовая синхронизация» (проверка без записи).
7. Если на рабочем сервере раньше был тестовый источник — «Подключить другую базу 1С» → ОЧИСТИТЬ.
8. `ONEC_ENABLED=true`, `docker compose --profile onec up -d onec-worker`; «Запустить историческую загрузку» (вне рабочих часов
   бухгалтерии); чтобы служба поднималась вместе с остальными — `COMPOSE_PROFILES=tunnel,onec` в `.env`.

Остановить: `docker compose stop onec-worker` (данные и курсоры остаются в OneBase). Пауза без остановки — кнопка на странице 1С.

| Переменная `.env` | В контейнере | По умолчанию | Назначение |
|---|---|---|---|

| `ONEC_TOKEN` | `OneC__Token` | — | токен вместо пароля |

| `ONEC_CA_CERT_PATH` | `OneC__CaCertificatePath` | — | сертификат внутреннего ЦС |

| — | `OneBase__InternalApiUrl` | http://api:8080 | внутренний API (без nginx) |

## Если что-то не так

| Страница 1С показывает | Что делать |
|---|---|
| «Сеть: нет ответа … (тайм-аут)» | брандмауэр Windows на 192.168.9.141, правило ESXi, веб-сервер не запущен — к администраторам сети и VENKON; на OneBase ничего не менять |
| «отклонил соединение» | на порту нет веб-сервера (IIS/Apache) или он остановлен |
| «TLS: … неизвестным центром сертификации» | положить сертификат ЦС в `deploy/onec/`, указать `ONEC_CA_CERT_PATH` |
| «Авторизация отклонена (401)» | пользователь или пароль 1С; служба повторять не будет до исправления |
| «Служба подключена к другой базе 1С» | убедиться, что это нужная база → «Подключить другую базу 1С» |
| «Служба интеграции не на связи» | `docker compose ps onec-worker`, `docker compose logs --tail 100 onec-worker`; ключ службы |
| «Курсор изменений устарел» | историческая загрузка за период с последней синхронизации (только в режиме плана обмена) |
| «Подключение задано: переменные службы на сервере», а на странице другой адрес | в `.env` службы задан `ONEC_BASE_URL` — он главнее; убрать его, если подключением управляют со страницы |
