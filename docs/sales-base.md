# Sales Base — управление полевыми продажами

Sales Base — модуль OneBase для РМ, супервайзеров и агентов: команды, торговые точки, маршруты, визиты, задачи, KPI
и AI-рекомендации. Отдельный домен `sales.1base.uz`, тот же backend и тот же Next.js, mobile-first и PWA.

## Архитектура (как встроено в OneBase)

| Слой | Где | Что |
|---|---|---|
| Домен | `backend/src/OneBase.Domain/Field/` | сущности Sales Base, схема БД `field` |
| Логика | `backend/src/OneBase.Application/Field/` | доступ (FieldAccess/FieldScope), сервисы, чистая математика (гео, маршрут, KPI, правила AI) |
| Данные Linko | `ILinkoSalesProvider` → `LinkoMirrorSalesProvider` | нормализует зеркало Linko (продажи, визиты, планы, точки) для Sales Base |
| Инфраструктура | `OneBase.Infrastructure/Persistence/FieldModel.cs`, `Field/FieldStatsRefresher.cs` | EF-модель, витрина статистики точек, фоновые задачи |
| API | `OneBase.Api/Controllers/Field*Controller.cs` | `/api/field/*` |
| AI | `OneBase.AI/Tools/Data/FieldTools.cs` | инструмент консультанта по данным Sales Base |
| Frontend | `frontend/src/app/(field)/field/**`, `components/field/**` | свой shell (sidebar на desktop, нижняя навигация на телефоне) |

Почему так:

- **Префикс `field`, а не `sales`.** `/sales` и `/api/sales` уже заняты аналитикой продаж (вторичка, аутсток…);
  проверки `startsWith("/sales")` во фронтенде зацепили бы новый модуль.
- **Схема `field`.** Сброс Linko (`PurgeAsync`) и `deploy/restore-linko.sh` очищают схемы `linko` и `sales`; данные Sales Base
  (маршруты, визиты, задачи) не должны пропадать при перезагрузке Linko.
- **Без внешних ключей в `linko.*`.** Точки, агенты и филиалы связаны с Linko по его `long`-идентификаторам (MarketId,
  LinkoUserId, BranchId): TRUNCATE зеркала без CASCADE не должен ломаться, а `sales.Regions` при сбросе получают новые Guid.
- **Точки не дублируются.** Торговая точка — это `linko.Markets` (49 981 точка, у всех координаты и ответственный агент);
  `field.Customers` — только то, чего нет в Linko: назначенный в Sales Base агент, приоритет, статус, план, контакт.
- **Linko только читается.** Смена агента, маршруты и визиты Sales Base в Linko не записываются (интеграция read-only).

## Роли и доступ

Права (JWT claim `perm`): `field.use` — работа в Sales Base, `field.manage` — управление (состав, команды, настройки).
Роли создаются при запуске: «РМ (Sales Base)», «Супервайзер», «Агент». Администратор получает все права.

Кто есть кто в Sales Base — `field.Members` (пользователь OneBase ↔ сотрудник Linko, роль RM/Supervisor/Agent, команда).
Область видимости (`FieldScope`) вычисляется на backend из участника, а не из запроса:

- **РМ** — все команды (или только команды своих филиалов, если они заданы); без участника, но с `field.manage` — вся организация.
- **Супервайзер** — агенты своих команд, их точки, маршруты, визиты, задачи.
- **Агент** — только свои точки, маршруты, визиты, задачи, продажи и KPI.

Любой объект по id проверяется по области: чужой → 404, как будто его нет (защита от IDOR).
Отключённая карточка участника закрывает Sales Base даже при праве `field.manage`.

Управление составом:

- **РМ всей организации или администратор** — импорт из Linko, настройки, журнал действий, карточки и вход РМ, любые команды.
- **РМ филиалов** — команды своих филиалов, их агенты и супервайзеры. Агента можно поставить только в команду своего филиала,
  сотрудника Linko — только своего филиала. Супервайзер, который ведёт команду другого филиала, РМ филиала не виден и не назначается.
- **Супервайзер** — даже с `field.manage` состав не меняет, только планы своей команды.
- Свою роль, доступ, филиалы, команду и привязку к Linko не меняет никто сам себе; свой пароль из Sales Base не сбрасывается.
- Пароль сбрасывается только у входа «только Sales Base» (роль «Агент» или «Супервайзер»). Вход РМ и учётные записи с другими
  ролями OneBase меняет администратор пользователей (`users.manage`). Отключённый вход сброс пароля не включает.

Рекомендации AI видят и решают РМ и супервайзер текущей команды агента, агент их не видит (подтверждённые приходят ему задачами).
Фото к визиту — во время визита или в течение 30 минут после него. Агент строит маршрут себе, только если на этот день его ещё нет.

## Данные

| Таблица | Назначение |
|---|---|
| `field.Members`, `field.Teams` | участники и команды (супервайзер + агенты, филиал Linko) |
| `field.Customers` | оверлей точки Linko: агент Sales Base, приоритет, статус, план, контакт |
| `field.CustomerStats` | витрина: последний визит и продажа, продажи 7/30/90 дней, тренд; пересчёт после синхронизации |
| `field.Routes`, `field.RoutePoints` | маршрут агента на день и его точки (порядок, время, статус) |
| `field.Visits` | визит Sales Base: начало/конец, координаты, расстояние до точки, результат, комментарий, фото |
| `field.JointVisits`, `field.JointVisitParticipants` | совместные выезды |
| `field.Tasks` | задачи (РМ, супервайзер, AI, система) |
| `field.Recommendations` | рекомендации AI: причина, исходные данные, уверенность, решение, созданная задача |
| `field.Notifications` | уведомления внутри приложения |
| `field.Settings` | настройки: радиус геозоны, точность GPS, длина маршрута, пороги AI, автопланирование |

Журнал действий — общий `AuditLogs` OneBase (`field.*`-действия).

## Источники цифр

- **Продажи** — заказы Linko: за день — заказы, принятые агентом в этот день (`CreatedDate`, без отменённых); за месяц и
  по точке — доставленные по дате приёмки, как во вторичке.
- **План** — staff_balance Linko (`sales.StaffPlans`): кг (`product_sales_weight`), сумы (`sales_sum`), АКБ.
- **Визиты Linko** — план дня (`pending`, в плане) и выполненные визиты; из них строится маршрут дня, а выполненный визит Linko
  отмечает точку маршрута посещённой.
- **Визиты Sales Base** — свои записи с геолокацией и результатом.

## Домен sales.1base.uz

Тот же Next.js: `proxy.ts` переписывает запросы хоста `FIELD_HOST` (по умолчанию `sales.1base.uz`) в `/field/*`, манифест PWA и
заголовок страницы зависят от хоста. nginx: отдельный server на порту 81 с `PUBLIC_HOST=${FIELD_HOST}`; в Cloudflare Tunnel —
public hostname `sales.1base.uz → http://nginx:81`. Вход на sales.1base.uz — отдельный (cookie без domain).

У Sales Base своя страница входа: `/login` на его домене (proxy переписывает в `/field/login`) и `/field/login` внутри OneBase.
Без сессии страницы Sales Base ведут на неё, проверка пароля общая с OneBase. Профиль в шапке и внизу боковой панели
открывает меню с ролью, командой и кнопкой «Выйти»; выход (`/logout?to=field`) возвращает на вход Sales Base.

## Первый запуск

1. **Импорт состава.** Sales Base → «Команды и доступы» → «Импорт из Linko» (РМ или администратор). Добавляются действующие
   агенты (JobName «Агент») и супервайзеры Linko; на каждый филиал с агентами создаётся команда, филиал агента — где
   большинство его точек. Супервайзер встаёт во главе команды своего филиала, если это видно по его визитам или должности
   («Супервайзер для Бухоро»); остальным командам супервайзера назначает РМ.
2. **Доступы.** «Выдать вход» у участника создаёт пользователя OneBase с ролью «Агент», «Супервайзер» или «РМ (Sales Base)».
   Логин — из Linko, пароль показывается один раз. Вход — `sales.1base.uz`, с телефона «Установить приложение».
3. **Настройки** (РМ): радиус геозоны и допуск GPS, длина автоматического маршрута, скорость и длительность визита, пороги
   AI-планирования, автопланирование (по умолчанию выключено).

## AI-планирование (первый этап)

Раз в день после 6:00 (и по кнопке «Проанализировать сейчас») правила создают рекомендации — план сразу не меняется:

| Правило | Когда | Предложение |
|---|---|---|
| Падение продаж | продажи точки за 30 дней ниже прошлых 30 на `DeclinePct`% и больше | визит в течение 2 дней |
| Клиент перестал покупать | 30 дней без заказов, до этого покупал | вернуть клиента, приоритет высокий |
| Давно не посещали | точка с продажами без визита `NotVisitedDays` дней | визит |
| Отставание от плана | агент отстаёт от темпа месяца на `BehindPlanPct` п.п. (с 5-го рабочего дня) | задача супервайзеру: разбор, совместный выезд |
| Пропущенная точка | точка маршрута пропущена вчера/позавчера | повторный визит |
| Точка без агента | ответственный в Linko — вакансия или не действующий агент | назначить агенту филиала с наименьшей нагрузкой |

У каждой рекомендации — причина, исходные цифры (`SourceData`), уверенность. Подтверждение создаёт задачу (и ставит точку в
маршрут на срок), «точка без агента» — назначает агента. Не больше 5 рекомендаций по точкам на агента за прогон; отклонённая
не повторяется 14 дней. Маршрут строится из задач с точкой, плана визитов Linko на день и (если плана нет) точек, которые
пора посетить; порядок — ближайший сосед + 2-opt. Консультант OneBase видит Sales Base через инструмент `get_field_team`.

## Мобильная версия и офлайн

PWA со своим манифестом и иконками на домене Sales Base. Service worker кэширует страницы Sales Base и ответы `/bff/api/field/*`
по принципу «сначала сеть»: без связи открываются уже загруженные маршрут, задачи и точки. Кэш очищается при выходе,
на странице входа, при ответе 401 или переадресации на вход и когда на устройстве вошёл другой пользователь.
Начать или завершить визит без связи нельзя — интерфейс сообщает об этом; офлайн-синхронизация визитов — следующий этап.

## Ограничения

- Смена агента точки, маршруты и визиты Sales Base в Linko не записываются (интеграция только читает).
- Позиция агента на карте супервайзера — по координатам последнего визита Sales Base (постоянного трекинга нет).
- План в сумах есть в Linko не у всех агентов; дневной план — месячный ÷ рабочие дни (пн–сб).
- Роль «РМ (Sales Base)» даёт и раздел продаж OneBase (`sales.read`): там РМ филиала видит аналитику всех филиалов.
  Если это нежелательно, РМ филиалов выдают роль без `sales.read`.
- Справочник участников и настройки кэшируются в памяти процесса API. При нескольких экземплярах API изменения состава
  доходят до других экземпляров с задержкой до 30 секунд, настройки — до 5 минут.
- В совместном выезде список участников показывается целиком, даже если среди них есть участник другой команды.
