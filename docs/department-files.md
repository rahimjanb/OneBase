# Файлы отделов (Department Files)

У каждого отдела OneBase своё файловое пространство. С ним работают двумя способами — и это **одно хранилище**:

- на сайте: раздел «Файлы» (`/base`, адрес `/files` ведёт туда же);
- в Windows: папка отдела подключается сетевым диском по WebDAV через HTTPS (`https://files.1base.uz/production`).

Файл, положенный через Проводник, сразу есть в базе и на сайте; загруженный на сайте — сразу в той же папке Windows. Второй копии нет.

Кроме папок отделов есть **общие папки** («Общие файлы») — для нескольких отделов и сотрудников; их видят только те, кому выдан доступ.
У каждого сотрудника может быть **личная ссылка Windows** («Мой диск Windows») — один диск со всем, что ему доступно.

## Архитектура

```
Проводник Windows ──HTTPS/WebDAV──► Cloudflare Tunnel ──► nginx :82 ──► API (WebDavHandler)  ─┐
Браузер ──HTTPS──► Cloudflare ──► nginx :80 ──► Next.js /bff ──► API (FilesController)       ─┤
                                                                                             ▼
                                                              DepartmentFilesService (права, версии, корзина, журнал)
                                                                 │                          │
                                                          PostgreSQL (метаданные)      MinIO (содержимое версий)
```

- **API** — один и тот же сервис `DepartmentFilesService` для сайта и для WebDAV: права (`FileAccessRules`), версии, корзина и журнал одинаковые.
- **WebDAV** — `OneBase.Api/Files/WebDavHandler.cs` (RFC 4918, классы 1 и 2): OPTIONS, PROPFIND, PROPPATCH, GET, HEAD, PUT, DELETE, MKCOL, MOVE, COPY, LOCK, UNLOCK.
  Снаружи весь домен файлов — WebDAV: nginx :82 передаёт адрес без изменений и ставит `X-Dav-Root: /`; nginx :80 и :81 этот заголовок
  стирают. На самом сервере тот же WebDAV доступен по `http://api:8080/dav/…`.
- **Сайт** — `FilesController` (`/api/files/…`), страницы `frontend/src/app/(app)/base`, компоненты `frontend/src/components/files`.

## Хранилище

- **MinIO** — тот же, что у всего OneBase (`Minio:*`, бакет `MINIO_BUCKET`). Ключ объекта — `files/{id файла}/{id версии}`: имя файла в ключ не
  входит, поэтому имя не может увести за пределы отдела. Каждая версия — свой объект.
- **PostgreSQL** — метаданные:
  - `Folders` — дерево папок отдела (`DepartmentId`, `ParentId`, `CreatedById`, `DeletedAt`). Корневая папка отдела создаётся при первом
    открытии вместе с «Документы», «Отчёты», «Архив»; она одна на отдел (`IX_Folders_DepartmentRoot`).
  - `Files` — файл (`DepartmentId`, `FolderId`, `SizeBytes`, `CurrentVersion`, кто изменил — сотрудник или подключение, `DeletedAt`).
  - `FileVersions` — версии (номер, ключ MinIO, размер, SHA-256, кто загрузил — `UploadedById` или `UploadedByConnectionId`).
  - `ResourcePermissions` — выдачи доступа к папке отдела другим отделам (субъект `Department`).
  - `FileConnections` — подключения к Windows (миграция `DepartmentFiles`); `LinkExpiresAt` — срок ссылки отдела.
  - Общие папки — те же `Folders` и `Files` с `SharedRootId` (id корня общей папки; у корня — свой id) и без `DepartmentId`;
    доступ — `ResourcePermissions` на корне (субъект `User`, `Department` или `Role`, уровень `Read` / `Write` / `Manage`). Старые
    папки без отдела и без `SharedRootId` (до папок отделов) никому не показываются.
  - `FileLocks` — блокировки WebDAV (файл, токен, кто, владелец из LOCK, до какого времени).
  - `FileUserLinks` — личные ссылки Windows (хэш и шифр кода, срок, отзыв, последняя активность).
- Миграция `DepartmentFiles` только добавляет колонки, таблицу и индексы; `FileVersions.UploadedById` становится необязательным. Данные не удаляются.
- Миграция `FileConnectionLinks` добавляет к `FileConnections` три пустых столбца (`LinkTokenHash`, `ProtectedLinkToken`, `LinkChangedAt`) и
  уникальный индекс по хэшу ссылки. Откат: `dotnet ef database update TelegramGenerationModel`.
- Миграция `SharedFilesAndLocks` только добавляет: столбцы `Folders.SharedRootId`, `Files.SharedRootId`, `FileConnections.LinkExpiresAt`
  (пустые), таблицы `FileLocks` и `FileUserLinks`, индексы. Уже выпущенным ссылкам отделов ставит срок — год от выпуска (подключённые
  диски продолжают работать). Откат: `dotnet ef database update RegionDealerAliases`.

## Права

Одно правило для сайта и WebDAV (`FileAccessRules`), данные — из БД на момент запроса (роль, сменённая после входа, действует сразу):

| Кто | Свой отдел | Чужой отдел |
|---|---|---|
| Сотрудник с `files.read` | чтение | только если отделу выдан доступ (чтение или запись) |
| Сотрудник с `files.write` | чтение и запись | выданный уровень |
| Администратор (`files.manage`) | всё | всё, управление подключениями и доступом |
| Директор (`files.read.all`) | по своим ролям | **просмотр всех отделов** (только чтение, без логинов подключений) |
| Подключение Windows отдела | уровень подключения (запись) | ничего |

Общие папки (`FileAccessRules.AccessToShared`): видны только по выдаче — сотруднику, его роли или отделу; администратору — все (управление).
Просмотр всех отделов (`files.read.all`, директор) общих папок не открывает. «Редактирование» и «Управление» по выдаче действуют только при
`files.write` в роли, иначе — просмотр; без прав на файлы (раздел «Файлы» снят) — ничего. Подключение Windows отдела видит общие папки,
выданные его отделу, не выше своего уровня и без управления. Личная ссылка — ровно права сотрудника.

`files.read.all` по умолчанию только у ролей «Администратор» и «Директор» (у существующей роли директора право добавляется при запуске,
`SystemRoles.Upgrades`). На странице «Файлы» отделы показаны папками верхнего уровня: «Файлы» → «Производство» → «Отчёты».
«Свой отдел» — отдел сотрудника и отделы его ролей. Доступ другого отдела к папке задаёт администратор в окне «Подключить к Windows» →
«Доступ других отделов к папке» (нет / только чтение / чтение и запись). Чужие папки и файлы отвечают 404, как несуществующие — по
перебору id ничего не узнать. Запись в отдел только на чтение — 403.

## Подключение к Windows

- **Способ — WebDAV по HTTPS.** Путь вида `\\files.1base.uz\production` — это SMB (порт 445): через Cloudflare Tunnel он не проходит
  (только с клиентом Cloudflare WARP на каждом компьютере), а открывать SMB в интернет небезопасно. Windows подключает WebDAV штатно:
  «Подключить сетевой диск» → адрес `https://files.1base.uz/production` (или путь `\\files.1base.uz@SSL\production`).
- **Главный способ — адрес без пароля (секретная ссылка отдела)**: `https://files.1base.uz/k/{код}/production` (путь Windows
  `\\files.1base.uz@SSL\k\{код}\production`). Диск подключается по нему без логина и пароля, **Word и Excel открывают и сохраняют
  файлы сразу**. Причина: Microsoft 365 (с версии 2311; розничные Office 2016–2021) блокирует вход по логину и паролю (Basic) на любой
  сервер — «Microsoft Office заблокировал доступ… метод входа, который может быть небезопасным», — пока это не разрешено на каждом
  компьютере политикой `basichostallowlist`. По ссылке сервер пароль не спрашивает вовсе, поэтому на компьютерах ничего настраивать не нужно.
  - Код — 32 знака (строчные буквы и цифры без похожих, 160 бит), подобрать нельзя. В базе — SHA-256 кода (`FileConnections.LinkTokenHash`,
    по нему ищется подключение) и копия, зашифрованная Data Protection (`ProtectedLinkToken`), для «Показать»/«Скопировать».
  - Ссылка работает как пароль: показывается тем же, кому пароль, отдельным POST (`…/connection/link`), факт показа — в журнал
    (`files.connection.link.revealed`). Видна только папка своего отдела, как у логина.
  - **Новая ссылка** (администратор, `…/connection/link/regenerate`) — старая перестаёт работать сразу (кэш входа сбрасывается),
    диск на компьютерах отдела подключают по новой. Отзыв подключения отключает и ссылку, и логин.
  - Подключения, созданные до ссылок, получают ссылку при первом открытии окна «Подключить к Windows» (`files.connection.link.created`).
  - Неверная ссылка — 404, без запроса пароля. Служебные запросы Office без входа к корню сервера и к адресам FrontPage (`/_vti_…`) — тоже
    404: ответ 401 с запросом пароля Office считает «небезопасным входом» и блокировал бы файл, открытый по ссылке. Проводник у корня
    по-прежнему получает 401 и входит по логину.
  - Код в журналы не попадает: nginx :82 пишет адрес как `/k/***/…` (`log_format dav_masked`), а журнал ошибок :82 — только
    критические (ошибки подключения к API nginx пишет с полным адресом). ASP.NET адреса запросов не пишет (`Microsoft.AspNetCore: Warning`).
- **Логин на отдел** (решение заказчика) остаётся для Проводника: `production_8f3a1`, пароль — 20 случайных символов. Логин и пароль видят сотрудники с правом
  записи в отделе и администраторы (подключение даёт запись — читателю его не показывают). Действия через подключение пишутся в журнал от имени
  подключения («Windows · production_8f3a1»), а не конкретного сотрудника.
- **Создать / новая ссылка / сменить пароль / отозвать** — администратор. Всё действует сразу (кэш проверенных входов сбрасывается).
- **Проверить подключение** — настоящая проверка: адрес настроен, подключение действует, MinIO пишет и читает проверочный объект, папка отдела
  есть в базе, публичный адрес отвечает на PROPFIND с логином и паролем отдела и **по ссылке без пароля** (через Cloudflare и nginx, как Windows).
- **Инструкция** строится на сервере: подключение по адресу без пароля; «Скопировать для сотрудников» даёт адрес и путь Windows, в скачанную
  инструкцию ни ссылка, ни пароль не пишутся.

### Ограничения Windows и Cloudflare

- Windows по умолчанию открывает через WebDAV файлы до 50 МБ. Поднять предел (PowerShell от имени администратора):
  `reg add HKLM\SYSTEM\CurrentControlSet\Services\WebClient\Parameters /v FileSizeLimitInBytes /t REG_DWORD /d 4294967295 /f; Restart-Service WebClient`.
- Cloudflare на бесплатном тарифе пропускает до 100 МБ на запрос — большие файлы загружайте на сайте (до 200 МБ).
- Служба «Веб-клиент» (WebClient) должна работать: в Windows 10/11 она есть и запускается по требованию; если Windows пишет «Указанное имя папки
  недействительно» — `services.msc` → «Веб-клиент» → «Запустить», тип запуска «Автоматически».
- Пароль по Basic Windows отправляет только по HTTPS (настройка `BasicAuthLevel=1` по умолчанию) — поэтому адрес только https.
- Word и Excel из Microsoft 365 по логину и паролю (Basic) файлы с диска не открывают — для работы с документами диск подключают по адресу
  без пароля (см. выше). Если всё же нужен вход по паролю, Office разрешают вход на сервер политикой «Allow specified hosts to show Basic
  Authentication prompts to Office apps» (`HKCU\Software\Policies\Microsoft\Office\16.0\Common\Identity`, значение `basichostallowlist`).
- Новые файлы с сайта Проводник показывает при следующем открытии папки или по F5. Сайт перечитывает папку раз в 15 секунд — файлы из Windows
  появляются без «Обновить».
- Блокировки (LOCK) настоящие — см. «Word, Excel и блокировки».

## Общие файлы

- **Что это.** Общая папка — отдельное пространство для нескольких отделов и сотрудников: не внутри отдела и не копия его файлов. На сайте —
  раздел «Общие файлы» на странице «Файлы» (`/base/shared/{id}`); в Windows — папка рядом с папками отделов
  (`https://files.1base.uz/k/{код}/Общие файлы`).
- **Кто создаёт.** Администратор: «Файлы» → «Новая общая папка». Пока доступ никому не выдан, папку видят только администраторы. Имя не может
  совпадать с кодом отдела, начинаться с «_» или быть «k» (они стоят в адресе WebDAV на том же месте).
- **Доступ.** В папке — «Доступ»: сотруднику или отделу — просмотр, редактирование или управление (управление — ещё настройка доступа этой
  папки; его можно выдать и не администратору). Отдел получает доступ для всех своих сотрудников и для подключения Windows этого отдела.
  Изменения действуют сразу — права читаются из базы при каждом запросе, и на сайте, и с диска Windows.
- **Как с отделами.** Версии, корзина, восстановление, поиск, предпросмотр и журнал — те же (`DepartmentFilesService`, `FileAccessRules`).
  Файл можно перенести из отдела в общую папку и обратно (нужна запись в обоих местах); папки переносятся только внутри своего пространства.
- **Удаление.** Только пустой общей папки (без файлов и папок, в том числе в корзине) — данные так не теряются.

## Word, Excel и блокировки

Проверено на Windows 11 с Office 2021 (16.0.14332) по диску без пароля. Word и Excel работают с файлом через свой WebDAV: `LOCK` (владелец —
имя пользователя Windows, `Timeout: Second-600`), `GET`, продление `LOCK` с токеном в `If`, при сохранении `PUT` с тем же токеном,
при закрытии `UNLOCK`. Каждое сохранение — новая версия файла.

- **Блокировка настоящая** (`FileLocks`). Пока она действует, файл меняет только тот, кто предъявил её токен (`If`). Второй редактор
  (другой компьютер) получает на `LOCK` 423 — Word открывает файл только для чтения; `PUT`, `DELETE`, `MOVE`, `PROPPATCH` без
  токена — 423. Сайт тоже не перезапишет открытый файл (новая версия, переименование, перенос, удаление — 423 с текстом «… открыт для
  редактирования (кем) …»), папку с открытым файлом нельзя переименовать, перенести или удалить.
- **Кем открыт** — в списке файлов на сайте (замок и имя) и в `PROPFIND` (`lockdiscovery` без чужого токена).
- **Срок.** Не больше часа (`DepartmentFilesService.MaxLockSeconds`); Office продлевает свою блокировку, пока документ открыт, упавший Word
  держит файл не дольше её срока. Зависшую блокировку снимает администратор или сотрудник с управлением: меню файла → «Снять блокировку».
- **Проводник** блокирует файл, когда копирует его на диск (`LOCK` → `PUT` с токеном → `UNLOCK`), а дописывает в него без блокировки —
  поэтому без токена запись запрещена, только пока файл открыт у другого.
- **Служебные запросы Office.** Word 2021 и новее спрашивает у сервера «сведения о совместном доступе» (`POST /_api/web/GetFileByUrl(…)/
  ListItemAllFields/GetSharingInformation`, SharePoint). Раньше этот адрес отвечал 401 с запросом пароля Basic — Microsoft 365 считает это
  «небезопасным входом»; теперь 404, как и все адреса «/_…».
- Совместного редактирования одного документа в реальном времени (как в SharePoint/OneDrive) нет: в каждый момент файл правит один человек.

## Личная ссылка Windows

- «Файлы» → «Мой диск Windows» (или кнопка в общей папке): «Выпустить ссылку» → «Скопировать» у «Личный адрес» → «Подключить сетевой диск».
  Адрес — `https://files.1base.uz/k/{код}` (путь Windows `\\files.1base.uz@SSL\k\{код}`): на диске — папки отделов сотрудника и общие
  папки, выданные ему или его отделу. Можно подключить и одну общую папку: `…/k/{код}/Общие файлы`.
- Права — сотрудника, проверяются при каждом запросе: отключили пользователя, сменили роль или забрали доступ — диск сразу видит меньше или
  не открывается. В журнале действия — от имени сотрудника с источником `windows-personal`.
- Код хранится как у ссылки отдела (хэш для входа, шифр для «Показать»), показывается только самому сотруднику, факт показа — в журнал.
  «Новая ссылка» отменяет прежнюю сразу, «Отключить» — совсем. Срок — `Files:LinkLifetimeDays` (по умолчанию 365 дней).

## Срок действия ссылок

У ссылки отдела и личной ссылки есть срок (`Files:LinkLifetimeDays`, по умолчанию 365 дней от выпуска; «Новая ссылка» выпускает новую со
своим сроком). Истёкшая, отозванная и неверная ссылка — 404, без запроса пароля. Срок виден в окне «Подключить к Windows» и «Мой диск Windows».

## Операции и версии

Загрузка (несколько файлов, перетаскивание), создание папок, скачивание, просмотр, переименование, перенос, удаление в корзину, восстановление,
перезапись. Загрузка файла с тем же именем — новая версия того же файла; все версии можно скачать. Пустая заготовка, которую Проводник создаёт
перед записью (PUT 0 байт, затем содержимое), отдельной версией не остаётся. Перенос (MOVE) поверх существующего файла — так сохраняют
«через временный файл» (`~WRD0001.tmp` → `отчёт.docx`) — делает содержимое новой версией того же документа: у него остаются история и
прежнее содержимое, временный файл уходит в корзину. Запись с `If-Match` на устаревшую версию и `If-None-Match: *` поверх существующего
файла — 412. Служебные файлы Windows и Office (`~$…`, `desktop.ini`,
`Thumbs.db`) хранятся для Проводника, но на сайте не показываются.

Поиск — по имени, расширению, папке, отделу и автору в доступных отделах (содержимое документов не индексируется).
Предпросмотр: картинки и PDF — в браузере; CSV и XLSX — таблица (первые 200 строк, 40 столбцов, до 10 листов); DOCX и TXT — текст.

## Журнал

`AuditLogs`, действия `files.*`: `files.uploaded`, `files.updated` (новая версия), `files.downloaded`, `files.renamed`, `files.moved`,
`files.copied`, `files.deleted`, `files.restored`, `files.folder.created|renamed|moved|deleted|restored`, `files.access.changed`,
`files.connection.created|regenerated|revoked|revealed|tested`, `files.locked`, `files.unlocked`, `files.unlocked.forced`, `files.replaced`,
`files.shared.created|renamed|deleted|access.changed`, `files.personal_link.created|regenerated|revealed|revoked`. Через подключение —
`ActorType = Connection`. В данных записи — источник (`source`: `web`, `windows-link` — ссылка отдела, `windows-login` — логин отдела,
`windows-personal` — личная ссылка) и IP клиента (за Cloudflare — из `CF-Connecting-IP`). Скачивание через Проводник
пишется раз в 10 минут на файл и версию (Проводник читает файлы и для эскизов). Паролей в журнале нет.

## Безопасность

- Пароль подключения: хэш PBKDF2-SHA256 (100 000 итераций, соль) для входа и копия, зашифрованная ASP.NET Data Protection (ключи в БД), для
  «Показать». Открытого пароля в базе нет; он не попадает в адрес, логи, журнал и аналитику — сайт запрашивает его отдельным POST по нажатию.
- Подбор пароля: после 10 неверных входов с одного адреса на один логин — пауза 5 минут (429). Неверные коды ссылок: после 30 с одного
  адреса за 5 минут — тоже 429 (подобрать 160-битный код и так нельзя; это защита от компьютера со старой ссылкой и сканеров).
- Служебные адреса Office, SharePoint и FrontPage (`/_api/…`, `/_vti_bin/…`, `/_layouts/…`) — всегда 404 без запроса пароля, даже с
  заголовком `Authorization`: ответ 401 с Basic Microsoft 365 считает «небезопасным входом» и блокирует файл. Коды отделов и имена общих
  папок с «_» не начинаются.
- Секретная ссылка — не единственная защита. Риск: у кого ссылка, тот пишет в папку до её отзыва. Что его ограничивает: код 160 бит
  (подобрать нельзя), в базе только хэш и шифр, в журналах nginx код замаскирован, срок действия (`Files:LinkLifetimeDays`, по умолчанию
  365 дней), «Новая ссылка» и отзыв действуют сразу, ссылка отдела открывает только свой отдел и выданные ему общие папки, личная — только
  права сотрудника на момент запроса (отключили пользователя — диск не открывается), каждое действие в журнале с IP. Утекла ссылка отдела —
  «Новая ссылка»; нужен доступ одному человеку — личная ссылка вместо ссылки отдела.
- Обход каталогов: сегменты `.` и `..` в пути и в `Destination` отклоняются (в том числе закодированные `%2E%2E`); путь ищется по именам в
  базе, а не в файловой системе. Недопустимые для Windows имена (`/ \ : * ? " < > |`, `CON`, `COM1` …) не сохраняются.
- Скачивание идёт через API с проверкой прав, ответ `no-store`; прямых ссылок на MinIO нет. В браузере открываются только картинки и PDF,
  остальное — вложением (HTML или SVG из файла не выполнится на сайте). XML запросов WebDAV читается без DTD (XXE).
- Сайт и `/api` через домен файлов не открываются: nginx :82 ведёт только в WebDAV.

## Развёртывание

1. `cd ~/onebase && bash deploy/update.sh` — новая сборка; миграция `DepartmentFiles` применится при старте API.
2. В `.env` на сервере: `FILE_STORAGE_DOMAIN=files.1base.uz` (перезапуск: `docker compose up -d api`).
3. Cloudflare Zero Trust → Tunnels → Public Hostname: `files.1base.uz` → `http://nginx:82` (как `sales.1base.uz` → `http://nginx:81`).
4. Cloudflare → Caching → Cache Rules: для `files.1base.uz` — «Bypass cache» (API и так отдаёт `no-store`).
5. В OneBase администратор: «Файлы» → отдел → «Подключить к Windows» → «Создать подключение» → «Проверить подключение» (все шаги ✓).
6. На компьютере с Windows: «Подключить сетевой диск» по инструкции из окна.

## Переменные окружения

| Переменная | Настройка API | По умолчанию | Назначение |
|---|---|---|---|
| `FILE_STORAGE_DOMAIN` | `Files:PublicDomain` | пусто | Домен подключения к Windows; пусто — подключение не настроено (сайт с файлами работает) |
| — | `Files:PublicScheme` | `https` | Схема адреса (Windows отправляет пароль только по https) |
| — | `Files:MaxUploadBytes` | 200 МБ | Предел файла через сайт (как `client_max_body_size` nginx :80) |
| — | `Files:MaxDavFileBytes` | 4 ГБ | Предел файла через WebDAV (на деле ограничивают Windows и Cloudflare) |

## Если не работает

| Признак | Что проверить |
|---|---|
| «Проверить подключение»: адрес не настроен | `FILE_STORAGE_DOMAIN` в `.env`, перезапуск `api` |
| WebDAV ответил 404/502 вместо 207 | маршрут Cloudflare `files.1base.uz → http://nginx:82`, nginx перезапущен с новой конфигурацией |
| Windows: «Указанное имя папки недействительно» | служба «Веб-клиент», адрес с `https://`, домен открывается в браузере |
| Windows снова и снова спрашивает пароль | пароль сменили или подключение отозвано — новый пароль в окне «Подключить к Windows» |
| Word/Excel: «заблокировал доступ… метод входа, который может быть небезопасным» | диск подключён по логину и паролю — отключить его и подключить по «Адрес без пароля» из окна «Подключить к Windows» |
| Диск по ссылке перестал открываться | администратор выпустил новую ссылку или отозвал подключение — подключить диск по новому адресу |
| Файл больше 50 МБ не копируется | предел Windows `FileSizeLimitInBytes` (команда выше); больше 100 МБ — только через сайт |
| 429 при входе | 10 неверных паролей подряд — подождать 5 минут |

`backend/tests/OneBase.AI.Tests/FileSharingTests.cs` — на PostgreSQL: служебные запросы Office (`/_api`, FrontPage) — 404 без пароля;
два редактора (чужой LOCK, PUT, DELETE, MOVE — 423; сайт тоже не перезапишет; продление, запись со своим токеном, UNLOCK, истёкшая и снятая
администратором блокировка); сохранение через временный файл, `If-Match`, корзина и восстановление; общие папки (имена, видимость без
выдачи, просмотр/редактирование/управление, доступ отдела через его подключение Windows, поиск, перенос из отдела, забранный доступ, запрет
удалить непустую); личная ссылка (ровно права сотрудника, источник и IP в журнале, отключённый сотрудник, новая ссылка, отзыв, истёкшие
ссылки); лимит неверных ссылок, `..`, MKCOL с телом, запись в несуществующую папку и в корень, LOCK без токена, файл больше предела (413).

Ручная проверка на Windows 11 с Office 2021 (16.0.14332): локальный API за прокси с той же схемой адресов, что nginx :82 (`/k/{код}/…`,
`X-Dav-Root: /`), диск по ссылке без пароля. Word и Excel открывают файл с диска на запись, сохраняют (LOCK → PUT с токеном → UNLOCK),
повторное открытие показывает правки, каждая сохранённая правка — новая версия; Проводник копирует, дописывает, переименовывает и удаляет;
Word в общей папке по личной ссылке создаёт и правит документ. Файл, который держит другой компьютер, Word на запись не открывает (его LOCK
получает 423).
