# Файлы отделов (Department Files)

У каждого отдела OneBase своё файловое пространство. С ним работают двумя способами — и это **одно хранилище**:

- на сайте: раздел «Файлы» (`/base`, адрес `/files` ведёт туда же);
- в Windows: папка отдела подключается сетевым диском по WebDAV через HTTPS (`https://files.1base.uz/production`).

Файл, положенный через Проводник, сразу есть в базе и на сайте; загруженный на сайте — сразу в той же папке Windows. Второй копии нет.

## Архитектура

```
Проводник Windows ──HTTPS/WebDAV──► Cloudflare Tunnel ──► nginx :82 ──► API (WebDavHandler)  ─┐
Браузер ──HTTPS──► Cloudflare ──► nginx :80 ──► Next.js /bff ──► API (FilesController)       ─┤
                                                                                             ▼
                                                              DepartmentFilesService (права, версии, корзина, журнал)
                                                                 │                          │
                                                          PostgreSQL (метаданные)      MinIO (содержимое версий)
```

- **API** — один и тот же сервис `DepartmentFilesService` для сайта и для WebDAV: права (`FileAccessRules`), версии, корзина и журнал одинаковые.
- **WebDAV** — `OneBase.Api/Files/WebDavHandler.cs` (RFC 4918, классы 1 и 2): OPTIONS, PROPFIND, PROPPATCH, GET, HEAD, PUT, DELETE, MKCOL, MOVE, COPY, LOCK, UNLOCK.
  Снаружи весь домен файлов — WebDAV: nginx :82 передаёт адрес без изменений и ставит `X-Dav-Root: /`; nginx :80 и :81 этот заголовок
  стирают. На самом сервере тот же WebDAV доступен по `http://api:8080/dav/…`.
- **Сайт** — `FilesController` (`/api/files/…`), страницы `frontend/src/app/(app)/base`, компоненты `frontend/src/components/files`.

## Хранилище

- **MinIO** — тот же, что у всего OneBase (`Minio:*`, бакет `MINIO_BUCKET`). Ключ объекта — `files/{id файла}/{id версии}`: имя файла в ключ не
  входит, поэтому имя не может увести за пределы отдела. Каждая версия — свой объект.
- **PostgreSQL** — метаданные:
  - `Folders` — дерево папок отдела (`DepartmentId`, `ParentId`, `CreatedById`, `DeletedAt`). Корневая папка отдела создаётся при первом
    открытии вместе с «Документы», «Отчёты», «Архив»; она одна на отдел (`IX_Folders_DepartmentRoot`).
  - `Files` — файл (`DepartmentId`, `FolderId`, `SizeBytes`, `CurrentVersion`, кто изменил — сотрудник или подключение, `DeletedAt`).
  - `FileVersions` — версии (номер, ключ MinIO, размер, SHA-256, кто загрузил — `UploadedById` или `UploadedByConnectionId`).
  - `ResourcePermissions` — выдачи доступа к папке отдела другим отделам (субъект `Department`).
  - `FileConnections` — подключения к Windows (миграция `DepartmentFiles`).
- Миграция `DepartmentFiles` только добавляет колонки, таблицу и индексы; `FileVersions.UploadedById` становится необязательным. Данные не удаляются.

## Права

Одно правило для сайта и WebDAV (`FileAccessRules`), данные — из БД на момент запроса (роль, сменённая после входа, действует сразу):

| Кто | Свой отдел | Чужой отдел |
|---|---|---|
| Сотрудник с `files.read` | чтение | только если отделу выдан доступ (чтение или запись) |
| Сотрудник с `files.write` | чтение и запись | выданный уровень |
| Администратор (`files.manage`) | всё | всё, управление подключениями и доступом |
| Директор (`files.read.all`) | по своим ролям | **просмотр всех отделов** (только чтение, без логинов подключений) |
| Подключение Windows отдела | уровень подключения (запись) | ничего |

`files.read.all` по умолчанию только у ролей «Администратор» и «Директор» (у существующей роли директора право добавляется при запуске,
`SystemRoles.Upgrades`). На странице «Файлы» отделы показаны папками верхнего уровня: «Файлы» → «Производство» → «Отчёты».
«Свой отдел» — отдел сотрудника и отделы его ролей. Доступ другого отдела к папке задаёт администратор в окне «Подключить к Windows» →
«Доступ других отделов к папке» (нет / только чтение / чтение и запись). Чужие папки и файлы отвечают 404, как несуществующие — по
перебору id ничего не узнать. Запись в отдел только на чтение — 403.

## Подключение к Windows

- **Способ — WebDAV по HTTPS.** Путь вида `\\files.1base.uz\production` — это SMB (порт 445): через Cloudflare Tunnel он не проходит
  (только с клиентом Cloudflare WARP на каждом компьютере), а открывать SMB в интернет небезопасно. Windows подключает WebDAV штатно:
  «Подключить сетевой диск» → адрес `https://files.1base.uz/production` (или путь `\\files.1base.uz@SSL\production`).
- **Один логин на отдел** (решение заказчика): `production_8f3a1`, пароль — 20 случайных символов. Логин и пароль видят сотрудники с правом
  записи в отделе и администраторы (подключение даёт запись — читателю его не показывают). Действия через подключение пишутся в журнал от имени
  подключения («Windows · production_8f3a1»), а не конкретного сотрудника.
- **Создать / сменить пароль / отозвать** — администратор. Смена пароля и отзыв действуют сразу (кэш проверенных входов сбрасывается).
- **Проверить подключение** — настоящая проверка: адрес настроен, подключение действует, MinIO пишет и читает проверочный объект, папка отдела
  есть в базе, публичный адрес отвечает на PROPFIND с логином и паролем отдела (через Cloudflare и nginx, как Windows).
- **Инструкция** строится на сервере из настоящих адреса и логина; её можно скопировать и скачать (без пароля).

### Ограничения Windows и Cloudflare

- Windows по умолчанию открывает через WebDAV файлы до 50 МБ. Поднять предел (PowerShell от имени администратора):
  `reg add HKLM\SYSTEM\CurrentControlSet\Services\WebClient\Parameters /v FileSizeLimitInBytes /t REG_DWORD /d 4294967295 /f; Restart-Service WebClient`.
- Cloudflare на бесплатном тарифе пропускает до 100 МБ на запрос — большие файлы загружайте на сайте (до 200 МБ).
- Служба «Веб-клиент» (WebClient) должна работать: в Windows 10/11 она есть и запускается по требованию; если Windows пишет «Указанное имя папки
  недействительно» — `services.msc` → «Веб-клиент» → «Запустить», тип запуска «Автоматически».
- Пароль по Basic Windows отправляет только по HTTPS (настройка `BasicAuthLevel=1` по умолчанию) — поэтому адрес только https.
- Новые файлы с сайта Проводник показывает при следующем открытии папки или по F5. Сайт перечитывает папку раз в 15 секунд — файлы из Windows
  появляются без «Обновить».
- Блокировки (LOCK) выдаются для Office и Проводника, но запись ими не ограничивается: если двое правят один файл, сохранится последний
  (предыдущее содержимое остаётся версией).

## Операции и версии

Загрузка (несколько файлов, перетаскивание), создание папок, скачивание, просмотр, переименование, перенос, удаление в корзину, восстановление,
перезапись. Загрузка файла с тем же именем — новая версия того же файла; все версии можно скачать. Пустая заготовка, которую Проводник создаёт
перед записью (PUT 0 байт, затем содержимое), отдельной версией не остаётся. Служебные файлы Windows и Office (`~$…`, `desktop.ini`,
`Thumbs.db`) хранятся для Проводника, но на сайте не показываются.

Поиск — по имени, расширению, папке, отделу и автору в доступных отделах (содержимое документов не индексируется).
Предпросмотр: картинки и PDF — в браузере; CSV и XLSX — таблица (первые 200 строк, 40 столбцов, до 10 листов); DOCX и TXT — текст.

## Журнал

`AuditLogs`, действия `files.*`: `files.uploaded`, `files.updated` (новая версия), `files.downloaded`, `files.renamed`, `files.moved`,
`files.copied`, `files.deleted`, `files.restored`, `files.folder.created|renamed|moved|deleted|restored`, `files.access.changed`,
`files.connection.created|regenerated|revoked|revealed|tested`. Через подключение — `ActorType = Connection`. Скачивание через Проводник
пишется раз в 10 минут на файл и версию (Проводник читает файлы и для эскизов). Паролей в журнале нет.

## Безопасность

- Пароль подключения: хэш PBKDF2-SHA256 (100 000 итераций, соль) для входа и копия, зашифрованная ASP.NET Data Protection (ключи в БД), для
  «Показать». Открытого пароля в базе нет; он не попадает в адрес, логи, журнал и аналитику — сайт запрашивает его отдельным POST по нажатию.
- Подбор пароля: после 10 неверных входов с одного адреса на один логин — пауза 5 минут (429).
- Обход каталогов: сегменты `.` и `..` в пути и в `Destination` отклоняются (в том числе закодированные `%2E%2E`); путь ищется по именам в
  базе, а не в файловой системе. Недопустимые для Windows имена (`/ \ : * ? " < > |`, `CON`, `COM1` …) не сохраняются.
- Скачивание идёт через API с проверкой прав, ответ `no-store`; прямых ссылок на MinIO нет. В браузере открываются только картинки и PDF,
  остальное — вложением (HTML или SVG из файла не выполнится на сайте). XML запросов WebDAV читается без DTD (XXE).
- Сайт и `/api` через домен файлов не открываются: nginx :82 ведёт только в WebDAV.

## Развёртывание

1. `cd ~/onebase && bash deploy/update.sh` — новая сборка; миграция `DepartmentFiles` применится при старте API.
2. В `.env` на сервере: `FILE_STORAGE_DOMAIN=files.1base.uz` (перезапуск: `docker compose up -d api`).
3. Cloudflare Zero Trust → Tunnels → Public Hostname: `files.1base.uz` → `http://nginx:82` (как `sales.1base.uz` → `http://nginx:81`).
4. Cloudflare → Caching → Cache Rules: для `files.1base.uz` — «Bypass cache» (API и так отдаёт `no-store`).
5. В OneBase администратор: «Файлы» → отдел → «Подключить к Windows» → «Создать подключение» → «Проверить подключение» (все шаги ✓).
6. На компьютере с Windows: «Подключить сетевой диск» по инструкции из окна.

## Переменные окружения

| Переменная | Настройка API | По умолчанию | Назначение |
|---|---|---|---|
| `FILE_STORAGE_DOMAIN` | `Files:PublicDomain` | пусто | Домен подключения к Windows; пусто — подключение не настроено (сайт с файлами работает) |
| — | `Files:PublicScheme` | `https` | Схема адреса (Windows отправляет пароль только по https) |
| — | `Files:MaxUploadBytes` | 200 МБ | Предел файла через сайт (как `client_max_body_size` nginx :80) |
| — | `Files:MaxDavFileBytes` | 4 ГБ | Предел файла через WebDAV (на деле ограничивают Windows и Cloudflare) |

## Если не работает

| Признак | Что проверить |
|---|---|
| «Проверить подключение»: адрес не настроен | `FILE_STORAGE_DOMAIN` в `.env`, перезапуск `api` |
| WebDAV ответил 404/502 вместо 207 | маршрут Cloudflare `files.1base.uz → http://nginx:82`, nginx перезапущен с новой конфигурацией |
| Windows: «Указанное имя папки недействительно» | служба «Веб-клиент», адрес с `https://`, домен открывается в браузере |
| Windows снова и снова спрашивает пароль | пароль сменили или подключение отозвано — новый пароль в окне «Подключить к Windows» |
| Файл больше 50 МБ не копируется | предел Windows `FileSizeLimitInBytes` (команда выше); больше 100 МБ — только через сайт |
| 429 при входе | 10 неверных паролей подряд — подождать 5 минут |
