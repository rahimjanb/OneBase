# Снабжение, этап 1: основа модуля и заявки — отчёт

Дата: 01.11.2026. Основа — аудит [ONEBASE_PROCUREMENT_AUDIT.md](ONEBASE_PROCUREMENT_AUDIT.md) и решения по нему.

## Решения, принятые перед этапом
- **Меню:** отдельный пункт «Заявки» рядом с «Задачами» (выбор пользователя). Задачи снабжения остаются в «Задачах» (отдел «Снабжение»). Склад, поставщики, заказы и оплаты появятся на этапах 2–4.
- **Права заявок** — роль, а не раздел пользователя: ручной выбор разделов в карточке пользователя их не снимает.
- **Роль «Кладовщик»** перенесена на этап 2, вместе со складом: на этапе 1 у неё не было бы ни одного своего действия.
- **Утверждение и отклонение директором** — этап 2 по ТЗ. Статусы уже есть, но на этапе 1 к ним не перейти.

## Что сделано

### Сущности (схема `procurement`, миграция `Procurement1_Requests`)
Миграция только создаёт таблицы. Существующие данные не меняются.

| Сущность | Таблица | Что хранит |
|---|---|---|
| `ProcurementRequest` | Requests | Номер `PR-2026-00001`, название, отдел, инициатор, приоритет, статус, желаемая дата, причина, комментарий, сумма, ключ повтора формы, `xmin` |
| `ProcurementRequestItem` | RequestItems | Позиция: наименование, категория, единица, количество, цена за единицу, комментарий, свой статус |
| `ProcurementCategory` | Categories | 15 категорий из ТЗ (засеваются по коду), настраиваются |
| `ProcurementUnit` | Units | Единицы: шт, кг, г, т, л, м, м², м³, упак, пачка, коробка, рулон, компл, услуга |
| `ProcurementCounter` | Counters | Номера без повторов: одна команда PostgreSQL `INSERT … ON CONFLICT … RETURNING` |
| `ProcurementAuditLog` | AuditLog | История: кто, когда, действие, статус до и после, комментарий, «было/стало» (jsonb). Пишется в той же записи, что и изменение |
| `ProcurementDocument` | Documents | Вложения: MinIO, ключ `procurement/requests/{заявка}/{файл}` |

Похожих сущностей в проекте нет:
- общий `AuditLog` сохраняет запись отдельно от изменения и не хранит статусы и комментарии;
- `ApprovalRequest` служит только для AI;
- товары Linko — готовая продукция и только для чтения.

### Статусы
- Объявлены все 9 статусов из ТЗ.
- Переходы этапа 1:

| Переход | Кто |
|---|---|
| Черновик или «Требуется доработка» → «Отправлена» | инициатор |
| «Отправлена» → «Ожидает директора» | снабжение |
| «Отправлена» → «Требуется доработка» (комментарий обязателен) | снабжение |
| Отмена до утверждения | инициатор |

- Править заявку можно только в черновике и на доработке.
- При отмене заявки отменяются и её позиции.

### Доступ (проверяется на сервере, контекст строится из токена и базы)
| Кто | Что видит и может |
|---|---|
| Сотрудник | Свои заявки. Подаёт за свой отдел |
| Руководитель отдела (руководитель в «Задачах») | Отправленные заявки своего отдела. Подаёт за свой отдел |
| Снабжение (`procurement.read` + `procurement.manage`) | Все отправленные заявки. Передаёт директору, возвращает на доработку |
| Директор (`procurement.read` + `procurement.settings`) | Все отправленные заявки, категории. Не обрабатывает заявки за снабжение |

- Черновик видит только инициатор.
- На чужую заявку сервер отвечает 403. Прямой вызов «передать директору» без права снабжения тоже получает 403.

### Права и роли
Права — `procurement.request`, `procurement.read`, `procurement.manage`, `procurement.settings`.

| Право | Кому |
|---|---|
| `procurement.request` | все роли отделов и «Сотрудник» |
| `procurement.read`, `procurement.manage` | «Снабжение» |
| `procurement.read`, `procurement.settings` | «Директор» |
| все | администратор (по правилу OneBase) |

Существующие роли получают права при запуске через `SystemRoles.Upgrades`.

### Защита от повторов и конкурентности
- **Двойное нажатие «Создать»:** ключ формы, уникальный индекс, при повторе возвращается та же заявка.
- **Двойная отправка:** второй запрос ничего не меняет.
- **Правка из двух вкладок:** версия `xmin`, ответ 409.
- **Номера при одновременном создании:** без повторов.

### Уведомления (колокольчик и push)
- **Отправлена:** руководителю отдела и снабжению.
- **Передана директору:** пользователям с ролью «Директор», инициатору — статус.
- **Возвращена на доработку:** инициатору, с комментарием.
- **Отменена после отправки:** снабжению.
- Администратор как техническая роль уведомления снабжения не получает.

### API `/api/procurement`
| Метод и путь | Что делает |
|---|---|
| `GET nav` | кнопки раздела и счётчик «ждут действия» |
| `GET overview` | главная раздела |
| `GET form` | отделы, категории, единицы для формы |
| `GET requests` | поиск, фильтры (статус, приоритет, категория, отдел, даты), сортировка, страницы |
| `GET requests/{id}` | карточка заявки |
| `POST requests` | создать |
| `PUT requests/{id}` | изменить |
| `POST requests/{id}/submit`, `forward`, `return`, `cancel` | смена статуса |
| `POST requests/{id}/attachments` | загрузить вложение |
| `GET`, `DELETE attachments/{id}` | скачать, удалить вложение |
| `GET`, `POST`, `PUT categories` | категории |

- Ошибки возвращаются как `{ error }` с кодами 400, 403, 404, 409.
- Вложения: PDF, Office, картинки, текст, ZIP, до 20 МБ, до 20 файлов. Тип определяется по расширению. Если описание вложения не сохранилось, файл удаляется из хранилища.

### Интерфейс (раздел «Заявки», `/requests`)
**Меню:**
- Пункт «Заявки» в «Рабочем пространстве».
- На телефоне — последним пунктом веера; нижний бар не изменился.
- Кнопки в шапке: Обзор (со счётчиком «ждут действия»), Все заявки (снабжению и директору), Мои заявки, Заявки отдела (руководителям), Категории (директору и администратору).

**Страницы:**
- **Обзор:** заявки по статусам, «ждут вашего действия», этот месяц (число и сумма, категории), последние заявки. Без заявок — пустое состояние с кнопкой.
- **Списки:** поиск по номеру, названию, товару и инициатору; фильтры; сортировка по клику на колонку; на телефоне — карточки.
- **Новая заявка и правка:**
  - позиции строками, сумма считается сразу;
  - новая строка берёт категорию предыдущей;
  - у первой позиции категория не выбрана заранее, чтобы её не пропустили;
  - кнопки «Сохранить черновик» и «Отправить», вложения.
- **Карточка:** полоса этапов, позиции со статусами, причина, вложения, сведения, история с комментариями. Кнопки — только разрешённые пользователю.

**Общее:** мгновенный макет при переходе (`RouteSkeleton`), RU и UZ, токены темы OneBase.

## Ограничения этапа 1
- Нет утверждения и отклонения директором, проверки склада, резерва, каталога товаров и роли «Кладовщик» — это этап 2.
- Позиция — своё наименование. Привязка к каталогу появится вместе со складом.
- Суммы только в UZS, без НДС (НДС — у предложений и заказов, этап 3).
