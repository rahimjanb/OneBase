# OneBase — «Производство → Технолог»: этап 3 (смены и оператор) — отчёт

Дата: 08.11.2026. [Аудит](ONEBASE_TECHNOLOGIST_AUDIT.md) · [Этап 1](ONEBASE_TECHNOLOGIST_STAGE1_REPORT.md) · [Этап 2](ONEBASE_TECHNOLOGIST_STAGE2_REPORT.md).

## Что сделано

- **Сменный отчёт `SHF-`** (`production.Shifts` и строки):
  - шапка — задание (версия рецептуры — из задания), дата, номер смены, линия, оператор, начальник смены;
  - итог смены — годный выход, упаковано упаковок, коробок;
  - фактические замесы — масса каждого;
  - по этапам:
    - отметка «этап заполнен»;
    - выпечка до и после — выход, потеря и отклонение считаются сразу; вне допуска нужна причина;
    - влажность;
    - «из переработки, кг» — брак, возвращённый в производство;
  - брак продукта по видам этапа — кг, «разрешён / направлен на переработку / запрещён»;
  - материалы этапа — брак (этикетки, плёнка) и взвешенный расход, в единице склада.
- **Статусы:** ввод → закрыта → утверждена; отменена; корректировка утверждённой смены — копия с причиной, которая после утверждения
  заменяет смену (исходная — «заменена»). Утверждённая не правится.
- **Права:**
  - новое право «Производство: ввод смены» и роль «Оператор производства» (создаётся при запуске): ввод, закрытие, отмена своей смены;
  - рецептуры, нормы и задания оператор не меняет;
  - утверждает мастер (задания на выпуск) или начальник производства — не тот, кто закрыл;
  - вернуть на ввод — с причиной;
  - всё проверяется на сервере.
- **Закрытие — только полная смена:**
  - годный выход внесён;
  - замесы внесены (если есть замес);
  - все этапы отмечены;
  - выпечка до и после внесена, отклонение объяснено;
  - упаковки внесены (если есть упаковка);
  - у корректировки — причина;
  - **переработка:** вернуть больше, чем направлено на переработку по заданию, нельзя — один и тот же брак дважды не используют.
- **Расчёт по результатам смены** — механизм этапа 1: фактические замесы, брак по этапам (кг → по массе потока), упаковки, брак
  материалов, переработка. Нет отметки этапа — расчёт неполный.
- **Экран оператора** (`/production/shifts/{id}`, удобен на планшете — крупные поля):
  - автосохранение через секунду после правки, с проверкой версии;
  - копия в браузере — обновление страницы или обрыв связи ввод не теряют, при открытии он восстанавливается;
  - «Сохранено 12:03» / «Нет связи»;
  - справа — чего не хватает для закрытия;
  - ниже — расчёт по результатам смены.
- **Журнал смен** (`/production/shifts`, вкладка «Смены»): фильтры («Открытые», «Ввод», «Ждут утверждения», «Утверждённые»), «Новая
  смена» по выпущенному заданию.
- **Узбекский** — строки смен и тексты сервера.

## Проверка

- **Сервер:** тесты производства 22/22. Новый `ProductionShiftDbTests` проходит сценарий:
  - смена по невыпущенному заданию не открывается, кладовщику открыть нельзя;
  - автосохранение со старой версией → 409;
  - выпечка 1 120 → 900 кг (80,4 %) без причины не закрывается;
  - расчёт смены: фактические замесы 4 × 280 → мука 600, брак выпечки 20 кг, этикетки 4 000 + 40 брака;
  - закрыл оператор — оператор не утверждает, мастер без причины не возвращает, мастер утверждает; утверждённую не сохранить;
  - переработка: направлено 20 кг — вернуть 30 нельзя, 15 можно;
  - корректировка: вторая открытая — нельзя; без причины не закрыть; после утверждения исходная — «заменена».
- **Интерфейс:** тесты 114/114 (новый — выпечка как на сервере), типы без ошибок.
- **Экраны на стенде:** смена с выходом вне допуска на компьютере; на планшете на узбекском.
