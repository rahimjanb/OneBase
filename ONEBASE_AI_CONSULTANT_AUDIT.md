# Аудит AI-консультанта OneBase: почему он отвечает «данных нет», когда данные есть

Дата: 30.10.2026. Ветка: `main` (`682a692`).

## Как проводилось исследование

- Код консультанта прочитан целиком по пути вопроса: от `POST /api/ai/chat` до сохранения ответа. Охвачены маршрутизатор, оркестратор, AI-сотрудники, инструменты, проверка чисел, память, база знаний, шлюз моделей и права доступа.
- Локальная база смотрелась только на чтение (`default_transaction_read_only=on`). Смотрели AI-сотрудников, выдачу инструментов, источники, базу знаний и настройки моделей.
- Платные запросы к Claude и OpenAI не выполнялись.
- Детерминированная часть маршрутизации (страховка по ключевым словам) прогнана на 28 сценариях временным тестом. Тест вызывает модель-независимые функции, после прогона он удалён.
- Лимиты сервисов проверены обычными GET-запросами к локальному API.
- Production, промпты, модели, настройки AI Gateway, `.env`, схема БД и данные не менялись.

> **Ограничение.** В локальной базе нет ни одного чата консультанта: `ai.Messages` пуст. Поэтому частоту каждой причины на проде здесь посчитать нельзя. Для этого есть готовые SQL-запросы только на чтение (раздел 10.3) и существующая платная оценка маршрутизации (раздел 10.2).

## 1. Текущая архитектура

```

  └─ POST /bff/api/ai/chat → Next route bff/[...path] → nginx (read timeout 300 с) → API
       └─ ConsultantController.Chat (SSE, «пульс», общий таймаут 6 мин)
            └─ ConsultantChatService.RunAsync (история 12 сообщений, кэш ответов)

                      ├─ права пользователя → доступные AI-сотрудники

                      ├─ CorrectionGuard / ReportIntent (намерение по регулярным выражениям)
```

## 3. Найденные проблемы

### 3.1 Маршрутизация

1. **Пустой выбор маршрутизатора превращается в отказ.**
   - Маршрутизатор-LLM может законно вернуть `agents: []`: так ему велит правило «общий вопрос о методике» (`AiRouter.cs:208`).
   - Тогда `Enforce` (`OrchestratedConsultantEngine.cs:151-176`) подключает сотрудников, только если одновременно:
     - вопрос совпал с `AsksForData()` (`:215`). Это «?» или одно из слов «сколько, какой, где, кто, покажи…». Слов «что», «как», «есть ли», «хватит ли», «найди», «проанализируй», «расскажи» в нём нет;
     - в тексте есть **русское** ключевое слово отдела.
   - Иначе итоговый ответ строится с инструкцией «данных OneBase в этом ответе нет… скажи, что нужно уточнить вопрос, и не называй цифр» (`:291-295`).
   - По прогону страховка спасает только **9 из 28** сценариев (раздел 6).
2. **Описания сотрудников, которые видит маршрутизатор, покрывают не все данные.**
   - В `Description` (`AgentDefaults.cs`, поле `Description`; в БД то же) нет задач и проектов отделов, Telegram-автоотчётов, находок AI, базы знаний (регламентов, документов), визитов и маршрутов, заказов, остатков и дозагрузки, долгов дилеров и прайсов.
   - Инструменты для всего этого есть (`get_department_tasks`, `get_work_projects`, `get_telegram`, `get_ai_alerts`, `search_knowledge`, `get_visits`, `get_orders`, `get_stock_reload`, `get_dso`, `get_prices`).
   - Маршрутизатору не к кому отнести такой вопрос, и он склонен вернуть `[]`.
3. **Страховка не знает словарь компании.**
   - `ByKeywords` использует словарь продаж: категории, товары, регионы.
   - `Enforce` вызывает `AiRouter.KeywordAgents(turn.Question, available)` без него (`OrchestratedConsultantEngine.cs:170`).
   - Поэтому «Помадка Самарканд октябрь» и «А по Самарканду?» страховкой не спасаются.
4. **Ключевые слова только русские** (`AiRouter.cs:23-37`). На узбекском («savdo», «reja», «xodim», «ombor») ни один отдел не находится, хотя интерфейс двуязычный.
5. **Ложное намерение «отчёт».** `ReportIntent` (`Reports/ReportIntent.cs:14`) реагирует на любое «отчёт»: «какие автоотчёты ушли в Telegram» включает режим Excel. Сотрудникам выдаётся `create_report`, ответ не кэшируется.

### 3.2 Выполнение инструментов

6. **Одно исключение инструмента роняет сотрудника целиком.**
   - `DataTool.ExecuteAsync` ловит только `ToolArgumentException` (`Tools/Data/DataTool.cs:44-51`).
   - Ни `ToolExecutor.ExecuteAsync`, ни цикл `AgentRunner.RunAsync` (`Agents/AgentRunner.cs:181`) остальные исключения не ловят: таймаут БД, `KeyNotFoundException`, `InvalidOperationException`, ошибку сети.
   - Исключение долетает до `AgentOrchestrator` (`:68-73`), и тот возвращает `failed` «Внутренняя ошибка OneBase» с **пустыми** фактами (`:80-81`).
   - Все данные, уже полученные сотрудником, теряются. Итоговый ответ говорит «данных нет / ошибка». Аккуратно ошибки оборачивают только HR-инструменты (`HrTools.cs:153-162`).
7. **Обрезка больших результатов.**
   - Ответ инструмента длиннее 40 000 символов режется посередине JSON (`AgentRunner.cs:46, 212-214`).
   - Строки после отреза модель не видит: «такого ТП / товара нет».
   - Часть списков ограничена топ-N (`Take(args.Cap(10|12|25|30|40|80))`), и не все отдают общее число строк.
8. **Гранулярность периода.**
   - Инструменты продаж работают по месяцу (`year` + `month`).
   - Отрезок дней в `get_visits` и `get_sales_days` — «в пределах одного месяца» (`RouteTools.cs:100, 170`).
   - HR — не больше 62 дней (`HrTools.cs:25, 107-108`, `HrService.MaxPeriodDays`); проверено: `/api/hr/timesheet` за 3 месяца → 400 «Период — не больше 62 дней».
   - «За последние две недели» через границу месяца, «за квартал» по HR, АКБ за несколько месяцев: несколько вызовов, расход шагов, частичный ответ или «недостаточно данных».
9. **Лимит 8 шагов** (`AgentRunner.cs:43`) включает одну правку по `EvidenceCheck`. На последнем шаге инструменты запрещены, поэтому сравнение 3–6 месяцев по регионам и ТП часто заканчивается `partial`.

### 3.3 Промпты (ничего не менялось — только диагностика)

10. **Категоричные «данных нет» в промптах отделов** (`AgentDefaults.cs`):
    - маркетинг: «Данных о кампаниях… нет — прямо скажи об этом» (`:85`);
    - производство: «Данных о выпуске… нет — прямо скажи» (`:110`);
    - финансы: «Бюджетов… нет» (`:65`);
    - снабжение: «Заказов поставщикам, закупочных цен… нет» (`:120`);
    - HR: «ФОТ, зарплат… нет» (`:102`);
    - продажи: «Воронки сделок… нет» (`:77`).

    Если такие данные загрузят документом в базу знаний или появятся в Google Sheets, сотрудник откажет, **не вызвав** `search_knowledge`.
11. **Две «шаблонные» отказные фразы** и общий запрет на детализацию:
    - «Если данных нет, прямо скажи: «В OneBase нет достаточных данных…»» (`Consultant/ConsultantPrompts.cs:45`);
    - «Нет данных — «В доступных данных OneBase не найдено подтверждение…»» (`:29`);
    - «не больше трёх попыток на показатель» (`:19`).

    Положительное: `AgentRunner.SystemPrompt` (`:253-258`) прямо требует спускаться к детализации до ответа «нет данных». Но правило в `QualityRules` идёт ниже и формулирует отказ проще.
12. **Сотрудник без инструментов** получает «Инструментов с данными OneBase у тебя сейчас нет — значит, данных для ответа нет» (`AgentRunner.cs:247-248`). Это ответ «нет данных» там, где правильно «нет доступа» (3.6).
13. **Главный консультант** «опирается только на результаты AI-сотрудников и историю чата» (`AgentDefaults.cs:52`). Сам он инструментов не вызывает, хотя ему открыт источник `knowledge.documents`.
14. **Уточнение неоднозначного вопроса** есть только для «нескольких товаров, точек, людей» (`ConsultantPrompts.cs`). Для вопроса без периода или отдела при пустом маршруте инструкция сразу «уточните, не называйте цифр», без попытки по умолчанию: текущий месяц, вся компания.

### 3.4 Документы, Google Sheets, RAG

15. **Поиск по документам:**
    - отключается совсем, если пользователю не доступен ни один документ (`AgentRunner.cs:73-78`);
    - PDF, `.doc`, `.xls` не читаются (`Infrastructure/Knowledge/DocumentTextExtractor.cs:33-34`), сканы — тем более;
    - Excel превращается в текст «заголовок: значение», до 20 000 строк на лист (`:15`). Итог по такому файлу RAG не посчитает: в ответ попадают 6 фрагментов по 1 200 символов;
    - полнотекстовый поиск только с конфигурацией `russian` (`KnowledgeFullTextSearch.cs:21, 34, 41`): узбекский текст и латиница ищутся плохо;
    - без модели эмбеддингов векторного поиска нет (локально так и есть);
    - документ отдела виден только своему отделу (`KnowledgeService.cs:196`).
16. **Документы из раздела «Файлы»** (MinIO, WebDAV) и файлы AI Data Manager (`ai.DataFiles`) **в базу знаний не попадают.** «Загруженный документ» для пользователя и для консультанта — разные вещи.
17. **Google Sheets** доступны AI только через заранее привязанные поля: планы, дилеры, P&L, сальдо и т. п. (`Application/DataSources/DataSourceModels.cs:30-71`). Любая другая таблица (план производства, бюджет маркетинга, свой KPI) консультанту не видна, и это корректно даёт «данных нет».

### 3.5 Память, кэш, таймауты

18. **Память чата сохраняет и итоги `no_data`** (`Memory/AiMemoryStore.cs:35`). Дальше этот вывод уходит:
    - маршрутизатору («Уже проанализировано»);
    - сотруднику («Ты уже анализировал… Вывод: данных нет»);
    - итоговому ответу.

    Один неудачный ответ подталкивает к повтору отказа в том же чате.
19. **Таймауты:**
    - общий таймаут 6 мин (`ConsultantController.cs:26`);
    - вызов модели до 180 с (`Providers/HttpAiProvider.cs:12`);
    - до 8 шагов на сотрудника;
    - при нескольких пользователях сотрудники ждут слот (`MaxConcurrentCalls = 8`, `AiSettings.cs:90`).

    Таймаут теряет весь ответ: частичные итоги не сохраняются.
20. **Кэш ответов** `no_data` не хранит (`ConsultantAnswerCache.Cacheable`). Но если сотрудник поставил `completed` с текстом «данных нет», такой ответ повторится 30 минут, пока не обновятся данные. Риск низкий.

### 3.6 Права (RBAC)

21. **У marketing, production и supply нет обязательного права** (`AgentDefaults.cs:89, 113, 122`). Они запускаются для любого пользователя, хотя почти все их инструменты требуют `sales.read`: это право по умолчанию у `DataTool` (`DataTool.cs:32`).
    - Пользователь без `sales.read` спрашивает про остатки.
    - Маршрутизатор отдаёт вопрос supply, у которого нет инструментов.
    - Ответ — «данных нет» вместо «нет доступа к данным продаж».
22. **P&L дилеров** требует и `finance.read`, и `sales.read` (`SalesExtraTools.cs:617-634`). Финансист без права «Продажи» получит «данных нет».

## 5. Причины преждевременного ответа «данных нет» (по силе влияния)

1. **Пустой выбор маршрутизатора + узкая страховка → ответ без данных.** Чаще всего: вопросы без «?», начинающиеся с «что/как», на узбекском, уточнения в диалоге, вопросы о документах, задачах, проектах, Telegram и находках AI.
2. **Непойманное исключение в инструменте** обнуляет весь результат сотрудника.
3. **Категоричные «данных нет» в промптах отделов** — отказ без вызова `search_knowledge` и без проверки других источников.
4. **Маршрутизатор не знает о части данных.** Описания сотрудников не упоминают задачи, проекты, Telegram, находки AI, документы, визиты, заказы, остатки, долги, прайсы.
5. **Документы недоступны:**
   - PDF и «Файлы» не индексируются;
   - Excel через RAG не считается;
   - нет эмбеддингов;
   - поиск выключен при нуле документов;
   - полнотекстовый поиск только по-русски.
6. **Сотрудник без инструментов из-за прав** отвечает «данных нет» вместо «нет доступа».
7. **Память чата повторяет прошлый `no_data`.**
8. **Обрезка 40 000 символов и топ-N без общего числа** — «не найдено» для строк за пределом.
9. **Гранулярность периодов** (месяц, ≤ 62 дня по HR, отрезок внутри месяца) плюс лимит 8 шагов — частичные ответы по сравнениям и кварталам.
10. **Таймаут 6 минут и очередь вызовов модели** теряют всё собранное. Ложное «отчёт» удлиняет путь.

## 8. Предлагаемая архитектура улучшения (внутри существующей)

Новой параллельной системы не нужно. Достаточно укрепить существующие звенья:

1. **Маршрутизация:** `AiRouter` + `Enforce`.
   - Пустой маршрут — только для явного разговора: список шаблонов в коде, по-русски и по-узбекски.
   - Во всех остальных случаях — `ByKeywords` со словарём продаж и расширенными словами.
   - Если не нашлось ничего — один сотрудник «по умолчанию» по правам пользователя. Сейчас это все доступные сотрудники, что дорого.
   - В подсказку маршрутизатору (`AiRouter.Prompt`) добавить перечень областей данных из реестра инструментов: `ITool.Title` и `Source`, а не только `Description` отделов. Описания останутся настройкой администратора.
2. **Изоляция ошибок:** `AgentRunner`.
   - `try/catch` вокруг вызова инструмента: ошибка уходит модели как `ОШИБКА: …` и пишется в журнал.
   - Модель пробует другой инструмент или честно называет сбой источника.
   - При исключении всего сотрудника `AgentOrchestrator` отдаёт `partial` с уже собранными источниками и доказательствами, а не пустой `failed`.
3. **Права:** `OrchestratedConsultantEngine`. Доступным считается сотрудник, у которого для пользователя есть хотя бы один инструмент данных. Иначе он в `forbidden`, и итоговый ответ честно говорит «нет доступа».
4. **Доказательная цепочка «данных нет».** У сотрудника — поле `no_data_reason`: `source_not_loaded`, `no_access`, `not_found`, `out_of_range`, `tool_error`, `not_in_onebase`. Оно сохраняется в подробностях и журнале. Итоговый ответ формулирует отказ по причине.
5. **Документы:** `KnowledgeService`.
   - PDF через извлечение текста.
   - Раздел «Файлы» — индексация по выбору отдела.
   - Включённые эмбеддинги.
   - Двухконфигурационный полнотекстовый поиск (`russian` + `simple`).
   - Excel из базы знаний — отдельным инструментом табличного расчёта, а не фрагментами.
6. **Google Sheets:** новые поля `DataSourceCatalog` (план производства, бюджет маркетинга) — по мере появления таблиц. Через существующие привязки, со своим инструментом чтения и владельцем в `SourceOfTruth`.

## 10. Тесты для проверки исправлений

### 10.1 Детерминированные (без вызова модели, в `backend/tests/OneBase.AI.Tests`)

1. **Страховка маршрута.** Все вопросы S01–S28, кроме разговорных, при ответе маршрутизатора `[]` получают хотя бы одного сотрудника. «Привет», «Спасибо», «Что ты умеешь?» остаются `[]`. Основа — временный прогон из этого аудита (`Enforce`, `KeywordAgents`, `ByKeywords`).
2. **Изоляция ошибки инструмента.** `AgentRunner` со сценарной моделью (как `ScriptedGateway` в `RouterTests.cs`). Первый инструмент бросает `InvalidOperationException`, второй отдаёт данные. Итог `completed/partial` с данными второго, ошибка в журнале.
3. **Сотрудник без инструментов.** Пользователь без `sales.read` и вопрос supply: сотрудник в `forbidden`, итог говорит «нет доступа».
4. **`ReportIntent`.** «Какие автоотчёты ушли в Telegram» → `false`; «Сделай отчёт по продажам в Excel» → `true`; «hisobot tayyorla» → `true`.
5. **Память.** Итог `no_data` не попадает в подсказку как вывод.
6. **Обрезка.** Результат длиннее лимита остаётся валидным JSON с `total` и `truncated: true`.
7. **Периоды.** HR-инструмент для AI принимает 92 дня; `get_sales_days` с 25.09 по 05.10 возвращает сумму двух месяцев.
8. **Кэш.** Ответ `completed` с «данных нет» в тексте не кэшируется.

### 10.2 Оценка маршрутизации (платно, только с подтверждением)

### 10.3 Замер на проде (только чтение)

Запросы проверены на локальной базе. Выполнять с `PGOPTIONS='-c default_transaction_read_only=on'`.

```sql
-- 1. Доля ответов без AI-сотрудников (маршрутизатор вернул [] — ответ без данных)
select count(*) filter (where jsonb_array_length("Details"->'agents') = 0) as no_agents, count(*) as total
from ai."Messages" where "Role" = 'Assistant' and "Status" = 'Completed' and "Details" is not null and "CreatedAt" > now() - interval '30 days';

-- 2. Итоги AI-сотрудников по статусам
select a->>'agent' as agent, a->>'status' as status, count(*)
from ai."Messages" m, jsonb_array_elements(m."Details"->'agents') a
where m."Role" = 'Assistant' and m."CreatedAt" > now() - interval '30 days'
group by 1, 2 order by 1, 3 desc;

-- 3. Тексты ошибок сотрудников
select a->>'agent' as agent, a->>'error' as error, count(*)
from ai."Messages" m, jsonb_array_elements(m."Details"->'agents') a
where m."Role" = 'Assistant' and a->>'status' = 'failed' and m."CreatedAt" > now() - interval '30 days'
group by 1, 2 order by 3 desc limit 30;

-- 4. Ответы «данных нет» с вопросом, причиной маршрута и статусами сотрудников
select m."CreatedAt", left(u."Content", 140) as question, jsonb_array_length(m."Details"->'agents') as agents,
       m."Details"->>'routingReason' as routing,
       (select string_agg((a->>'agent') || ':' || (a->>'status') || ':' || coalesce(jsonb_array_length(a->'toolsUsed'), 0), ', ')
          from jsonb_array_elements(m."Details"->'agents') a) as statuses
from ai."Messages" m
join lateral (select "Content" from ai."Messages" q where q."ConversationId" = m."ConversationId" and q."Role" = 'User' and q."CreatedAt" <= m."CreatedAt"
              order by q."CreatedAt" desc limit 1) u on true
where m."Role" = 'Assistant' and m."CreatedAt" > now() - interval '30 days'
  and (m."Content" ilike '%не найдено подтверждение%' or m."Content" ilike '%нет достаточных данных%' or m."Content" ilike '%данных нет%'
       or m."Content" ilike '%нет данных%' or m."Content" ilike '%нужно уточнить%' or m."Content" ilike '%не удалось подтвердить%')
order by m."CreatedAt" desc limit 100;

-- 5. Ответы с пометкой «Не подтверждено данными OneBase»
select count(*) filter (where m."Details"->'grounding'->>'warned' = 'true') as warned, count(*) as total
from ai."Messages" m where m."Role" = 'Assistant' and m."CreatedAt" > now() - interval '30 days';

-- 6. Сбои ответа целиком (таймаут, модель, внутренняя ошибка)
select "Error", count(*) from ai."Messages" where "Role" = 'Assistant' and "Status" = 'Failed' and "CreatedAt" > now() - interval '30 days'
group by 1 order by 2 desc;

-- 7. Сотрудник ответил no_data, не вызвав ни одного инструмента
select a->>'agent' as agent, count(*)
from ai."Messages" m, jsonb_array_elements(m."Details"->'agents') a
where a->>'status' = 'no_data' and coalesce(jsonb_array_length(a->'toolsUsed'), 0) = 0 and m."CreatedAt" > now() - interval '30 days'
group by 1 order by 2 desc;

-- 8. База знаний: документы и эмбеддинги
select "Status", count(*), sum("Chunks") as chunks, string_agg(distinct coalesce("EmbeddingModel", '—'), ', ') as embedding
from ai."KnowledgeDocuments" where "ArchivedAt" is null group by 1;
```
