## 2. Что исправлено

### Задача 1. Маршрутизация

- **Пустой маршрут — только для разговора.** Это приветствие, благодарность, прощание, вопрос о возможностях консультанта (`RouteIntent.IsSmallTalk`).
  - Включая «Спасибо, план понятен» и «Rahmat, tushunarli».
  - «Привет, какие продажи сегодня?» — уже вопрос о данных.
- **Любой другой вопрос получает сотрудника.** Порядок выбора (`OrchestratedConsultantEngine.Enforce` → `RouteIntent.Resolve`):
  1. ключевые слова отделов: русские и узбекские основы, латиница и кириллица;
  2. словарь продаж: категории, товары, регионы;
  3. области данных по источникам инструментов: задачи и проекты, визиты, заказы и цены, остатки, долги, P&L, первичка и экспорт, Telegram, находки AI, документы;
  4. если область не определилась — **один** сотрудник с наибольшим доступом к данным; для вопроса о компании в целом — все.

  Область добавляет сотрудника, только если её не покрывает уже выбранный, так что лишние сотрудники не назначаются.
- **`AsksForData`** (`RouteIntent.AsksForData`): «?» не нужен.
  - Русский: «что», «как», «почему», «найди», «проанализируй», «расскажи», «сравни», «хватит ли», «выполнение плана».
  - Узбекский, латиница и кириллица: «qancha», «qaysi», «tahlil», «bajarilishi», «қанча», «қайси», «таҳлил» и т. д.
- **Уточнения наследуют прошлый вопрос.**
  - Распознаются «А по Самарканду?», «А за прошлый месяц?», «Сравни с предыдущим», «А кто хуже всех?», «Samarqand-chi?».
  - Задача сотруднику: «{прошлый вопрос}\nУточнение: {вопрос}».
  - Запасной выбор маршрутизатора `ByKeywords` тоже читает историю.
- **Страховка использует словарь продаж**: раньше `Enforce` его не получал.
- **Попутная находка:** «опаздывал» (через «а») не совпадало с основой «опозд». Добавлена основа «опаздыв».

### Задача 2. Изоляция ошибок инструментов

- **Сбой инструмента не роняет сотрудника.** Исключение инструмента внутри `ToolExecutor.ExecuteAsync` не выходит наружу.
  - Модель получает `ОШИБКА: {"error":{"tool","kind","message","next"}}` и может попробовать другой инструмент.
- **Без служебных подробностей.** Текст доменных исключений OneBase показывается («Период — не больше 62 дней», «Регион не найден»). Текст остальных исключений (база, сеть) заменяется общим.
  - Само исключение пишется в журнал сервера (`LogError`).
  - В аудит пишется `ai.tool.failed` с видом, типом исключения и безопасным текстом.
- **Сбой модели или службы после полученных данных** → итог `partial` (`AgentRunner.Salvage`). В нём:
  - выдержки результатов инструментов (до 3 000 символов каждая, до 12 000 всего);
  - источники;
  - сбои;
  - доказательства для проверки чисел.

  То же при исчерпании шагов.
- **Ни одного результата и сбой инструмента** → `failed` с причиной `tool_error` (`AgentRunner.Classify`), какой бы статус ни назвала модель. Ошибка больше не выдаётся за `no_data`.
- **Сбой без данных** по-прежнему `failed`, теперь с причиной `model_unavailable` или `internal_error`.

### Задача 3. Права

- **Доступен только сотрудник с инструментами.** Это сотрудник, у которого для пользователя есть хотя бы один инструмент данных (`ToolExecutor.DataSourcesAsync`: грант × открытый источник × право пользователя). Остальные не запускаются, модель для них не вызывается.
- **Четыре разных случая:**

  | Случай | Статус | Причина (`reason`) |
  |---|---|---|
  | Нет доступа | `forbidden` | `no_access` |
  | Источник не подключён (права есть, данных нет — например, ни одного документа) | `no_data` | `source_not_connected` |
  | Инструмент завершился ошибкой | `failed` | `tool_error` |
  | Данные действительно не найдены | `no_data` | `not_found` |

- **Вопрос о недоступной области** (отдел без прав, Telegram без права на рассылки) отдаётся итогу как «нет доступа», а не уходит другому отделу.
- **`AgentRunner`** без инструментов сразу возвращает `forbidden` (или «источник не подключён»), без вызова модели.
- **Права не расширяются**, RBAC и ограничения отделов не обходятся: используются те же проверки `ToolExecutor`.

### Задача 4. Память

- `no_data` больше не сохраняется ни в память чата, ни в память сотрудника. Следующий вопрос проверяет данные заново.
- Старые записи `no_data` пропускаются при чтении (`AiMemoryStore.ConversationAsync`). Маршрутизатор и сотрудники их не видят, из базы они не удаляются.
- Найденные данные (`completed`, `partial`) сохраняются как раньше.

### Задача 5. Намерение «отчёт»

Режим Excel включается, если есть:
- формат (Excel, xlsx);
- выгрузка или скачивание;
- слово «отчёт» с действием («сделай», «сформируй», «нужен», «hisobot tayyorla»);
- слово «отчёт» без вопроса («Отчёт по продажам за сентябрь», «Sentabr bo'yicha hisobot»).

Не включается на:
- автоотчёты («Какие автоотчёты ушли в Telegram?»);
- вопросы об отчётах («Какие отчёты отправлялись вчера?», «hisobot yuborildimi?»).

Все прежние примеры из `ReportTests` дают тот же результат.

### Задача 7. Совместимость

- **API и SSE не меняются.**
  - В `details.agents[]` появились необязательные поля `reason` и `toolErrors`.
  - Статус прогресса `Skipped` («нет доступа») фронт уже понимает.
  - Карточки `forbidden` фронт и раньше скрывал.
- **Платных вызовов меньше.** Сотрудники без инструментов и «нет доступа» больше не вызывают модель. Разговор при нечитаемом ответе маршрутизатора больше не запускает всех шестерых. Уточнение по истории идёт одному отделу.
- **Изменения поведения, о которых нужно знать:**
  - ответы с итогом «нет доступа» не кэшируются (`ConsultantAnswerCache.Cacheable` требует `completed` или `partial` у всех);
  - вопросу о данных без отдела теперь отвечает один сотрудник по умолчанию, а не «уточните вопрос».

## 6. Какие проблемы остались

1. **Итоговая формулировка не проверена на настоящей модели.**
   - Инструкция итогового ответа не менялась: «Если сотрудник вернул no_data или ошибку — прямо скажи, каких данных нет».
   - Теперь в данных есть `reason` и `toolErrors`, и модель видит разницу. Но фразу «данных нет» при `failed`/`tool_error` модель всё ещё может выбрать.
   - Проверить можно только платным прогоном.
2. **Распознавание области — по словам.** Новых формулировок может не хватить: вопрос уйдёт сотруднику по умолчанию (продажи), а не «нет данных». Список слов — в `AiRouter.Keywords` и `RouteIntent.Domains`.
3. **Сотрудник по умолчанию — продажи**, если права равные. Для HR-пользователя это HR (у него больше источников). Вопросы о людях по имени («Как дела у Алишера») идут к продажам.
4. **`HrTool.Guard` превращает `FieldForbiddenException`** в ошибку аргументов: для HR-инструментов «нет доступа» внутри инструмента видно как текст, без вида `forbidden`.
5. **Итог `partial` после сбоя** содержит выдержки JSON инструментов, а не выводы: выводы делает итоговый ответ.
6. **Не сделано из аудита (P1–P3):**
   - обрезка 40 000 символов и общее число строк;
   - периоды: HR ≤ 62 дней, отрезок только внутри месяца;
   - промпты отделов с категоричным «данных нет»;
   - описания сотрудников для маршрутизатора;
   - база знаний: PDF, раздел «Файлы», эмбеддинги, узбекский поиск;
   - потеря ответа по таймауту 6 минут;
   - причина отказа в `ai.AuditLogs`.
7. **Маршрутизатор-LLM по-прежнему может вернуть `[]`.** Теперь это ловит страховка, но частоту на проде покажут только SQL-запросы из аудита (раздел 10.3).

## 7. Что требует отдельного согласования

1. **Выкладка на production** и отправка изменений в git.
2. **Промпт итогового ответа и промпты отделов.** Различать в тексте «нет доступа», «источник не подключён», «сбой источника» и «не найдено». Отказ — только после `search_knowledge` и `get_source_of_truth`.
3. **Описания AI-сотрудников для маршрутизатора** (поле `Description` в настройках AI): перечислить все области данных.
4. **Платная оценка маршрутизации** («Настройки → AI → Маршрутизация») с новыми кейсами S05–S28 и узбекскими вопросами.
5. **Показ `reason` и `toolErrors` в интерфейсе** (карточка сотрудника под ответом) — правка фронтенда.
6. **Этапы P1–P3** аудита.
