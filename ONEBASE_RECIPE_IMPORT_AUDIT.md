# Импорт техкарт из «Tex karta.xlsx» — аудит и план

Источники: `docs/guide/supply-production.pdf` (разделы 19–25, 32), код модуля «Производство», `Tex karta.xlsx` (копия файла из «Загрузок»,
разбор без изменения файла). Локальная база — только чтение (каталог склада и Linko для оценки сопоставления).

## 1. Что есть в OneBase

| Что | Где | Состояние |
|---|---|---|
| Техкарта: код, версия, название, товар Linko, выход (количество и единица — «на какое количество заданы нормы»), номер карты, технолог, дата начала, замес (мин./макс., частичный), упаковка, позиция склада выхода (полуфабрикат) | `ProductionRecipe` (`production.Recipes`) | реализовано |
| Этапы (замес, выпечка, начинка, глазурь, добавки, охлаждение, упаковка, другое): выход и допуск, база брака, влажность, переработка | `ProductionRecipeStage` | реализовано |
| Компоненты: позиция склада, этап (у карты без этапов — пусто, нормы на выход), база нормы (выход, замес, штука, упаковка, коробка), единица строки, масса единицы, потери % | `ProductionRecipeLine`; норма `numeric(18,6)`, > 0; позиция — одна строка на этап (у карты без этапов — одна на карту) | реализовано |
| Виды брака продукта и материалов | `ProductionDefectType` | реализовано |
| Версии и утверждение: черновик → на утверждение → другой технолог или начальник производства (автор не утверждает) → действующая, прежняя — архив; утверждённая не правится, «Новая версия» — черновик-копия; одна неутверждённая версия на код | `ProductionRecipeService` (Create, Update, Submit, Approve, Return, NewVersion, Archive) | реализовано |
| Сравнение версий: карта, этапы, компоненты (норма с единицей и базой, потери), брак — добавлено, убрано, изменено | `ProductionRecipeDiff` | реализовано |
| Расчёт на выпуск, потребность, годный остаток | `ProductionCalc`, `RequirementAsync`, `ProductionStock` | реализовано |
| Задания (снимок версии и расчёта), выдача по партиям (FEFO), возврат, смены, закрытие со сверкой, оприходование выхода полуфабриката партией | `ProductionOrderService`, `ProductionShiftService` | реализовано |
| Каталог склада: артикул `Sku` (уникальный), название, единица, единицы закупки, включена ли | `procurement.Items` | реализовано |
| Товары Linko: `Code`, название | `linko.Products` | реализовано (синхронизация) |
| История действий по техкарте | `ProcurementAuditLog` (`DocType = recipe`) | реализовано |
| **Импорт техкарт из Excel** | — | **нет** (в документации — «Чего пока нет») |

Права: техкарты правит право «Производство: рецептуры» (`ctx.Recipes`), утверждает технолог или начальник производства. Импорт — то же право.

## 2. Что в Excel

16 листов: 11 видимых «norma …» с рецептурами и 5 скрытых без рецептур («Siryo/Gp sklad aktiv oy», «Prodaja aktiv oy» — выгрузки остатков и продаж; «proizvodstvo GP/XA» — одна строка заголовков).

Шаблон листа «norma …»:
- строка-заголовок: «№ | Артикул | Наименование сырья | Ед.изм. | Сум | Доллар | Курс | НАХР | Вес», правее — названия продуктов;
- над ней — артикулы продуктов;
- выше — итоги: «1 тонна учун кг» (сырья на 1 тонну), «Потери», «1 тонна учун нарх», «1 кг учун нарх»;
- **продукты — по столбцам, сырьё — по строкам**;
- **нормы — кг (или шт) на 1 тонну готового продукта** («1 тонна учун» — «на 1 тонну»).

Отличия листов:
- строки итогов на разных местах (потери — строка 2 или 3, на «pesochnoe» и «polufabrikati» без подписи);
- на «norma pechenye» продукт стоит левее «НАХР» (столбец H), «Вес» — в J;
- столбец «Итого» на «norma pesochnoe»;
- пустые строки далеко внизу («trubochka» до строки 6506, «Pomadki» — до 2938).

| Показатель | Значение |
|---|---|
| Продуктов (столбцов) | 319, с составом — 313, пустых — 6 (сумма 0, итог #DIV/0!) |
| Норм (положительных) | 6 246; знаков после запятой: 0–3, одна — 12 (`=1000*1000/999` на «norma pudra») |
| Нули | 648 — в состав не входят |
| Отрицательные | 94 — «Отход Кекс» (105-053) и «Отход этикетка ва пакет» (104-027): возвратные отходы, в техкарту не переносятся (норма > 0) |
| Число записано текстом | 6: «1 050,00», «1 050», «25,542», «0,15», «250», «0,86» — не исправляются, ручная проверка |
| Ошибки формул | #REF! (цены, «norma pechenye»), #DIV/0! (потери пустых продуктов и «pesochnoe», где «Вес» записан текстом — итог 0), #N/A, #VALUE! — в итоговых строках, не в нормах |
| Сумма компонентов «Вес» ≠ «1 тонна учун кг» | «pesochnoe» (итог 0 — ошибка формулы), «sechka», «pudra» (итог 0), «Pomadki» (несколько продуктов), «pridzel» (3), «pechenye» BF, «polufabrikati» AK, AN — предупреждение |
| Продукт без артикула | 2: «СВЕТОШ ОК 270 гр» (pechenye Q) и столбец «Итого» (pesochnoe AC — не продукт) |
| Один артикул — два столбца | 105-048 (pechenye H и BB), 105-012 (keks AD и polufabrikati J), 101-005 (polufabrikati AJ и pudra J), 105-100 (polufabrikati AK и trubochka J); 069 — у двух разных продуктов («ГЛАЗУР ВОДИЙ», «Vodiy Lazzati 25kg») |
| Компонент дважды в одной рецептуре | 1: polufabrikati AD, 101-123 «Сухое молоко» 52,52 + 52,52 |
| Компонент без единицы | 15 норм: 101-186 «Высоко олеиновое» (pridzel) |
| Полуфабрикаты | 30 артикулов — продукт одного листа и компонент другого (глазури, начинки, киём 105-…, «РОЛЛЕР 89» S-089, сахарная пудра 101-005, сечка 101-072/073); 430 использований |
| Максимум компонентов в рецептуре | 41 (в техкарте — до 100) |

Сопоставление с локальной базой (только для оценки):
- **сырьё:** артикулов — 499;
  - в каталоге — 421, у 339 из них название совпадает дословно; у остальных расходятся пробелы и «№ …» в названии;
  - единица совпадает у 420;
  - нет в каталоге — 78 (в т. ч. полуфабрикаты 105-…, S-089).
- **продукты:** точный код Linko — у 22. Ещё 196 — по номеру без буквенного префикса («K-304» → «304»); это только предложение, нужно подтверждение.

## 3. Решения

- **Без параллельной таблицы рецептур.** Черновики создаются существующими `CreateAsync` и `NewVersionAsync` + `UpdateAsync` — с их проверками,
  историей и утверждением.
- **Этапов в Excel нет** — карта без этапов (нормы на выход, как «прежняя рецептура» OneBase) с пометкой «Требуется распределение по этапам
  технологом». Этапы, выход, влажность, брак не придумываются.
- **База:** «1 тонна учун кг» → выход 1 000 кг. Нет такой строки — карта не создаётся, пока технолог не укажет базу.
- **Точность:** число — как его хранит Excel (кратчайшая запись double, до 15 значащих цифр), в `decimal`. Больше 6 знаков после запятой
  (столько хранит техкарта) — не округляется, ручная проверка.
- **Сопоставление:**
  1. точный артикул (`Sku`);
  2. подтверждённое сотрудником сопоставление — запоминается для следующих загрузок;
  3. иначе — «не сопоставлено».
  Похожие названия не объединяются. Позиции в каталоге не создаются сами — только кнопкой с подтверждением.
- **Единицы не меняются:** единица Excel = единица позиции или переводится (кг/г/т, единица закупки), иначе — ручная проверка.
- **Полуфабрикат:** продукт, который входит в другие рецептуры. Позиция выхода — позиция склада с тем же артикулом. В других картах он —
  обычная позиция склада, поэтому его сырьё дважды не списывается.
- **Повторная загрузка:** тот же файл (SHA-256) — та же загрузка, не новая. Рецептура опознаётся по «лист + артикул продукта», компонент —
  по артикулу и строке. Изменённый файл сравнивается с прошлым импортом и с действующей версией карты:
  - без изменений — «без изменений»;
  - изменения — «Новая версия» черновиком после подтверждения;
  - утверждённая карта не перезаписывается;
  - карта, уже распределённая по этапам, обновляется только технологом вручную.
- **Двойное нажатие и параллельная загрузка** — уникальный хеш файла, условный захват статуса при создании черновиков, уникальные
  индексы техкарт.

## 4. Этапы работы

1. **Чтение Excel и разбор рецептур.** Чтение xlsx без потери точности: формулы, кэш, ошибки. Разбор листов: заголовок, продукты,
   компоненты, база, итоги, проверки. Тесты на синтетических файлах.
2. **Загрузка, сопоставление, предпросмотр, создание черновиков.** Новые таблицы `production.RecipeImports`, `RecipeImportRecipes`,
   `RecipeImportLines`, `RecipeImportItemMaps` — только новые, существующие не меняются. API, права, история, повторная загрузка,
   идемпотентность. Тесты.
3. **Экран.** Кнопка в «Техкартах», загрузка, сводка и список рецептур со статусами, построчное сравнение «Excel → техкарта», ручное
   сопоставление, решения по ошибкам, подтверждение. Компьютер и телефон.
4. **Производственный цикл на импортированных картах** (тесты):
   - утверждение другим технологом;
   - задание и потребность, нехватка;
   - выдача партий (FEFO), смена, возврат, закрытие и сверка;
   - оприходование полуфабриката и выдача его в другую карту без двойного списания;
   - новая версия после изменения нормы.
5. **Прогон настоящего файла** на отдельной базе с копией каталога и Linko. Цифры для отчёта, проверка на экране, финальный отчёт.
