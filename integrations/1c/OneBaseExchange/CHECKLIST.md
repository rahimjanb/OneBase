# Приёмка расширения OneBaseExchange — чек-лист разработчика 1С

Расширение написано по спецификации без запуска на настоящей 1С, поэтому каждый пункт ниже проверяется **на копии рабочей
базы** до установки на рабочую. Установка и настройка — [README.md](README.md).

Обозначения в командах:

```bash
export ONEBASE_SECRET='…секрет…'
BASE=https://<сервер>/<публикация>/hs/onebase/v1
C="curl -sS --cacert onec.crt -u OneBase_ReadOnly -H X-OneBase-Secret:$ONEBASE_SECRET"
ORG=<uuid организации из /organizations>
```

curl спросит пароль `OneBase_ReadOnly` при каждом вызове; для серии запросов удобнее файл `~/.netrc` с правами 600 и ключ
`--netrc-file` вместо `-u`. Для разбора JSON удобен `jq` (`… | jq '.page'`). В Windows — `curl.exe` и `jq.exe`.

## 1. Установка

- [ ] Платформа 8.3.10 или новее, версия записана: ______. Конфигурация и релиз (из `/metadata` → `configuration`): ______.
- [ ] Расширение `OneBaseExchange`, префикс `OneBase_`, назначение «Дополнение»; «Активно», «Безопасный режим», «Защита от
      опасных действий» — включены.
- [ ] Общие модули `OneBase_Settings`, `OneBase_Json`, `OneBase_Metadata`, `OneBase_Export`: «Сервер» — да; «Глобальный»,
      «Клиент», «Внешнее соединение», «Вызов сервера», **«Привилегированный»** — нет.
- [ ] HTTP-сервис `OneBase_API`, корневой URL `onebase`, шаблон `Все` = `/*`, метод `Получить` = `GET`, обработчик `ВсеПолучить`.
- [ ] Роль `OneBase_ЧтениеHTTP` без прав на данные (только «Использование» HTTP-сервиса, если такое право есть).
- [ ] Синтаксический контроль всех пяти модулей и «Проверка конфигурации» расширения — без ошибок.
- [ ] `OneBase_Settings.ХешСекретаSHA256()` — 64 hex-символа; хеш посчитан `printf %s "$SECRET" | shasum -a 256` (без перевода строки).
- [ ] Пользователь `OneBase_ReadOnly`: только чтение + `OneBase_ЧтениеHTTP`, без интерактивного входа и без прав записи.

## 2. Безопасность и доступ

- [ ] Без заголовка секрета: `curl … -u OneBase_ReadOnly "$BASE/ping"` → `401`, JSON `error.code = "unauthorized"`.
- [ ] Неверный секрет → `401`; в ответе нет ни секрета, ни хеша.
- [ ] Без логина/пароля → `401` от веб-сервера 1С.
- [ ] Пользователь без роли `OneBase_ЧтениеHTTP` → `403 forbidden`.
- [ ] Пользователь с правами записи (например, администратор) → `403 forbidden` «есть права на изменение данных».
- [ ] `$C "$BASE/ping"` → `200`, `"userWriteAccess": false`, `"readOnly": true`, `"changeTracking": "versions"`,
      `"capabilities": ["versions","ids"]`.
- [ ] HTTP (порт 80) не отвечает; TLS 1.1 не принимается: `curl --tlsv1.1 --tls-max 1.1 …` — ошибка; TLS 1.2 — работает.
- [ ] Сертификат содержит адрес, по которому обращается OneBase:
      `openssl s_client -connect <сервер>:443 </dev/null 2>/dev/null | openssl x509 -noout -ext subjectAltName`.
- [ ] С адреса, отличного от 192.168.9.168 (и не с самого сервера), соединение не устанавливается.
- [ ] Публикация не отдаёт веб-клиент и OData: `https://<сервер>/<публикация>/` и `…/odata/standard.odata` — не открываются.

## 3. Сопоставление с конфигурацией

`$C "$BASE/metadata?section=mapping" | jq '.mapping'`

- [ ] `warnings` пуст или каждое предупреждение понятно и принято.
- [ ] `accountingRegister`: найден нужный регистр, `correspondence = true`, верные `chartOfAccounts`, `maxSubconto`; измерения
      `organization`, `currency`, `department` и ресурсы `amount`, `currencyAmount`, `quantity` — те, что есть в конфигурации.
- [ ] `accountingCurrency.found = true`, `code = "UZS"`.
- [ ] `exchangeRates`: регистр, валюта, курс, кратность найдены; `otherDimensions` пуст (иначе — см. README).
- [ ] `catalogs.*.fields` и `references.*.fields`: каждый `null` объяснён (реквизита в конфигурации нет) или исправлен в настройках.
- [ ] `documentTypes`: у каждого нужного типа найден документ; `notFound` — лишние кандидаты; поля шапки
      (`organizationId`, `counterpartyId`, `amount`, `currency`…) и колонки строк найдены там, где они есть в документе.
- [ ] `otherDocuments` просмотрен: всё, что должно иметь свой тип, перенесено в `ТипыДокументов()`; то, что нельзя
      передавать даже без субконто сотрудников (например, начисление зарплаты), — в `ИсключенныеДокументы()`.
- [ ] `personalSubcontoTypes` совпадает с видами субконто сотрудников/физлиц в конфигурации
      (`$C "$BASE/metadata?object=ПланВидовХарактеристик.<виды субконто>"` и список видов в плане счетов).
- [ ] `infobaseId`: в `ИдентификаторИнформационнойБазы()` вписан постоянный UUID — **разный** у копии и у рабочей базы.

## 4. Методы

Для каждого списка: `page.hasMore`/`nextCursor` работают, поля по спецификации, пустые ссылки — `null` или нет поля.

- [ ] **Листание без потерь и повторов** (на большом справочнике, например контрагентах, с `limit=100`): обойти все страницы
      по `nextCursor`; число элементов = `totals.count` первой страницы; повторов `id` нет
      (`jq -r '.items[].id' стр*.json | sort | uniq -d` — пусто).
- [ ] `/organizations` — число = число организаций в базе; `inn`, `accountingCurrency`.
- [ ] `/accounts` — коды и наименования как в плане счетов; `type` (active/passive/active_passive), `offBalance`, `currency`,
      `quantity`, `subconto[].type` и `turnoverOnly` — как в карточке счёта.
- [ ] `/counterparties` — `inn`, `kind`, `legalForm`, `isGroup`, `parentId`, `bankAccounts` (номер, МФО, банк, валюта); `pinfl`
      отсутствует (пока не согласовано).
- [ ] `/contracts` — `counterpartyId`, `organizationId`, `kind`, `currency`, `paymentTermDays` (если есть в конфигурации).
- [ ] `/currencies` — `code` = буквенный код (`UZS`, `USD`), `numericCode` = цифровой (`860`, `840`). Если наоборот — поменяйте
      кандидаты `code`/`numericCode` в `СправочникиМетодов()`.
- [ ] `/exchange-rates?from=2026-10-01&to=2026-10-31` — совпадает с регистром курсов за месяц (число строк = `totals.count`),
      `rate`, `multiplier`; `&currency=USD` отбирает одну валюту.
- [ ] `/warehouses`, `/departments`, `/items` (`kind`, `unit`, `vatRate`, `ikpu`), `/references?kind=…` — по каждому виду.
- [ ] `/directories` — у всех нужных справочников `available = true` и `count` совпадает с базой.
- [ ] `/documents?organizationId=$ORG&from=…&to=…&type=<тип>` — по каждому типу: `number`, `date`, `posted`, `amount`
      (= сумма документа в форме), `vatAmount`, `currency`, `amountAccounting` (в UZS — = `amount`; у валютного — реквизит
      суммы в валюте учёта или `amount × rate.value / max(1, rate.multiplier)`, 2 знака, середина — к чётной копейке), `rate`
      (у валютных), `lines` (= табличная часть: номенклатура, количество, цена, сумма, НДС, счёт учёта).
- [ ] `/documents?…&withEntries=true` — `entries` документа = «Результат проведения» (Дт/Кт, суммы, субконто); у
      непроведённого — `[]`.
- [ ] `/documents?ids=<3 uuid>` — ровно эти документы; UUID удалённого на копии документа — отсутствует в ответе.
- [ ] `/entries?organizationId=$ORG&from=…&to=…` — один элемент = все проводки одного документа; номера строк набора без
      пропусков; набор никогда не разрезан между страницами (проверить на документе с тысячами проводок, например закрытие
      месяца); отменить проведение документа на копии → он приходит с `entries: []`.
- [ ] Субконто сотрудников/физлиц в проводках по зарплате: `{"index":…, "type":"…", "hidden": true}` без `id`, `code`, `name`
      (проводки не сворачиваются — их ключ регистратор + номер строки).
- [ ] `/balances?organizationId=$ORG&period=2026-10&subconto=false` и `&subconto=true` — см. раздел 7.
- [ ] `/versions?entityType=document&organizationId=$ORG&from=…&to=…` — `id`, `version`, `deletionMark`, `posted`, `date`, `type`;
      число = числу документов `/documents` за тот же отбор.
- [ ] На копии изменить документ → его `version` в `/versions` поменялась; удалить документ → его нет ни в `/versions`, ни в
      `/documents?ids=`.
- [ ] `/versions?entityType=counterparty` (и organization, account, currency, contract, warehouse, department, item,
      `reference&kind=…`) — без ошибок.
- [ ] Псевдонимы: `/health` = `/ping`, `/products` = `/items`, `/sales`, `/purchases`, `/warehouse`, `/finance`, `/production`
      отдают только свои типы; `/accounting` = `/entries`; `/turnovers` = `/balances`.
- [ ] `/changes` → `404 not_found` с подсказкой про `/versions`.
- [ ] Ошибки параметров → `400 invalid_parameter` с `field`: `from=2026-13-01`, `limit=0`, `limit=abc`, `ids` из 101 UUID,
      `ids=abc`, `cursor=abc`, `modifiedSince=…`, `type=unknown`, `/sales?type=purchase`, `/balances` без `period`,
      `/versions?entityType=document` без `organizationId`.
- [ ] `limit=5000` → страница из 1000 строк, `page.limit = 1000`.

## 5. Только чтение

- [ ] Поиск операций записи по исходникам ничего не находит (команда — README, раздел «Гарантии только чтения»).
- [ ] Расширение содержит только 1 HTTP-сервис, 4 общих модуля и 1 роль; заимствованных объектов нет.
- [ ] Полная загрузка OneBase за несколько месяцев на копии. После неё **журнал регистрации** с отбором «Пользователь =
      OneBase_ReadOnly» не содержит событий «Данные. Добавление», «Данные. Изменение», «Данные. Удаление», «Данные. Проведение»,
      «Данные. Отмена проведения». Допустимы: «Сеанс. Начало/Завершение», «Доступ…», «OneBase.Ошибка».
- [ ] `/versions?entityType=counterparty` (и документы месяца) до и после полной загрузки совпадают (`diff` пуст), если на
      копии в это время никто ничего не менял.
- [ ] В консоли кластера сеансы `OneBase_ReadOnly` (приложение — HTTP-сервис) завершаются и не держат блокировок.

## 6. Производительность (на копии рабочего объёма)

Время запроса: `$C -o /dev/null -w "%{http_code} %{time_total}\n" "<адрес>"`.

- [ ] Самый «тяжёлый» месяц, `limit=500`: каждая страница `/entries`, `/documents`, `/balances?subconto=true` — меньше 60 с
      (лимит OneBase); первая страница с `includeTotals=true` — тоже.
- [ ] `/versions?entityType=document` за месяц, `limit=1000` — несколько секунд.
- [ ] Два запроса одновременно (OneBase делает не больше 2) не мешают работе пользователей 1С.
- [ ] Если медленно: уменьшить размер страницы в OneBase, `ПроводокНаСтраницеМаксимум()`; записать, какой метод и период медленный.

## 7. Сверка с оборотно-сальдовой ведомостью

Отчёт «Оборотно-сальдовая ведомость» за тот же месяц и организацию:

- [ ] `/balances?…&subconto=false&includeTotals=true`: по каждому счёту `opening`, `turnover`, `closing` (`debit`/`credit`)
      совпадают с ОСВ; `totals.amount` = «Итого» оборотов по дебету ОСВ.
- [ ] Валютные счета: строки по валютам, `currencyDebit`/`currencyCredit` = ОСВ с показателем «Валютная сумма».
- [ ] `&subconto=true` по счёту расчётов с покупателями (например 4010): строки по контрагентам/договорам = «ОСВ по счёту»
      с разворотом по субконто; обороты Дт и Кт всех строк в сумме = оборотам строки счёта из `subconto=false`
      (остатки по субконто — развёрнутые, у активно-пассивного счёта их сумма не равна свёрнутому остатку счёта).
- [ ] **Счета с субконто сотрудников/физлиц** (расчёты по оплате труда, подотчёт и т.п.), `&subconto=true`:
      - строк по людям нет: на каждое сочетание организации, валюты и остальных субконто — одна строка, персональное
        субконто в ней — `{"index":…, "type":"…", "hidden": true}` без `id`, `code`, `name`;
      - нет двух строк с одинаковыми `account` + `currency` + `subconto` (`jq` по всем страницам — повторов ключа нет);
      - суммы свёрнутой строки совпадают с итогом «ОСВ по счёту» с разворотом по работникам: начальный и конечный остаток
        Дт и Кт — суммы дебетовых и кредитовых остатков людей по отдельности (не взаимозачтённые), обороты Дт и Кт — суммы
        оборотов;
      - `totals.count` с `includeTotals=true` = числу строк, полученных по всем страницам (свёрнутых), `totals.amount` =
        сумме `turnover.debit` по ним.
- [ ] `/entries?…&includeTotals=true`: `totals.count` = числу проводок за месяц («Журнал проводок» / отчёт по регистру),
      `totals.amount` = сумме проводок.
- [ ] `/documents?…&includeTotals=true`: `totals.count` = числу документов выбранных видов за месяц; `totals.amount` = сумме
      `amountAccounting` по всем страницам (проверить на месяце с валютными документами).

## 8. Перед установкой на рабочую базу

- [ ] `ЗапрещатьПользователюПраваЗаписи()` = `Истина`, `РежимОбслуживания()` = `Ложь`, `ЗаписыватьОшибкиВЖурналРегистрации()` —
      по решению администратора.
- [ ] `ИдентификаторИнформационнойБазы()` — UUID рабочей базы (не копии).
- [ ] Хеш секрета рабочей базы; секрет передан администратору OneBase отдельно от пароля.
- [ ] Расширение сохранено в файл `.cfe` и загружено в рабочую базу; пользователь `OneBase_ReadOnly` и роль созданы там же.
- [ ] Публикация, HTTPS, брандмауэр — на рабочем сервере (раздел 2 повторить).
- [ ] Администратору OneBase переданы: адрес, пользователь, пароль, секрет, `.crt`, `infobaseId`, ответ
      `/metadata?section=mapping`, окна недоступности.
