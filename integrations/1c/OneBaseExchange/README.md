# OneBaseExchange — расширение 1С для OneBase (HTTP-сервис только для чтения)

Расширение конфигурации для «1С:Бухгалтерии для Узбекистана» (VENKON GROUP, ред. 3.0, платформа 8.3, клиент-серверная база
на MS SQL). Оно публикует HTTP-сервис, через который OneBase забирает бухгалтерские данные по спецификации
[`docs/integrations/ONEC_API_SPECIFICATION.md`](../../../docs/integrations/ONEC_API_SPECIFICATION.md) (v1.1).

> **Статус.** Код написан по спецификации без доступа к конфигурации VENKON и к платформе 1С — **он ни разу не запускался**.
> Имена справочников, документов и реквизитов в настройках — типовые кандидаты, а не проверенные имена. Разработчик 1С
> устанавливает расширение **сначала на копии базы**, сверяет сопоставление по `/metadata`, проходит [CHECKLIST.md](CHECKLIST.md)
> и только потом ставит его на рабочую базу.

## Что делает расширение

- Отдаёт по `GET` справочники, план счетов, курсы, документы, проводки (наборами по документу), остатки и обороты, версии
  объектов — в JSON по спецификации.
- Изменения OneBase находит **только чтением**: `GET /versions` отдаёт идентификаторы и `ВерсияДанных` объектов, OneBase
  дочитывает изменённое по `ids=`. Метод `/changes` (план обмена) **не реализован** — он требует записи в базу; ответ —
  `404 not_found` со ссылкой на `/versions`.
- Не знает заранее имён объектов конфигурации: всё ищет в метаданных по спискам кандидатов из модуля `OneBase_Settings`.
  Чего нет в конфигурации — пропускает (поле не выгружается). Значений не выдумывает.
- Не выгружает персональные данные сотрудников: значения субконто «Сотрудники/Работники/Физические лица» заменяются на
  `"hidden": true` (без id, кода и наименования), а остатки по таким счетам сворачиваются в 1С — строк по людям нет.

## Гарантии только чтения

**Что есть в расширении:** один HTTP-сервис, четыре общих модуля (только сервер, не глобальные, не привилегированные), одна
роль `OneBase_ЧтениеHTTP`. **Чего нет:** планов обмена, своих регистров, констант, справочников, документов, подписок на
события, регламентных заданий, заимствованных объектов с изменёнными модулями.

**Что делает код:** только запросы `ВЫБРАТЬ` (без `ПОМЕСТИТЬ` и `ДЛЯ ИЗМЕНЕНИЯ`), чтение метаданных и констант,
`ПолучитьСсылку(УИД)` (ссылка строится в памяти, база не читается и не пишется), запись JSON в строку. Нет `Записать()`,
`Удалить()`, `ПолучитьОбъект()`, транзакций, управляемых блокировок, привилегированного режима.

**Единственная запись — в журнал регистрации**: при внутренней ошибке (500) расширение пишет событие `OneBase.Ошибка` с кодом,
который возвращает в ответе. Журнал регистрации хранится отдельно от данных информационной базы (файлы журнала на сервере 1С).
Отключается в `OneBase_Settings.ЗаписыватьОшибкиВЖурналРегистрации()`.

**Как проверить самостоятельно** (подробно — [CHECKLIST.md](CHECKLIST.md), раздел «Только чтение»):

1. **Код.** Поиск операций записи по исходникам (вне комментариев) должен ничего не найти:

   ```bash
   grep -rnE 'Записать\(|Удалить\(|ПолучитьОбъект|НачатьТранзакцию|ЗафиксироватьТранзакцию|БлокировкаДанных|ПланыОбмена|ПривилегированныйРежим|ПОМЕСТИТЬ|ДЛЯ ИЗМЕНЕНИЯ|\.Установить\(|УстановитьЗначение|Вычислить\(' src \
     | grep -vE '^[^:]+:[0-9]+:\s*//'
   ```

   В PowerShell:

   ```powershell
   Get-ChildItem -Recurse src -Filter Module.bsl | Select-String -Pattern 'Записать\(|Удалить\(|ПолучитьОбъект|НачатьТранзакцию|ЗафиксироватьТранзакцию|БлокировкаДанных|ПланыОбмена|ПривилегированныйРежим|ПОМЕСТИТЬ|ДЛЯ ИЗМЕНЕНИЯ|\.Установить\(|УстановитьЗначение|Вычислить\(' | Where-Object { $_.Line -notmatch '^\s*//' }
   ```

   Совпадения вида `ЗаписатьНачалоОбъекта`, `ЗаписатьJSON`, `ЗаписьЖурналаРегистрации` — это запись JSON в строку и в журнал,
   под шаблон `Записать\(` они не попадают.
2. **Права пользователя.** `GET /v1/ping` возвращает `"userWriteAccess": false`. По умолчанию сервис вообще отказывает (403),
   если у пользователя есть административные права или права «Изменение», «Добавление», «Проведение» на выгружаемые объекты
   (`OneBase_Settings.ЗапрещатьПользователюПраваЗаписи()`).
3. **Журнал регистрации.** После полной загрузки на копии базы отбор по пользователю `OneBase_ReadOnly` не содержит событий
   «Данные. Добавление», «Данные. Изменение», «Данные. Удаление», «Данные. Проведение», «Данные. Отмена проведения».

## Адреса и методы

Базовый адрес: `https://<сервер>/<публикация>/hs/onebase/v1/<метод>`. У HTTP-сервиса один шаблон URL `/*` и один метод `GET`:
модуль сам разбирает путь `/v1/<метод>`, поэтому новые методы и псевдонимы не требуют правки метаданных. Неверный путь —
`404 not_found` в JSON.

| Метод | Спецификация | Параметры |
|---|---|---|
| `ping` (псевдоним `health`) | 4.1 | — |
| `organizations` | 4.2 | `limit`, `cursor`, `ids`, `includeTotals` |
| `accounts` | 4.3 | то же |
| `counterparties` | 4.4 | то же |
| `contracts` | 4.5 | то же |
| `currencies` | 4.6 | то же |
| `exchange-rates` | 4.6 | `from`, `to`, `currency` (коды через запятую), `limit`, `cursor`, `includeTotals` |
| `warehouses`, `departments` | 4.7 | `limit`, `cursor`, `ids`, `includeTotals` |
| `references` | 4.7 | `kind` (обязательно; `cash_flow_items` = `cash-flow-items`), `limit`, `cursor`, `ids`, `includeTotals` |
| `items` (псевдоним `products`) | 4.8 | `limit`, `cursor`, `ids`, `includeTotals` |
| `documents` | 4.9 | `type` (коды через запятую), `organizationId`, `from`, `to`, `ids`, `withEntries`, `limit`, `cursor`, `includeTotals` |
| `sales` | 4.9 | как `documents`, типы `sale,sale_return,invoice_out,order_customer` |
| `purchases` | 4.9 | типы `purchase,purchase_return,invoice_in,order_supplier` |
| `warehouse` | 4.9 | типы `transfer,write_off,inventory` |
| `finance` | 4.9 | типы `cash_in,cash_out,bank_in,bank_out` |
| `production` | 4.9 | типы `production,material_issue` |
| `entries` (псевдоним `accounting`) | 4.10 | `organizationId`, `from`, `to`, `ids` (документы-регистраторы), `limit`, `cursor`, `includeTotals` |
| `balances` (псевдоним `turnovers`) | 4.11 | `period=ГГГГ-ММ` (обязательно), `organizationId`, `accounts`, `subconto` (по умолчанию `true`), `limit`, `cursor`, `includeTotals` |
| `versions` | 4.13 | `entityType` (обязательно), для `document` — `organizationId`, `from`, `to` (обязательно), `type`; для `reference` — `kind` |
| `directories` | — | список справочников: вид, метод, найден ли, число элементов |
| `metadata` | — | `section`, `details`, `object` — см. [ниже](#сопоставление-с-конфигурацией-metadata) |
| `changes` | 4.12 | не реализован: `404 not_found` |

Типы документов: `sale`, `sale_return`, `purchase`, `purchase_return`, `invoice_out`, `invoice_in`, `order_customer`,
`order_supplier`, `cash_in`, `cash_out`, `bank_in`, `bank_out`, `production`, `material_issue`, `transfer`, `write_off`,
`inventory`, `manual`, `other`. `other` — все остальные документы, которые пишут проводки в регистр бухгалтерии.

Параметр `modifiedSince` не поддерживается (1С не хранит момент изменения): ответ `400` с подсказкой использовать `/versions`.

## Установка в Конфигураторе

Нужна платформа **8.3.10 или новее** (HTTP-сервисы в расширениях; функции `ПолучитьHexСтрокуИзДвоичныхДанных`,
`ПолучитьДвоичныеДанныеИзСтроки` — с 8.3.9). Всё делается **сначала на копии рабочей базы**.

### 1. Создать расширение

1. Откройте копию базы в Конфигураторе. Меню **Конфигурация → Расширения конфигурации → Добавить**.
2. Имя — `OneBaseExchange`, синоним — «OneBase: выгрузка (только чтение)», **префикс имён — `OneBase_`**, назначение —
   **«Дополнение»**. Откройте расширение (**Конфигурация** в строке расширения).
3. В списке расширений («Расширения конфигурации») оставьте флажки **«Активно»**, **«Безопасный режим»** и **«Защита от опасных
   действий»** включёнными: расширению не нужны ни файлы, ни COM, ни внешние компоненты.

### 2. Общие модули

В дереве расширения: **Общие → Общие модули → Добавить** — четыре модуля. У каждого в свойствах:

| Свойство | Значение |
|---|---|
| Глобальный | нет |
| Клиент (управляемое приложение), Клиент (обычное приложение) | нет |
| **Сервер** | **да** |
| Внешнее соединение | нет |
| Вызов сервера | нет |
| **Привилегированный** | **нет** (данные читаются с правами пользователя) |
| Повторное использование возвращаемых значений | Не использовать |

Имена — строго такие, они используются в коде: `OneBase_Settings`, `OneBase_Json`, `OneBase_Metadata`, `OneBase_Export`.
Откройте модуль каждого и вставьте целиком текст соответствующего файла `src/CommonModules/<Имя>/Module.bsl`.

### 3. HTTP-сервис

1. **Общие → HTTP-сервисы → Добавить.** Имя — `OneBase_API`, **корневой URL — `onebase`**, повторное использование сеансов —
   «Не использовать» (каждый запрос — новый короткий сеанс; можно «Автоматически использовать», если нагрузка вырастет).
2. В нём **Шаблоны URL → Добавить**: имя `Все`, **шаблон `/*`**.
3. В шаблоне **Методы → Добавить**: имя `Получить`, **HTTP-метод `GET`**. В свойстве «Обработчик» нажмите лупу — конфигуратор
   создаст в модуле сервиса функцию `ВсеПолучить(Запрос)`.
4. Откройте модуль HTTP-сервиса, удалите заготовку и вставьте текст `src/HTTPServices/OneBase/Module.bsl`. Если конфигуратор
   назвал обработчик иначе — впишите в свойство «Обработчик» имя `ВсеПолучить`.

Других шаблонов и методов не нужно: все адреса `/v1/<метод>` разбирает модуль.

### 4. Роль

**Общие → Роли → Добавить**, имя `OneBase_ЧтениеHTTP`. Если в редакторе прав роли у HTTP-сервиса `OneBase_API` (или его метода)
есть право «Использование» — отметьте его. **Других прав роль не даёт**: права на чтение данных берутся из ролей пользователя
`OneBase_ReadOnly` в основной конфигурации. Модуль сервиса проверяет наличие этой роли (`РольДоступна`) и без неё отвечает
`403` — так роль работает пропуском даже в версии платформы, где у HTTP-сервиса нет своего права.

### 5. Сохранить

**Конфигурация → Сохранить** в окне расширения; если конфигуратор предложит обновить конфигурацию базы данных — согласитесь
(у расширения нет своих данных, реструктуризации не будет). Расширение действует в новых сеансах. Проверка: **Конфигурация →
Проверка конфигурации** в окне расширения — без ошибок; «Синтаксический контроль» (Ctrl+F7) в каждом модуле — без ошибок.
На рабочую базу расширение переносится файлом: **Конфигурация → Расширения конфигурации → Сохранить в файл** (`.cfe`) на копии
и **Загрузить из файла** на рабочей.

### 6. Настроить

В модуле `OneBase_Settings`:

1. `ХешСекретаSHA256()` — хеш секрета ([Секрет API](#секрет-api)). Пока он пуст, сервис на всё отвечает `401`.
2. Временно, на время первого знакомства с конфигурацией под администратором: `ЗапрещатьПользователюПраваЗаписи()` →
   `Ложь`. После настройки — **вернуть `Истина`** и работать только под `OneBase_ReadOnly`.
3. Остальное — по ответу `/metadata` ([ниже](#сопоставление-с-конфигурацией-metadata)).

После каждой правки — **Сохранить**. Опубликованный сервис подхватит изменения в новых сеансах.

## Секрет API

Помимо логина и пароля пользователя 1С (HTTP Basic), каждый запрос несёт секрет API в заголовке
`X-OneBase-Secret: <секрет>`. В расширении хранится **только SHA-256 секрета** (64 шестнадцатеричных символа), сам секрет — нигде.
Сравнение — без раннего выхода; секрет не попадает ни в ответы, ни в журнал.

Вместо `X-OneBase-Secret` можно прислать `Authorization: Bearer <секрет>`, но только если публикация не требует Basic (в одном
заголовке `Authorization` нельзя передать и то и другое). Рекомендуемый вариант — **Basic + `X-OneBase-Secret`**.

Сгенерировать секрет и хеш (секрет — случайные 32 байта в hex, без пробелов и перевода строки):

```bash
# macOS / Linux
SECRET=$(openssl rand -hex 32)
printf %s "$SECRET" | shasum -a 256      # на Linux можно sha256sum; в хеш НЕ должен попасть перевод строки
```

```powershell
# Windows PowerShell
$bytes = New-Object byte[] 32
[Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($bytes)
$secret = -join ($bytes | ForEach-Object { $_.ToString('x2') })
$hash = -join ([Security.Cryptography.SHA256]::Create().ComputeHash([Text.Encoding]::UTF8.GetBytes($secret)) |
    ForEach-Object { $_.ToString('x2') })
$hash
```

Хеш вставьте в `OneBase_Settings.ХешСекретаSHA256()`:

```bsl
Функция ХешСекретаSHA256() Экспорт
	Возврат "3f1c…64 символа…9ab0";
КонецФункции
```

Секрет храните как пароль: передайте его администратору OneBase отдельно от пароля пользователя и не пересылайте вместе
с адресом. Смена секрета — новый хеш в настройках и новый секрет в OneBase (`OneC__ApiSecret`).

## Сопоставление с конфигурацией: /metadata

`GET /v1/metadata` показывает, что реально есть в конфигурации, и как с ней сопоставились настройки:

| Запрос | Что вернёт |
|---|---|
| `/v1/metadata` | конфигурация (имя, версия, платформа), раздел **`mapping`**, списки справочников, документов (с признаком «пишет проводки»), регистров бухгалтерии, планов счетов, регистров сведений, ПВХ, констант, перечислений |
| `/v1/metadata?section=mapping` | только сопоставление |
| `/v1/metadata?section=documents&details=true` | все документы с реквизитами и табличными частями (большой ответ; так же `catalogs`, `accountingRegisters`, `chartsOfAccounts`, `informationRegisters`) |
| `/v1/metadata?object=Документ.РеализацияТоваровУслуг` | один объект подробно: реквизиты с типами, табличные части, движения |

Раздел `mapping`:

- `accountingRegister` — найден ли регистр бухгалтерии, его план счетов, число субконто, измерения (`organization`, `currency`,
  `department` — с признаком балансовости), ресурсы (`amount`, `currencyAmount`, `quantity`), реквизит содержания;
- `accountingCurrency`, `infobaseId` — откуда взяты валюта учёта и идентификатор базы;
- `exchangeRates` — регистр курсов и его поля;
- `catalogs`, `references` — для каждого метода: найденный справочник и `fields` (поле OneBase → реквизит 1С или `null`);
- `documentTypes` — для каждого типа: найденные документы, их поля, табличные части строк и колонки, `notFound` — кандидаты,
  которых нет в конфигурации;
- `otherDocuments` — документы с проводками, не попавшие ни в один тип (уйдут с типом `other`);
- `warnings` — что не найдено и чем это грозит.

Порядок настройки: прочитайте `warnings` и поля со значением `null` → найдите настоящие имена (`?object=…`) → впишите их
первыми в списки кандидатов в `OneBase_Settings` (кандидаты — строка через запятую, берётся первый найденный; для типа документа
— все найденные) → сохраните расширение → повторите `/metadata`. Все места, где имя — лишь типовой кандидат, помечены
в коде комментарием `// проверить по /metadata`.

Что настраивается в `OneBase_Settings`:

| Функция | Что задаёт |
|---|---|
| `РегистрБухгалтерии()` | регистр (по умолчанию кандидат `Хозрасчетный`), измерения организации, валюты, подразделения, ресурсы, реквизит содержания, признаки учёта плана счетов |
| `КурсыВалют()` | регистр сведений курсов (`КурсыВалют`), измерение валюты, ресурсы курса и кратности, источник |
| `СправочникиМетодов()` | справочник и поля для `organizations`, `counterparties`, `contracts`, `currencies`, `warehouses`, `departments`, `items` |
| `ПрочиеСправочники()` | справочники `references?kind=` и состав `attributes` |
| `БанковскиеСчетаКонтрагентов()` | справочник банковских счетов для `bankAccounts` |
| `ТипыДокументов()`, `ПоляДокументов()`, `ПоляДокументовПоИмени()` | документы каждого типа и поля шапки (общие и для отдельных документов) |
| `ТабличныеЧастиСтрок()`, `ПоляСтрок()` | табличные части и колонки строк `lines` |
| `ПерсональныеВидыСубконто()`, `ВыгружатьПИНФЛ()` | что считается персональными данными |
| `ИсключенныеДокументы()`, `ВыгружатьПрочиеДокументы()` | что не выгружать / выгружать ли тип `other` |
| `ИдентификаторИнформационнойБазы()`, `ИмяИнформационнойБазы()` | `infobaseId` и `infobaseName` в `/ping` |
| `ЛимитПоУмолчанию()`, `ЛимитМаксимум()`, `ПроводокНаСтраницеМаксимум()` | размер страниц |
| `РежимОбслуживания()`, `ПовторитьЧерезСекунд()` | ответ `503` с `Retry-After` на время закрытия месяца или обновления |

**Идентификатор базы.** По умолчанию `infobaseId` берётся из константы `ИдентификаторИнформационнойБазы` (если она есть
в конфигурации), иначе вычисляется из строки соединения. Рекомендуется вписать постоянный UUID из первого ответа `/ping`
в `ИдентификаторИнформационнойБазы()` **рабочей** базы и **другой** — в копии: OneBase по смене `infobaseId` понимает, что
подключили другую базу, и не смешивает данные.

## Пользователь OneBase_ReadOnly

1. **Администрирование → Пользователи → Добавить** (в типовой конфигурации на БСП — в режиме 1С:Предприятие,
   «Администрирование → Настройки пользователей и прав», через профиль групп доступа).
2. Имя `OneBase_ReadOnly`, аутентификация 1С:Предприятия с длинным случайным паролем; аутентификация ОС — нет;
   «Показывать в списке выбора» — нет. Запретите интерактивный вход, если конфигурация это позволяет.
3. Роли: **только чтение** нужных справочников, документов, регистра бухгалтерии, плана счетов, регистра курсов и констант
   (валюта учёта, идентификатор базы) **и роль `OneBase_ЧтениеHTTP`**. Без «Изменения», «Добавления», «Проведения»,
   «Администрирования». Если подходящей роли «только чтение» в конфигурации нет — её делает разработчик 1С (в основной
   конфигурации или в отдельном расширении), это вне этого расширения.
4. Проверка: `GET /v1/ping` под этим пользователем → `"user": "OneBase_ReadOnly"`, `"userWriteAccess": false`. Если у
   пользователя есть права записи, сервис отвечает `403 forbidden` и пишет, в чём дело.

Нехватка прав на чтение какого-то объекта даёт `403 forbidden` с кодом для журнала регистрации.

## Публикация на веб-сервере и HTTPS

Публикуется **только во внутренней сети**, только HTTPS (TLS 1.2+), без веб-клиента.

### Публикация

На сервере, где стоит веб-сервер (IIS или Apache) и модуль расширения веб-сервера 1С: Конфигуратор **от имени администратора
Windows** → **Администрирование → Публикация на веб-сервере**:

- Имя публикации, например `buh`; веб-сервер — IIS или Apache 2.4; каталог публикации.
- **Снять** «Публиковать доступ для клиентских приложений» (тонкий и веб-клиент), «Публиковать стандартный интерфейс OData»,
  «Публиковать Web-сервисы по умолчанию».
- Вкладка **HTTP-сервисы**: снять «Публиковать HTTP-сервисы по умолчанию», включить публикацию HTTP-сервисов расширений
  («Публиковать HTTP-сервисы расширений по умолчанию» или отметить `OneBase_API` в списке).
- **Не** указывать пользователя и пароль 1С в параметрах публикации: аутентификация — Basic в каждом запросе.

Результат в `default.vrd` (пример; адрес сервера 1С и имя базы — ваши):

```xml
<point xmlns="http://v8.1c.ru/8.2/virtual-resource-system" base="/buh" ib="Srvr=&quot;1c-server&quot;;Ref=&quot;buh&quot;;">
  <ws pointEnableCommon="false"/>
  <httpServices publishByDefault="false" publishExtensionsByDefault="false">
    <service name="OneBase_API" rootUrl="onebase" enable="true" reuseSessions="dontuse" sessionMaxAge="20" poolSize="10" poolTimeout="5"/>
  </httpServices>
</point>
```

В строке `ib=` не должно быть `Usr=` и `Pwd=`.

### Сертификат

OneBase проверяет сертификат полностью, **включая имя**: в сертификате (Subject Alternative Name) должен быть ровно тот адрес,
по которому OneBase обращается к 1С (IP `192.168.9.141` и/или DNS-имя). Отключить проверку в OneBase нельзя.

- **Внутренний центр сертификации** — выпустите сертификат сервера с SAN и передайте администратору OneBase **корневой
  сертификат ЦС** (PEM, `.crt`).
- **Самоподписанный** — передайте сам сертификат сервера (PEM, `.crt`, без закрытого ключа).

IIS (PowerShell от администратора; адрес и имя замените на свои):

```powershell
$cert = New-SelfSignedCertificate -Subject "CN=1c-buh" -CertStoreLocation "Cert:\LocalMachine\My" `
  -TextExtension @("2.5.29.17={text}IPAddress=192.168.9.141&DNS=1c-buh") `
  -KeyAlgorithm RSA -KeyLength 3072 -HashAlgorithm SHA256 -NotAfter (Get-Date).AddYears(3)
Export-Certificate -Cert $cert -FilePath C:\temp\onec.cer      # открытая часть, DER
certutil -encode C:\temp\onec.cer C:\temp\onec.crt             # PEM — этот файл отдать OneBase
```

Затем в «Диспетчере IIS» → сайт → **Привязки**: `https`, порт 443, этот сертификат; привязку `http` (80) удалить. TLS 1.0/1.1
отключить в реестре (`HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\SCHANNEL\Protocols\TLS 1.0\Server`,
`…\TLS 1.1\Server`: `Enabled = 0`, `DisabledByDefault = 1`) или утилитой IIS Crypto; TLS 1.2 должен быть включён.

Apache (OpenSSL 1.1.1+):

```bash
openssl req -x509 -newkey rsa:3072 -sha256 -days 1095 -nodes \
  -keyout onec.key -out onec.crt -subj "/CN=1c-buh" \
  -addext "subjectAltName=IP:192.168.9.141,DNS:1c-buh"
```

```apache
<VirtualHost *:443>
    SSLEngine on
    SSLProtocol -all +TLSv1.2 +TLSv1.3
    SSLCertificateFile    "C:/Apache24/conf/ssl/onec.crt"
    SSLCertificateKeyFile "C:/Apache24/conf/ssl/onec.key"
    <Location "/buh">
        Require ip 192.168.9.168 127.0.0.1
    </Location>
</VirtualHost>
```

Порт 80 для публикации не слушать.

## Брандмауэр

Доступ к порту публикации — **только с адреса OneBase 192.168.9.168** (и с самого сервера 1С для проверки).

Windows (PowerShell от администратора):

```powershell
New-NetFirewallRule -DisplayName "1C HTTPS for OneBase" -Direction Inbound -Protocol TCP -LocalPort 443 `
  -RemoteAddress 192.168.9.168 -Action Allow
```

Проверьте, что нет других разрешающих правил для 443 со всех адресов (`Get-NetFirewallRule | Where-Object Enabled -eq True`).
В IIS дополнительно: роль «IP and Domain Restrictions» → сайт → «Ограничения IP-адресов и доменов» → разрешить
`192.168.9.168` и `127.0.0.1`, «Изменить параметры компонента» → доступ для неуказанных клиентов — «Запретить». Если между
серверами есть ESXi/виртуальный коммутатор или сетевой экран — откройте там TCP 443 с 192.168.9.168 на сервер 1С.

## Проверка curl

С сервера OneBase (192.168.9.168). `-u OneBase_ReadOnly` без пароля — curl спросит его и не оставит в истории команд;
секрет — из переменной окружения.

```bash
export ONEBASE_SECRET='…секрет…'
BASE=https://192.168.9.141/buh/hs/onebase/v1

curl --cacert onec.crt -u OneBase_ReadOnly -H "X-OneBase-Secret: $ONEBASE_SECRET" "$BASE/ping"
curl --cacert onec.crt -u OneBase_ReadOnly -H "X-OneBase-Secret: $ONEBASE_SECRET" "$BASE/metadata?section=mapping"
curl --cacert onec.crt -u OneBase_ReadOnly -H "X-OneBase-Secret: $ONEBASE_SECRET" "$BASE/organizations"
curl --cacert onec.crt -u OneBase_ReadOnly -H "X-OneBase-Secret: $ONEBASE_SECRET" \
  "$BASE/documents?organizationId=<uuid>&from=2026-10-01&to=2026-10-31&limit=50&includeTotals=true"
curl --cacert onec.crt -u OneBase_ReadOnly -H "X-OneBase-Secret: $ONEBASE_SECRET" \
  "$BASE/entries?organizationId=<uuid>&from=2026-10-01&to=2026-10-31&limit=50&includeTotals=true"
curl --cacert onec.crt -u OneBase_ReadOnly -H "X-OneBase-Secret: $ONEBASE_SECRET" \
  "$BASE/balances?organizationId=<uuid>&period=2026-10&includeTotals=true"
curl --cacert onec.crt -u OneBase_ReadOnly -H "X-OneBase-Secret: $ONEBASE_SECRET" \
  "$BASE/versions?entityType=document&organizationId=<uuid>&from=2026-11-01&to=2026-11-30"
```

Следующая страница — тот же запрос с `&cursor=<page.nextCursor>` (курсор передаётся как есть). Без секрета — `401`, без
пароля — `401` от веб-сервера 1С, с чужого адреса — соединение не устанавливается. В Windows вместо `curl` — `curl.exe`
(в PowerShell `curl` — это псевдоним `Invoke-WebRequest`).

## Что передать администратору OneBase

Отдельными сообщениями, не одним письмом:

1. Адрес: `https://<сервер>/<публикация>/hs/onebase/v1` (в OneBase — `OneC__BaseUrl`).
2. Пользователь `OneBase_ReadOnly` (`OneC__Username`) и пароль (`OneC__Password`) — пароль отдельно.
3. Секрет API (`OneC__ApiSecret`) — отдельно от пароля.
4. Файл сертификата `.crt` (PEM): самоподписанный сертификат сервера или корневой сертификат внутреннего ЦС
   (`OneC__CaCertificatePath`).
5. `infobaseId` из `/ping` рабочей базы и ответ `/v1/metadata?section=mapping` (в нём нет данных, только имена объектов) —
   чтобы OneBase знал, какие типы документов и поля реально выгружаются.
6. Окна недоступности (закрытие месяца, обновления, резервное копирование) — в это время можно включить
   `РежимОбслуживания()`.

## Как устроены ответы

- **Формат** — JSON UTF-8 без BOM, `Content-Type: application/json; charset=utf-8`. Даты без времени — `"2026-10-15"`, дата и
  время — `"2026-10-15T14:30:00+05:00"` (к времени 1С добавляется пояс из `СмещениеЧасовогоПояса()`). Суммы — числа
  с 2 знаками, количество — 3, курсы — 4. Пустая ссылка — `null` или поле отсутствует. `id` — UUID ссылки, `version` —
  `ВерсияДанных`.
- **Страницы** — `limit` (по умолчанию 500, больше 1000 урезается до 1000), `page.nextCursor` (непрозрачная строка,
  URL-безопасный Base64 JSON), `page.hasMore`. С `ids=` (до 100 UUID) страниц нет — возвращаются все найденные объекты,
  удалённых в ответе нет.
- **Порядок и курсоры.** Справочники и план счетов — по ссылке, курсор — последняя ссылка (`Ссылка > &последняя`, без
  смещения: вставка и удаление между страницами не сдвигают строки). Документы, наборы проводок, версии документов — по виду
  документа (в порядке `OneBase_Settings.ТипыДокументов()`, затем прочие), внутри вида — по дате и ссылке; курсор — вид, дата
  и ссылка последнего документа. Курсы — по периоду, валюте и прочим измерениям, курсор — смещение (таблица небольшая; запись
  курса между страницами может сдвинуть строку — OneBase повторяет курс по ключу «валюта + дата» без вреда). Остатки — по коду
  счёта, внутри счёта — по организации, валюте и субконто (у счетов с персональными субконто — по ключу свёрнутых строк);
  курсор — счёт и смещение внутри счёта.
- **Итоги** (`includeTotals=true`, считаются по всему отбору): документы — число и сумма `amountAccounting` (правило ниже); проводки — число
  проводок и сумма в валюте учёта по периоду проводки; остатки — число строк и сумма оборота Дт; курсы и справочники — число.
- **Документы, `amountAccounting`** — по тому же правилу, что нормализатор OneBase, без пересчёта текущим курсом:
  1) реквизит суммы в валюте учёта, если он найден; 2) иначе документ в валюте учёта или без валюты — `amount`;
  3) иначе, если у документа есть курс, — `amount × rate.value / max(1, rate.multiplier)`, округление до 2 знаков с середины
  к чётной копейке (как `Math.Round` в OneBase), из тех же значений `amount`, `rate.value`, `rate.multiplier`, что в ответе;
  4) иначе поле не выгружается. `totals.amount` документов — сумма ровно этого значения по каждому документу отбора (итог
  считается в 1С построчно той же функцией), поэтому месячная сверка OneBase сходится и в месяцах с валютными документами.
  `rate` — курс и кратность из реквизитов документа (для валюты ≠ валюты учёта).
- **Документы, прочее.** `lines` — строки всех найденных табличных
  частей, `lineNumber` сквозной; дополнительно `section` и `sectionLineNumber`. `withEntries=true` — проводки документа
  в `entries` (не проведён — пустой список).
- **Проводки.** Набор — все проводки документа (`ДвиженияССубконто` по регистратору, с отбором по организации), страница набор
  не разрывает; документ попадает в период, если у него есть проводки с периодом в отборе. Непроведённые документы периода
  приходят пустым набором `entries: []`. Валюта, валютная сумма, количество и подразделение — только если такие измерения
  и ресурсы есть в регистре. Субконто — `index`, `type` (имя вида субконто), `id`, `code`, `name`, плюс `valueType`
  (`Справочник.Контрагенты`); у перечислений — `code` = имя значения, без `id`.
- **Персональные данные.** Значения видов субконто из `ПерсональныеВидыСубконто()` (и элементы таких справочников) не
  выгружаются: `{ "index": 1, "type": "Работники", "hidden": true }`. Такие справочники в `/references` — `403`.
- **Остатки по счетам с персональными субконто** (`/balances`, `/turnovers`) **сворачиваются в 1С до разбиения на страницы**:
  строки счёта читаются целиком, колонки персональных субконто убираются, строки с одинаковыми счётом, организацией, валютой
  и остальными субконто складываются (`ТаблицаЗначений.Свернуть`). Складываются все суммы — начальный и конечный остаток Дт
  и Кт, обороты Дт и Кт, валютные суммы и количество, — каждая отдельно, то есть дебетовые и кредитовые остатки людей не
  взаимозачитываются (как итог «ОСВ по счёту» с разворотом по работникам). Строк по людям в ответе нет, суммы по людям из 1С
  не выходят, а у OneBase не появляется нескольких строк с одинаковым ключом «период + счёт + валюта + субконто». Порядок
  свёрнутых строк — по ключу из UUID оставшихся полей (одинаков при каждом запросе), `includeTotals` считается по тем же
  свёрнутым строкам. В `/entries` проводки не сворачиваются: ключ проводки — регистратор и номер строки.
- **Ошибки** — `{ "error": { "code", "message", "field" } }`: `400 invalid_parameter`, `401 unauthorized`, `403 forbidden`,
  `404 not_found`, `500 internal_error` (без текста исключения — с кодом для журнала регистрации), `503 unavailable`
  с `Retry-After` (режим обслуживания, конфликт блокировок, монопольный режим).
- **Не найденный в конфигурации справочник** — пустой список с `warnings` (OneBase не повторяет запрос); не найденный регистр
  бухгалтерии для `/entries` и `/balances` — `404`.
- **Дополнительные поля**, которых нет в спецификации (OneBase их игнорирует): `userWriteAccess`, `extensionVersion` в `/ping`;
  `posted` у набора проводок; `valueType`, `hidden` у субконто; `section`, `sectionLineNumber` у строк; `warnings` у списков.

## Устранение неполадок

| Признак | Причина и что делать |
|---|---|
| `401` с HTML-страницей, а не JSON | Не прошла Basic-аутентификация в веб-сервере 1С: неверный логин/пароль или у пользователя нет аутентификации 1С:Предприятия |
| `401 unauthorized` «Секрет API не настроен» | Пустой или неполный (не 64 символа) `ХешСекретаSHA256()` |
| `401` «Неверный секрет API» | Хеш посчитан от секрета с переводом строки (`echo` вместо `printf %s`) или с пробелами; заголовок не дошёл через прокси |
| `403` «нет роли OneBase_ЧтениеHTTP» | Роль не назначена пользователю или расширение неактивно |
| `403` «есть права на изменение данных» | Пользователь с правами записи/администратора. Нужен пользователь только для чтения (на время настройки — см. `ЗапрещатьПользователюПраваЗаписи`) |
| `403` «нет прав на чтение данных метода» | Роли пользователя не дают «Чтение» на объект; код из сообщения — в журнале регистрации, событие `OneBase.Ошибка` |
| `404` HTML от IIS/Apache | Неверное имя публикации, HTTP-сервисы расширений не опубликованы, расширение не активно |
| `404 not_found` «Адрес должен иметь вид…» | Путь не `/hs/onebase/v1/<метод>` |
| `500 internal_error` с кодом | Подробности — журнал регистрации 1С, отбор по событию `OneBase.Ошибка` и коду. Чаще всего — неверное имя реквизита в настройках (поле найдено, но тип не тот) или особенность регистра |
| `503 unavailable` | Включён `РежимОбслуживания()`, конфликт блокировок или монопольный режим; OneBase повторит после `Retry-After` |
| Пустые списки с `warnings` | Не найден справочник или регистр курсов — поправьте кандидаты по `/metadata` |
| В документах нет `counterpartyId`, `amount`… | У документа нет реквизита из списка кандидатов — см. `mapping.documentTypes` |
| `type` субконто — наименование, а не имя («Статьи затрат» вместо «СтатьиЗатрат») | Платформа не отдала `ИмяПредопределенныхДанных` в запросе или вид субконто не предопределённый; можно оставить или переключить `ИмяВидаСубконто()` |
| Страница проводок долго отвечает (> 60 с) | Уменьшите `limit` на стороне OneBase и/или `ПроводокНаСтраницеМаксимум()` |
| Ошибка TLS в OneBase | В сертификате нет SAN с адресом из `OneC__BaseUrl`, передан не тот сертификат (нужен корневой ЦС или сам самоподписанный), включены только TLS 1.0/1.1 |
| `infobaseId` сменился | Сменилась строка соединения (база перенесена). Впишите постоянный UUID в `ИдентификаторИнформационнойБазы()` |
