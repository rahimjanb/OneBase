## Коротко

AI-аналитик теперь исследует сложный вопрос, а не отвечает одним проходом.
- **План.** Шаги с зависимостями выполняются волнами.
- **Гипотезы.** Проверяются расчётом; статус и вид вывода ставит код — модель их изменить не может.
- **Противоречия** ищутся. Если не хватает данных, план дополняется.
- **Скептик и ревизор.** В глубоком исследовании скептик предлагает альтернативы. Ревизор возвращает ответ на доработку, если причиной названа
  непроверенная или отклонённая гипотеза, не названы ограничения или не совпал пересчёт.
- **Простые вопросы** идут прежним путём — без лишних вызовов модели.

Новое вокруг исследований:
- вычислительный движок — 23 метода, журнал каждого расчёта с повтором;
- анализ сценариев: чувствительность, безубыточность, подбор под цель, Монте-Карло, оптимальный выпуск;
- авторасследование находок и их история;
- память решений;
- уровни безопасности инструментов;
- мониторинг качества;
- набор из 104 сложных вопросов с эталонами.

## Приёмка (Module 15)

| Критерий | Как выполнено |
|---|---|
| Десятки аналитических операций | Исследование — до 8 шагов, каждый со своим циклом инструментов, плюс до 6 + 3 + 3 проверок гипотез и пересчёт. Тест: 4 шага, 3 гипотезы, перепланирование, скептик, 2 цикла проверки |
| Несколько источников и модулей | Шаги — аналитики разных отделов. Межмодульный вопрос получает балл сложности за каждый отдел |
| Несколько гипотез | До 6 от планировщика, до 3 от перепланирования, до 3 от скептика. Обязательна «нулевая» (сезонность, эффект базы) |
| Сложные вычисления | 23 метода и анализ сценариев — кодом, эталоны в тестах |
| Сравнение периодов | `drivers`, `pvm`, `mix`, `churn` — равные отрезки; срезы — `compare` |
| Проверка противоречий | Один показатель с разными значениями, одна гипотеза с разными статусами |
| Дополнительное исследование | Перепланирование при пробелах, противоречиях и недоказанных гипотезах |
| Не останавливается после первой неудачи | Альтернативный источник при перепланировании; Query Repair; повтор неудачного вызова запрещён — модель меняет запрос |
| Точное объяснение ограничения | Метод без данных — «insufficient» с причиной; реестр методов называет, каких данных нет. Ревизор требует ограничения в ответе |
| Никаких выдуманных чисел и причин | Числа — EvidenceCheck. Причины — только по статусам гипотез, их проверяет ревизор. Таблицу гипотез пишет код |

### Стенд на копии базы разработки

Копия `onebase_e2e_intel` (1,27 млн строк продаж, секреты вычищены), второй API и `next dev`. Linko, Telegram, фоновые задачи и платные
вызовы модели выключены.

- **Миграции.** `Analytik5_Intelligence` применилась вместе с последующей миграцией другой сессии.
- **Регрессия набора на реальных данных:**
  - первый прогон — 99 из 104. Четыре сценария честно получили «ok» вместо «нет данных»: у компании есть планы и оплаты, которых нет в
    тестовом мире;
  - пятый нашёл ошибку — две точки с одинаковым названием ломали ABC/XYZ. Исправлено для всех методов, добавлен тест;
  - второй прогон — 104 из 104.
- **Решение** «Усилить команду в Самарканде» (сентябрь → октябрь), записано через экран:
  - база 2 267 000 150 сум, факт 2 780 035 225 сум;
  - +18,7 % в день против ожидаемых +10 % — «ожидание выполнено»;
  - p = 0,203, поэтому вид вывода честно «наблюдаемая зависимость».
- **Анализ сценария на реальном снимке:**
  - торнадо — сильнее всего влияет спрос;
  - Монте-Карло: медиана 381 046, 80 % — 347 532…412 327, ниже базы — 45 %;
  - оптимальный выпуск объясняет, что у проданных товаров нет техкарт (как и ожидалось на базе разработки).
- **Экран исследования** (запись из тестового прогона): план волнами, гипотезы, проверки, возражения скептика, трасса, метрики. По ходу
  исправлено: шаги перепланирования показывались в первой волне.
- **Сводка качества.** По ходу исправлено:
  - прогоны набора больше не попадают в слабые места;
  - замечания проверки — словами;
  - доля неполных ответов считается по ответам.
- **Телефон 390 px** — без горизонтальной прокрутки на всех новых страницах. Ошибок в консоли нет.

### Найдено и исправлено по ходу

- **Журнал срезов.** Источник длиннее 16 символов (`investigation:semantic`) не записывался, неудачная запись оставалась в контексте базы и
  молча ломала сохранения после неё — расчёты гипотез не попадали в журнал. Неудачная запись теперь отсоединяется, источники короткие.
- **Остатки.** Фильтр по региону уходил в срез остатков, а остатки по регионам не делятся.
- **Кортежи C#.** Результаты оптимизации и Монте-Карло сериализовались пустыми объектами. Заменены записями.
- **Одинаковые названия.** Две точки с одним названием сливались в расчётах.

## Что важно знать

- **Не закоммичено** — вы не просили.
  - Другая сессия параллельно добавила миграцию `SalesProductPhotos`, и общий снимок модели содержит обе миграции.
  - Для коммита только моих файлов готов снимок «HEAD + Analytik5» (так проверялась чистая копия).
  - Общие файлы с чужими правками: `docs/analytik.md` — мой только раздел «Advanced Intelligence».
- **Живого прогона моделью не было** — он платный. Исследование, скептик, ревизор и набор проверены на подставной модели по назначению вызова.
  - Запуск: «Аналитик → Качество» → галочка «Понимаю: платные вызовы» → «Живой прогон», бюджет по умолчанию $2.
  - Или `POST /api/analytik/benchmark/live {"confirm": true}`.
- **Глубокое исследование дороже ответа**: план, шаги, иногда перепланирование, скептик и проверка моделью. Ограничения:
  - бюджет вопроса (`QuestionBudgetUsd`, исследование останавливает дополнительные роли на 75 %);
  - пределы `Analytik:Investigation*`;
  - режим `InvestigationMode = off` возвращает прежнее поведение.
- **Меню раздела** сейчас переделывает другая сессия (`sections.ts`). Поэтому входы в «Исследования», «Решения» и «Качество» — на странице
  «Аналитик → История». В меню их стоит добавить, когда их работа будет закоммичена.
- **История и расследование находки** доступны по API (`/api/analytik/insights/{id}/history`). Экран «Риски» сейчас правит другая сессия —
  показ там стоит добавить после их коммита.
- **Две упавших проверки полного прогона в рабочей папке** — от незаконченной работы другой сессии:
  - новая фоновая служба фото не внесена в проверку изоляции восстановления;
  - набор фото не лежит рядом с сервером.

  В чистой копии с моими файлами их нет.
