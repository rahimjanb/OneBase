# OneBase — еженедельные PDF-отчёты в Telegram: итоговый отчёт

Дата: 01.11.2026 · Аудит и план — `ONEBASE_TELEGRAM_PDF_REPORTS_AUDIT.md`.

## 1. Итог

Еженедельный PDF встроен в существующие автоотчёты как восьмой отчёт «8. Еженедельный PDF». Расписание, получатели, история, Telegram-аккаунт и
защита от дублей — общие с картиночными отчётами, второй интеграции нет.

Кто что получает:

| Получатель | Что приходит |
|---|---|
| РОП | страна, 3 страницы A4 |
| РМ | направление, 3 страницы |
| СВ | регион и команда, 10 страниц; при включённой настройке вторым файлом идут карточки всех ТП региона |
| ТП | личная карточка, 2 страницы под телефон, только его цифры |

Отправка: подпись и PDF документом, по расписанию (по умолчанию понедельник 09:00, за прошлую неделю пн–сб), вручную или тестом в выбранный
чат. Файлы хранятся для «скачать» и «сформировать заново».

Состояние:
- **Все тесты проходят:** AI 578 из 579 (1 пропущен), Sales 436, Files 41. Фронтенд собирается (`tsc`, `next build`).
- **Ничего не закоммичено и не выложено.** Настоящих отправок в Telegram не было: локально Telegram выключен, тесты идут на подставном шлюзе.

## 3. Как это работает

```
TelegramReportWorker (30 с) ── weekly-pdf.monday наступил ──► ReportRun (запуск × день, уникально)
   │  перед запуском — обновление Linko, если данным больше 10 минут («Обновлять данные Linko перед отправкой»)
   ├─ ReportDeliveries: получатель × чат × область (уникальный ключ — второй экземпляр службы и повторный круг дубля не дают)
   └─ WeeklyPdfService для каждой строки:
        сбор данных (WeeklyReportBuilder, неделя — последняя полная пн–сб дня запуска)
        → проверка полноты → PDF (WeeklyPdfRenderer) → хранилище (MinIO, telegram/weekly-pdf/<день>/<отправка>/<вид>.pdf)
        → TelegramReportSender: подпись + документы; FLOOD_WAIT — ожидание; сбой связи — повтор (до 3 попыток);
          тайм-аут посреди отправки — «неизвестно, дошёл ли» без автоповтора
```

Ошибки Telegram для картинок и PDF обрабатывает один общий участок кода, `TelegramReportSender.GuardAsync`. Поведение картиночных отчётов не
изменилось, их тесты проходят.

## 4. Как пользоваться

1. **Настройки:** «Настройки → Telegram → Еженедельные PDF-отчёты», или вкладка «Отчёты PDF» на странице автоотчётов. Здесь задаются:
   - «Только при полных данных»;
   - «СВ получает карточки своих ТП»;
   - «Суммы КПУ и DSO в PDF»;
   - формулы целей недели (по умолчанию — формулы образцов).
2. **Проверка:** выбрать роль и область, затем «Предпросмотр» (страницы и состояние данных) или «Скачать PDF». Затем отправить «тест в этот
   чат»: он уходит только туда, с пометкой «ТЕСТОВАЯ ОТПРАВКА».
3. **Получатели:** на вкладке «Получатели» отметить «8. Еженедельный PDF» и при необходимости выбрать язык PDF. Новым получателям PDF по
   умолчанию не отмечается.
4. **Расписание:** на вкладке «Расписание» включить «8. Еженедельный PDF · 09:00». Включение действует с этого момента: прошедшее время не
   догоняется.
5. **Контроль:**
   - «Обзор» показывает готовность, ближайшие и последние запуски и регионы без получателя;
   - «История» показывает статус, этап, лог, скачивание PDF, «сформировать заново» и повтор неудачных.

## 5. Правила данных

| Что | Правило |
|---|---|
| Неделя | пн–сб; воскресенье относится к прошедшей неделе; по расписанию — последняя полная неделя дня запуска |
| Месяц | месяц субботы недели; в воскресенье 1-го числа отчёт ещё за прошлый месяц |
| Факт | по правилам «Продаж»: доставленные заказы минус возвраты, по дате приёмки |
| % плана ТП | из KPI Linko («Тотал»); прогноз — по рабочим дням (пн–сб без праздников справочника) |
| Команда СВ | все ТП региона в «Продажах» |
| Полные данные | заказы и визиты Linko обновлены после конца недели; KPI Linko по области есть. Акции, остатки, DSO и ДМП в PDF при отсутствии показываются как «нет данных» |
| Неполные данные | «только при полных данных» включено — отправка «пропущена» с причиной; выключено — уходит с пометкой в подписи; тест уходит всегда |
| Деньги | в отправках — по настройке «Суммы КПУ и DSO»; в предпросмотре — только с правом finance.read |
| Язык | у получателя (ru или uz), иначе общий язык автоотчётов |
| Цели недели | АКБ — ТТ прошлой недели × 1,1; ТТ по акциям × 1,2, не меньше 25; вернуть 30% спящих 15–30 дней и 20% спящих 30+; продажи — план месяца ÷ рабочие дни × 6 (настраиваются, кроме продаж); весового плана ТП нет — «Тотал» KPI Linko: в кг или в сумах, как заведён. Неделя целей в следующем месяце, а планов ТП на него в Linko ещё нет — план РОП региона на следующий месяц, разложенный по ТП по их планам этого месяца (кг, иначе суммы, иначе факт — первая основа, где вес есть хотя бы у половины ТП; `WeeklyReportMath.SplitPlan`). Подписи АКБ и акций — «было N · +X%», у акций — «но не меньше 25 на ТП»: минимум часто больше факта (у команды из многих ТП — в разы больше прошлой недели), он настраивается в «Отчётах PDF» |
| Неделя в шапке | неделя не закончилась (собран до субботы или за прошедший день) — диапазон по последний день данных, а не по субботу |
| График по месяцам | текущий месяц — по тот же день, что шапка (раньше график брал весь месяц на момент сборки) |
| «К прошлой неделе / месяцу» | от базы меньше 50 кг и у ушедшей в возвраты недели процента нет («+185%» с 15 кг, «−1496%» ничего не значат) — вместо него разница в кг («+28 кг», «−134 кг») |
| Конверсия | визиты с заказом ÷ визиты (0–100%); заказы, принятые без визита, её не поднимают. Плитка ТП — «Визиты / с заказом» (4 / 2), число заказов — в подписи: заказов бывает больше визитов |
| СВР | из «Настроек продаж»; не задан — человек с показателями СВР в KPI Linko, если сам не работает как ТП (меньше 20 визитов за месяц); никого — «не указан» (не «вакансия»: OneBase не знает, свободно ли место) |
| Приоритетные линии | показатели KPI Linko «Могуль» и «Twizos» — в кг или в млн сум, как заведены (в Ташкенте и Намангане — в сумах) |
| Деньги дилера | DSO по дилеру региона и его другим именам («Настройки продаж»): итог — сумма, и таблица по каждому дилеру отдельно (прежний и новый не смешиваются); отрицательная «оплата» — возврат денег дилеру, так и подписана. Подпись блока — дилер, который сейчас отгружается (последняя открытая отгрузка), а не имя склада в Linko |
| Месяц закончился | «КПУ: итог месяца» и «Итог месяца: порог и план» (сколько не хватило) вместо «что добрать» и «нужно в день» |

## 8. Ограничения и риски

| Что | Комментарий |
|---|---|
| ДМП (стеллажи TWIZOS) | данных в OneBase нет: страница ДМП и цели ДМП — «нет данных». Нужна синхронизация инвентаря Linko (только чтение) — отдельная задача |
| Узбекский текст | переводы сделаны разработчиком — нужна вычитка носителем языка |
| Сверка с образцами | известные расхождения: план АКБ региона (сумма планов ТП), Тотал СВ в KPI, % ТП из Linko, прогноз при празднике 1 октября (26 рабочих дней), продажи по акциям |
| Личный аккаунт, не бот | массовая рассылка рискует PEER_FLOOD. Пауза между отправками — 3 с. Начинать с одного региона: тест → СВ и ТП одного региона → остальные |
| Понедельник утром | субботние вечерние заказы приходят только с обновлением Linko — оставить включённым «Обновлять данные Linko перед отправкой» |
| Время сборки | первый отчёт после запуска сервера собирается 30–40 с (загрузка данных «Продаж»), дальше секунды; на ~20 регионов и ~130 ТП с паузой 3 с — порядка 10–20 минут |
| РМ по направлению | на реальных данных не проверен: в локальной копии направлений нет. Проверены РОП, СВ и ТП |
| QuestPDF Community | бесплатно, пока годовая выручка компании меньше $1 млн; иначе нужна платная лицензия |
| Публичный репозиторий | в тестах только вымышленные имена и числа |
