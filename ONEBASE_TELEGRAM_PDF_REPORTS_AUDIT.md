# OneBase — еженедельные PDF-отчёты в Telegram: аудит (этап 0)

Дата: 31.10.2026. Только чтение кода и документации — ничего не изменено. Образцы: PDF РОП (республика), РМ, СВР и карточки ТП
(неделя 26–31.10.2026), собранные внешним дашбордом «Полевой контроль».

## 1. Коротко

- **Почти вся «обвязка» уже есть** в автоотчётах Telegram (v2): каталог запусков, расписание, получатели по оргструктуре
  (РМ/СВ/ТП → чаты), журнал запусков и отправок, защита от дублей, повторы, предпросмотр, тестовая отправка, история. PDF-отчёт —
  это ещё один тип отчёта в этой системе, а не отдельный модуль.
- **Отправка файла-документа уже поддерживается** Telegram-шлюзом (`TelegramFile(Photo=false)` → документ, до 50 МБ).
- **PDF в проекте нет совсем.** Есть растровый рисовальщик отчётов на SkiaSharp (PNG 1920×1080) и шрифт Inter в сборке.
  **Решение (31.10.2026): PDF — на QuestPDF** (вёрстка документа: переносы таблиц с повтором шапки, ориентация страниц, нумерация);
  тип лицензии (Community или Professional) — по консолидированной выручке компании-пользователя, см. раздел 5.
- **Данные для 9 из 10 страниц в OneBase уже считаются** (продажи, план, KPI и премии, категории, визиты и конверсия, клиенты, акции,
  остатки и аутсток, DSO, первичка). **Нет данных по ДМП (стеллажи TWIZOS)** — инвентарь Linko не синхронизируется. **Нет формул
  целей на неделю** — их нужно утвердить.
- Важные отличия ТЗ от устройства OneBase: Telegram — **личный аккаунт (MTProto), не бот**; **нет организаций (OrganizationId)** —
  система однотенантная; **ТП в Linko не привязаны к СВ** — сейчас команда СВ = все ТП региона.

## 2. Текущая архитектура

### 2.1. Telegram

| Что | Где | Как устроено |
|---|---|---|
| Подключение | `Infrastructure/Telegram/WTelegramGateway.cs`, `TelegramConnectionWorker` | Личный аккаунт (WTelegramClient, MTProto), сессия зашифрована DataProtection; `Telegram:Enabled=false` выключает |
| Отправка | `Application/Telegram/TelegramAbstractions.cs` — `ITelegramGateway.SendAsync(accountId, peer, TelegramOutgoing)` | Текст до 4096, подпись до 1024, файлы `TelegramFile(FileName, ContentType, Content, Photo)`: `Photo=false` — документ, фото — альбомом по 10; файл до 50 МБ |
| Ошибки Telegram | `TelegramRules.Classify`, `TelegramReportSender` | FLOOD_WAIT — ожидание без потери попытки; PEER_FLOOD — постоянная ошибка (аккаунт ограничен за массовые сообщения) |
| Привязка человека | `TelegramLinkService`, `TelegramUserPermission.VerifiedAt` | Код привязки на 15 минут; привязанный — личный чат «Telegram привязан» |
| Ограничение | `docs/telegram.md` → «Ограничения Telegram» | Писать можно только в чаты из диалогов аккаунта; массовые сообщения незнакомым — риск блокировки номера |

### 2.3. Хранение файлов, документы, права

- Файлы: `IFileStorage` → `MinioFileStorage` (один бакет MinIO; префиксы `files/`, `telegram/campaigns/`, `tasks/`, …).
  Картинки автоотчётов сейчас **не хранятся** — только число страниц и размер.
- Документы: Excel (ClosedXML: остатки, автозаказ, HR, отчёты ИИ), Word (`DocumentWriter`, OpenXml). **PDF — нет**
  (QuestPDF, Chromium, LibreOffice, wkhtmltopdf отсутствуют; образы Docker — чистые `dotnet/aspnet` и `node:alpine`).
- Права: `Permissions` (`telegram.manage`, `sales.read`, `finance.read`, …), `HasPermission`. Деньги (премии, DSO) — только с
  `finance.read`. **Организаций/тенантов нет** — изоляция по ролям и по области отчёта (`ReportScopes`: СВ — свой регион, ТП — только себя).

## 3. Данные: что есть для каждой страницы

staff_balance (`sales.StaffPlans`, «Тотал» без суммирования с частями — исправлено 30.10); планы регионов — `sales.RegionPlans`.

(`Sales:IncludeToday`).

### 3.1. Расхождения правил, которые надо решить до PDF

1. **Факт недели.** Еженедельный отчёт Telegram считает заказы по дню ввода (все, кроме отменённых), «Продажи» — по дате приёмки
   (доставленные). В одном PDF неделя и месяц должны считаться одинаково — предлагается правило «Продаж».
2. **СВ ↔ ТП.** В Linko ТП к СВ не привязаны: сейчас команда СВ = все ТП региона (два СВ в одном регионе видят одних и тех же ТП).
   Настоящая привязка есть только в Sales Base (`field.Teams`, `FieldMemberService`).
3. **Прогноз месяца** — по рабочим дням пн–сб с праздниками (`DailyPlanMath`), как в образце, а не по календарным.
4. Образцы сделаны внешним дашбордом: где правила OneBase отличаются (статусы возвратов, АКБ, вес заказа — см. `docs/sales-linko.md`),
   цифры PDF будут по правилам OneBase и с образцом сходиться не будут.

## 5. Предлагаемая архитектура

```
TelegramReportWorker (30 с) ── наступил weekly-pdf.monday ──► ReportRun (запуск × неделя, уникально)
        │
        ├─ получатели: ReportSubscriptions (РОП=rm:all, РМ=rm:направление, СВ=sv:регион, ТП=tp:агент) → чаты
        │
        ├─ для каждой области: WeeklyReportBuilder → WeeklySupervisorReport (источники, время данных, предупреждения)
        │        └─ SalesAnalytics · ReportDataService · PromoService · StockService/OutstockService · DsoCompute · PrimaryService
        │
        ├─ PdfReportRenderer (QuestPDF) → MinIO telegram/reports/…
        │
        └─ ReportDeliveries (отчёт × неделя × чат × область — уникально) → ITelegramGateway: подпись + PDF документом
                 повторы 30 с / 2 мин / 10 мин · FLOOD_WAIT · «неизвестно» без автоповтора · ручной «повторить»
```

**Движок PDF — решение: QuestPDF** (31.10.2026). Сравнение вариантов:

| Вариант | Плюсы | Минусы |
|---|---|---|
| SkiaSharp `SKDocument` | уже в проекте (и в Linux-образе); тот же шрифт и приёмы, что в картинках; векторный текст; без новых зависимостей и лицензий | раскладку таблиц, переносы и графики пишем сами (часть уже есть в `SkiaReportRenderer`) |
| **QuestPDF (выбран)** | удобная раскладка, таблицы с повтором шапки и переносы «из коробки», страницы разной ориентации, номера страниц | новая зависимость; Community (бесплатно) — только если консолидированная выручка компании, которая пользуется системой (вместе с компаниями под общим контролем), за прошлый год меньше $1 млн; считается выручка клиента, не разработчика; иначе Professional — $1 999 за первый год, дальше ежегодное продление (questpdf.com/license/guide.html, /pricing.html, проверено 31.10.2026) |
| HTML → PDF (Chromium/Playwright) | вёрстка как у веб-страницы | +сотни МБ в образе, шрифты, медленнее, ещё один процесс на сервере |

**Статусы ТЗ ↔ OneBase.** Запуск: `running/done/partial/failed/skipped`; отправка: `pending/sending/sent/failed/skipped/unknown`.
Этапы ТЗ (CollectingData, DataWarning, GeneratingPdf, ReadyToSend) — добавочным полем «этап» у запуска, без смены существующих статусов.

**Интерфейс.** В ТЗ — раздел «Автоотправка» с шестью вкладками. Расписание, получатели и история у автоотчётов уже есть; чтобы не
было двух расписаний и двух историй, предлагается расширить существующую страницу «Автоматические отчёты»: добавить «Обзор» и
«Отчёты PDF», остальное — общее.

## 6. Риски и зависимости

| Риск | Чем грозит | Что делаем |
|---|---|---|
| Личный аккаунт, не бот: PDF каждому ТП (~130 человек) | Telegram ограничивает (PEER_FLOOD) или блокирует номер | слать только в чаты, где человек уже писал аккаунту или привязал Telegram; группы регионов; запуск поэтапно (сначала РОП/РМ/СВ, потом ТП одного региона); пауза между отправками |
| СВ ↔ ТП не привязаны в Linko | СВ получит чужих ТП, если в регионе два СВ | решить: команда региона или команды Sales Base |
| ДМП нет в данных | стр. 8 и цели ДМП пустые | новая синхронизация инвентаря Linko или «нет данных» в первой версии |
| Формулы целей недели | придуманные цели = неверные задачи людям | утвердить формулы, хранить в настройках |
| DSO из Google Sheets | устаревшие или несопоставленные дилеры | «нет данных — сверить название дилера» вместо нулей; время данных в подвале |
| Расхождения с образцом | вопросы «почему цифры другие» | правила OneBase и ссылка на `docs/sales-linko.md` |
| Нагрузка в понедельник утром | ~20 регионов + ~130 ТП PDF | расчёты «Продаж» кэшируются по месяцу; PDF рисуется за доли секунды; отправка с паузой 3 с ≈ 7–10 минут |
| Узбекский язык | непереведённые подписи | словарь `ReportTexts`; проверка глифов узбекской кириллицы (ў, қ, ғ, ҳ) в Inter |
| Публичный репозиторий | реальные имена и цифры в тестах | только вымышленные данные в тестах и примерах |
