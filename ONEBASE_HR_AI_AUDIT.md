# AI-рекрутер: язык, документы, собеседования — аудит

Задание: язык и графика кандидата, приём и разбор резюме из Telegram, приглашение на собеседование с записью в календарь, результаты
собеседования, фоновая обработка. Аудит — по коду ветки `macbook-pro` на 10.11.2026.

## Что уже есть

| Часть | Где | Что умеет |
|---|---|---|
| Telegram HR | `RecruitmentTelegramHandler`, `TelegramAgentWorker`, `TelegramOutbox` | Настоящий аккаунт (MTProto), маршрутизация по подразделениям, диалоги и история, очередь исходящих с паузой и лимитом. Бота и второго подключения нет. |
| AI-рекрутер | `OneBase.AI/Recruitment/RecruiterAgent.cs`, «Настройки → ИИ-агенты» | Согласие, вопросы отбора, вакансии OneBase, передача HR, выбор времени номером, ограничения, журнал ответов. |
| Язык | `AnswerLanguages.Of`, `DialogAgentPrompt.Uzbek` | Различает ru / uz-Latn / uz-Cyrl по буквам и словам, но рекрутер сводит это к «узбекский или нет». |
| Резюме | `RecruitmentService.AddResumeAsync`, `DocumentTextExtractor`, `DocumentVisionReader` | Файл в MinIO (`recruitment/resumes/{кандидат}/{резюме}`), SHA-256, текст из PDF/DOCX/TXT, фото и сканы читает Claude. Карточка: список резюме, скачать, «Распознать снова (AI)». |
| Дубли кандидатов | `IntakeAsync`, `DetectDuplicatesAsync` | По ID источника и подтверждённым контактам; неподтверждённый контакт — подозрение для HR. |
| Оценка | `CandidateScoring` | Балл 0–100 по критериям вакансии с проверкой цитат. Автооценка выключена по умолчанию. |
| Собеседования | `InterviewService` | Интервьюеры вакансии, свободные слоты по календарю OneBase, повторная проверка при записи, событие календаря, уведомления, напоминание за сутки. Страница «Подбор → Собеседования» — общий список. |
| Календарь | `CalendarService`, `work.CalendarEvents` | Один календарь OneBase; события с участниками и отделом. |
| Уведомления | `UserNotifier` (колокольчик и push), `TelegramOutbox` (кандидату) | Записи в базе в той же транзакции; push — после сохранения. |
| Фоновые службы | `RecruitmentAutomationWorker` (5 мин), `TelegramOutboxWorker` (3 с) | Напоминания, касания, проверка номеров HR. |

## Чего не хватает

### 1. Язык и графика

- **Графика.** Рекрутер различает только «узбекский или нет». Все шаблоны без модели — согласие, «записал на собеседование», варианты
  времени, напоминания, касания — на узбекском написаны латиницей. Кандидат, пишущий кириллицей, получает латиницу.
- **Профиль.** У кандидата одно поле `Language` (ru/uz). Нет графики, последнего определения и уверенности.
- **Смена языка.** Язык не закреплён: каждое сообщение определяется заново. Короткое «ok» или «1» может переключить язык. Явной просьбы
  («пишите кириллицей», «по-русски») рекрутер не понимает.
- **Модель.** Модель получает «пиши той же графикой, что собеседник», без указания, какая это графика.
- **Проверки.** Ответ модели на чужой графике не проверяется.
- **Голос.** Входящие голосовые из Telegram в OneBase не приходят (`TelegramIncoming` — текст, документ, фото). Распознавания голоса для
  Telegram нет — сделать нельзя без новой инфраструктуры.

### 2. Документы

- **Порядок.** Задание: сначала сохранить оригинал, потом разбирать. Сейчас наоборот: текст и распознавание AI идут до записи в MinIO. Если
  разбор упал с исключением, файл не сохраняется.
- **Блокировка ответа.** Распознавание фото в Claude идёт внутри обработчика сообщения — до ответа кандидату. У HR всего 2 слота, поэтому два
  скана держат все диалоги HR.
- **Повторная загрузка из Telegram.** Ссылка на файл живёт только в памяти сервера и удаляется после первой попытки. Если скачивание сорвалось,
  повторить его нельзя, и файл теряется молча.
- **Форматы:**
  - DOC не читается («старый формат Office»);
  - RTF и ODT принимаются, но текст не извлекается;
  - таблицы DOCX склеиваются в строку.
- **Тип файла** проверяется только по расширению. Сигнатура не проверяется: под `.pdf` может прийти что угодно.
- **Антивирус.** Сканера в стеке нет (ClamAV не развёрнут). Файлы не исполняются и отдаются на скачивание как вложение. Опасные типы
  отдаются как `application/octet-stream`.
- **Поля у документа.** Нет статусов (обработка, OCR, анализ), отклика, к которому относится документ, и ссылки на сообщение Telegram.
- **Повторы и лимит.** Тот же файл второй раз — ошибка, сообщение без документа. 11-й файл кандидата — ошибка, файл не сохраняется.
- **Разбор резюме.** Структурированных полей нет (ФИО, телефон, опыт, образование, навыки, ожидания) — только сплошной текст. Нет пометок
  «из резюме / выведено» и «не подтверждено». Карточка кандидата из резюме не дополняется.
- **Ответ кандидату** о приёме резюме — только если ответила модель. Обещания «изучил» ничто не останавливает.
- **Согласие.** Распознавание в Claude (внешний сервис) идёт и без согласия кандидата на обработку данных.
- **Раздел «Документы».** В карточке есть «Резюме»: имя, размер, текст. Нет статусов, просмотра и истории версий.

### 3. Приглашение на собеседование

- **Оценка перед приглашением.** Модель решает «пригласить» сама. Порога оценки по вакансии нет — критерии вакансии не проверяются.
- **Настройки — общие для всех вакансий.** Есть только часы, длина и дни. Нет по вакансии:
  - ответственного интервьюера;
  - перерывов;
  - минимального срока записи (жёстко 2 часа);
  - горизонта (жёстко 10 дней);
  - формата и адреса;
  - онлайн-ссылки;
  - часового пояса (жёстко +5).
- **Действия кандидата.** «Другое время», «отказываюсь», «отменить», «перенести» не распознаются, и нет кириллических вариантов.

### 4. Собеседование и календарь

- **Статусы.** Нет `AWAITING_CANDIDATE_CONFIRMATION` и `RESCHEDULED`, нет подтверждения кандидатом.
- **Поля.** Нет интервьюера, часового пояса и онлайн-ссылки.
- **Защита от одновременной записи** — замок в памяти одного процесса. Второй экземпляр backend его не видит.
- **Связь с календарём** — `CalendarEventId`, без уникальности. Событие собеседования можно изменить или удалить в общем календаре, и
  собеседование об этом не узнает.
- **Изменения:**
  - переноса нет;
  - отмена удаляет событие, но никого не уведомляет — ни кандидата, ни интервьюера.
- **Руководитель отдела** вакансии не уведомляется.
- **Страница «Собеседования»** — два списка («предстоящие» и «остальные»). Нет видов «Сегодня», «Завтра», «Неделя», «Прошедшие»,
  «Отменённые», «Перенесённые». Нет отдела, интервьюера, ссылки на резюме, сводки AI и подтверждения кандидата.

### 5. Итоги собеседования

Нет совсем: оценок, сильных и слабых сторон, рекомендации, следующего этапа.

### 6. Очереди и фоновая обработка

- **Очередь заданий.** Длительных заданий с повтором и переживанием перезапуска нет. Есть только очередь исходящих Telegram.
- **Брокер.** Брокера сообщений (RabbitMQ и т. п.) в OneBase нет. Принятый в проекте способ — таблица-очередь в PostgreSQL с захватом
  строки условным `UPDATE` (как `telegram.OutgoingMessages`).

### Мультитенантность

В OneBase нет `TenantId`: одна установка — одна компания. Поле арендатора не вводится, иначе получится инфраструктура, которой нет в
остальных модулях. Изоляция — права «Подбор персонала» и пути `recruitment/…` в MinIO. Публичных ссылок MinIO нет: файлы отдаёт API после
проверки прав.

## План по этапам

Каждый этап — сборка, тесты, проверка, отчёт.

1. **Язык и графика:**
   - `LanguageDetection` — язык, графика, уверенность;
   - закреплённый язык кандидата и явная смена;
   - три варианта всех шаблонов;
   - явная графика в промпте;
   - проверка ответа модели;
   - язык в карточке кандидата.
2. **Документы и очередь:**
   - таблица-очередь `recruitment.Jobs` с отдельными очередями `hr.resume.download`, `hr.resume.ocr`, `hr.resume.analysis`,
     `hr.candidate.scoring`, `hr.interview.scheduling`, `hr.interview.notifications`, с повтором и арендой;
   - документ сначала сохраняется (запись + задание скачивания), разбор — в фоне;
   - проверка сигнатур;
   - DOC, RTF, ODT, таблицы DOCX;
   - разбор резюме AI с доказательствами;
   - дополнение карточки без перезаписи проверенного;
   - уведомление кандидата;
   - раздел «Документы».
3. **Собеседования и календарь:**
   - настройки собеседования у вакансии;
   - порог оценки перед приглашением;
   - статусы и подтверждение кандидатом;
   - запись под замком PostgreSQL;
   - одно событие календаря на собеседование;
   - перенос и отмена — в обоих местах с уведомлениями;
   - защита события собеседования в общем календаре;
   - действия кандидата в Telegram;
   - страница «Собеседования» с видами.
4. **Итоги собеседования** — форма HR и следующий этап отклика (решение — за HR).
5. **Документация, проверка на экране, итоговый отчёт.**

Все изменения схемы — только новые таблицы и столбцы. Данные, Telegram-сессии, `.env` и production не трогаются. Платные вызовы AI в тестах
не выполняются: используется подставная модель.
