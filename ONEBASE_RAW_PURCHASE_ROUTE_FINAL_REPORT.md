## Как теперь работает

- **Два типа заявок** — «Обычная закупка» и «Закупка сырья». Тип выбирается в «Новой заявке».
  - В заявке на сырьё — только позиции категорий сырья, в обычной — без них. Сейчас категории сырья — «Сырьё» и «Производственные
    материалы».
  - Флажок «сырьё» у категорий — в «Заявки → Настройки».
- **Заявку на сырьё создают** снабженцы (право «Снабжение: обработка заявок»), аналитики (новая роль «Аналитик») и финансист из настроек
  снабжения. Остальные сотрудники — только обычные заявки.
- **Кто согласует — по автору.** После последнего шага заявка уходит в снабжение («К закупке»):

| Кто создал | Кто согласует (по умолчанию) |
|---|---|
| Снабженец | аналитик → финансист |
| Аналитик | финансист |
| Финансист | аналитик |

- **Маршрут настраивается** в «Настройки → Отделы → Снабжение → Маршрут закупки сырья».
  - Для каждого автора — шаги по порядку из «аналитик», «финансист», «директор», «директор, если сумма больше лимита».
  - Заявки в пути идут шагами, с которыми их отправили.
- **Свою заявку никто не согласует.** Шаг аналитика решают другие аналитики. Если их нет, заявка ждёт, а тем, кто настраивает снабжение,
  приходит предупреждение.
- **После существенной правки** утверждённая заявка на сырьё снова идёт на согласование с первого шага.
- **Обычные закупки** — как раньше: руководитель отдела → финансист → директор, если сумма больше лимита.
- **Заявки по прежнему маршруту сырья** (руководитель снабжения → директор) доходят по-старому.

## Этапы

1. **Сервер:**
   - тип заявки, роль «Аналитик», маршрут по автору из настроек, проверки авторов и состава;
   - статус «Ожидает аналитика», уведомления, повторное согласование;
   - миграция `RawPurchaseRoute` — только добавления;
   - тесты.
2. **Интерфейс:**
   - выбор типа в «Новой заявке» с подсказкой, кто согласует; категории и товары по типу;
   - метка «Закупка сырья», статус и маршрут с аналитиком в карточке;
   - таблица маршрута в настройках; счётчики;
   - узбекский — 36 строк;
   - инструкция для сотрудников и описание модуля.
3. **Проверка:** миграция на локальной базе, проверка на настоящих данных только чтением, этот отчёт.

## Что не сделано или требует вас

1. **Проверка в самом приложении со входом.** У меня нет входа в приложение: страницы отвечают переадресацией на вход, ошибок сборки нет.
   Посмотрите, пожалуйста: «Заявки → Новая заявка», «Настройки → Отделы → Снабжение», карточку заявки на сырьё.
2. **Настроить людей — иначе заявки на сырьё не пройдут.** На локальной базе сейчас:
   - нет ни одного пользователя с ролью «Аналитик»;
   - нет сотрудников с ролью «Снабжение» — заявки на сырьё может создать только администратор;
   - финансист не выбран.

   Чтобы маршрут заработал:
   - «Настройки → Пользователи» — роль «Аналитик» аналитикам, «Снабжение» снабженцам;
   - «Настройки → Отделы → Снабжение» — выбрать финансиста.
3. **Снимки экрана в инструкции и PDF.** Снимки сделаны в настоящем приложении.
   - `settings-raw.png` и `request-waiting.png` показывают прежний маршрут — ссылки на них из текста убраны, файлы остались.
   - `approvals.png` и `raw-materials.pdf` не пересняты.
   - Чтобы переснять, нужен вход в приложение.
4. **«Производственные материалы» — тоже сырьё.** У категории стоит флажок «сырьё», поэтому, например, перчатки и смазку теперь можно
   заказать только заявкой на сырьё. Если это не так, снимите флажок у категории в «Заявки → Настройки».
5. **Тесты, где сырьё было взято случайно.** В шести старых тестах закупок рядовой сотрудник заказывал «Сырьё» обычной заявкой. По новому
   правилу так нельзя, поэтому там категория заменена на «Комплектующие». Сами проверки не менялись.
6. **Коммит.** Ничего не загружено в git — по команде «загружай в гит».
