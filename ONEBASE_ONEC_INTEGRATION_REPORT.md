# Интеграция 1С:Бухгалтерия (VENKON GROUP) → OneBase — итоговый отчёт

Обновлено 26.11.2026 по ТЗ «Полная интеграция 1С с OneBase до Production Ready». Первая версия — 17.11.2026 (коммит c64e465), аудит —
[ONEBASE_ONEC_INTEGRATION_AUDIT.md](ONEBASE_ONEC_INTEGRATION_AUDIT.md), работа и запуск — [docs/finance.md](docs/finance.md).

> **Главное.** Настоящая 1С **не подключена**: сервер 1С 192.168.9.141 из сети разработки не отвечает ни на одном порту (443, 80, 1540,
> 1541 — проверено 26.11), HTTP-сервиса в 1С пока нет, адреса, пользователя, пароля и API Secret нет. Всё, что ниже отмечено как
> «проверено», проверено на **тестовом источнике** (демо-данные 1С по той же спецификации), а не на рабочей 1С. Пункты, которые без 1С
> проверить нельзя, отмечены «ждёт 1С». Критерии приёмки «реальное подключение», «история загружена», «KPI сверены с 1С» **не выполнены**
> и не могут быть выполнены без доступа к 1С.

## 1. Что реализовано

**До 26.11 (c64e465):** служба интеграции (отдельный процесс и контейнер `onec-worker`), внутренний API с ключом службы, схема `onec`
(справочники, документы, проводки со всеми субконто, оборотно-сальдовая ведомость, журнал изменений, служебные таблицы), нормализация,
историческая загрузка по месяцам со сверкой итогов, синхронизация каждые 30 минут с повторами, очередь ошибок, страница «1С» в настройках,
раздел «Финансы», AI-инструменты `finance_*`, тестовый источник с демо-данными, спецификация API для 1С.

**26.11 — по новому ТЗ:**

| Требование ТЗ | Что сделано |
|---|---|
| «Запрещено изменять данные в 1С», «Не полагайся только на дату документа» | **Изменения только чтением — сверка версий.** Метод `/versions` (идентификатор + `ВерсияДанных`) и отбор `ids=`: служба сравнивает версии 1С со своими, дочитывает новое и изменённое, пропавшее в 1С перепроверяет по `ids=` и помечает удалённым. Каждые 30 минут — справочники и документы текущего и двух прошлых месяцев, раз в сутки ночью — все загруженные месяцы. План обмена (`/changes`, он пишет в базу 1С) стал необязательным. Режим выбирается автоматически по `/ping` или `ONEC_CHANGE_TRACKING`. |
| HTTP-сервис 1С: методы, авторизация, инструкция | **Расширение 1С `OneBaseExchange`** (исходники и инструкция для 1С-программиста): все методы спецификации v1.1 и логические адреса ТЗ (`/health`, `/sales`, `/purchases`, `/warehouse`, `/finance`, `/accounting`, `/turnovers`, `/production`, `/directories`, `/products`), только запросы — ни записи, ни транзакций, ни планов обмена; имена объектов не выдумываются — ищутся в метаданных и сверяются через `/metadata`. |
| API Secret | Заголовок `X-OneBase-Secret` вместе с пользователем 1С (расширение хранит только SHA-256 секрета). |
| Настройки в панели: адрес, API Secret, организация, интервал, модули, дата начала истории | Блок «Подключение к 1С» (адрес, пользователь, пароль, API Secret, сертификат PEM) — пароль и секрет хранятся зашифрованными (ASP.NET Data Protection), обратно не показываются, в аудит не пишутся; служба применяет подключение без перезапуска. Блок «Что загружать»: организации, модули, начало истории. |
| Синхронизация отдельных модулей | «Синхронизировать модуль»: только документы модуля (проводки — если включена «Бухгалтерия»). |
| Мониторинг с фильтрами по датам, модулям, статусам | Журнал запусков — отбор по дням, статусу, виду; ошибки — по потоку; в шагах — «Сверка версий · документы …». |
| Dashboard: день/месяц/год, фильтры организация, подразделение, склад, контрагент, номенклатура | «Финансы»: блок «День, месяц, год» (продажи, валовая прибыль, закупки, затраты на производство), отборы по контрагенту, номенклатуре, складу, подразделению во всех отчётах. |
| Заказы покупателей и поставщикам | Типы документов `order_customer`, `order_supplier` (модули «Продажи» и «Закупки»). |
| Персональные данные | Расширение не отдаёт значения субконто сотрудников и физлиц; строки ведомости по ним сворачиваются в 1С, OneBase дополнительно складывает строки с одинаковым ключом. |

## 11. Что нужно со стороны 1С и сети

1. **Сеть:** доступ с сервера OneBase 192.168.9.168 к 192.168.9.141 по HTTPS (сейчас — нет ответа ни на одном порту); правило брандмауэра
   Windows / ESXi — только для 192.168.9.168.
2. **Веб-сервер и публикация** (IIS или Apache) базы 1С с HTTP-сервисами по HTTPS; сертификат (если внутренний ЦС — файл .crt).
3. **Установка расширения `OneBaseExchange`** 1С-программистом: сначала копия базы, сопоставление по `/metadata` (имена документов,
   реквизитов, регистра бухгалтерии и курсов в настройках — типовые кандидаты, их нужно подтвердить), [CHECKLIST](integrations/1c/OneBaseExchange/CHECKLIST.md),
   затем рабочая база.
4. **Пользователь 1С только для чтения** + API Secret (в расширение — только его SHA-256).
5. Передать администратору OneBase: адрес публикации, пользователя, пароль, API Secret, сертификат — они вводятся на странице «1С».
6. Подтвердить: какие организации загружать, с какой даты история, что нельзя передавать (персональные данные уже скрываются).
7. После подключения: «Проверить соединение» → «Тестовая синхронизация» → историческая загрузка вне рабочих часов → сверка ОСВ и итогов
   с 1С по каждому месяцу (страница показывает расхождения).
