# Интеграция 1С:Бухгалтерия (VENKON GROUP) → OneBase Finance — итоговый отчёт

Дата: 17.11.2026. Ветка `macbook-pro`, **не закоммичено**, production не обновлялся. Аудит перед началом —
[ONEBASE_ONEC_INTEGRATION_AUDIT.md](ONEBASE_ONEC_INTEGRATION_AUDIT.md). Работа раздела и запуск — [docs/finance.md](docs/finance.md).

> **Настоящая 1С не подключена.** Сеть до 192.168.9.141:443 не отвечает (timeout), HTTP-сервис 1С не опубликован, API VENKON
> не подтверждён. Всё проверено на тестовом источнике (демо-данные 1С). Реальная 1С включается после ответа VENKON
> ([вопросы](docs/integrations/ONEC_VENKON_QUESTIONS.md)) — переменными окружения службы, без изменения кода, если API совпадёт с
> [предложенной спецификацией](docs/integrations/ONEC_API_SPECIFICATION.md) (иначе меняется только адаптер `OneCHttpDataProvider`).

## 2. Архитектура

```
1С:Бухгалтерия (192.168.9.141, HTTPS, GET)
   │  /ping, справочники, /documents, /entries, /balances, /changes — страницами по 500
   ▼
onec-worker (контейнер, профиль «onec»)        IOneCDataProvider: OneCHttpDataProvider | OneCMockDataProvider
   │  OneCNormalizer → пакет; RetryPolicy; SyncEngine; ConnectionDiagnostics; пульс 15 с
   │  POST http://api:8080/api/internal/onec/*   (X-OneBase-Integration-Token)
   ▼
api: OneCInternalController ─► OneCSyncService (запуски, команды, ошибки, история)
                              OneCImportService (пакет = транзакция: записи + журнал + курсор)
   ▼
PostgreSQL, схема onec ─► FinanceReportService ─► /api/finance (раздел «Финансы»), finance_* (AI)
```

Служба в PostgreSQL не пишет. Учётные данные 1С — только у службы. Состояние — в OneBase, поэтому служба без состояния.

## 3. Структура БД (миграция `20261116203502_Finance1_OneCImport` — только новые таблицы схемы `onec`)

| Таблица | Что хранит |
|---|---|
| `Organizations`, `Accounts` (виды субконто — jsonb), `Counterparties` (реквизиты — jsonb), `Contracts` (отсрочка), `Currencies`, `ExchangeRates` (курс, кратность, источник), `References` (склады, подразделения, статьи ДДС и затрат, банковские счета, кассы, партии…), `Items` | справочники 1С |
| `Documents` (+ `DocumentLines`) | документы: тип, сумма в валюте и в валюте учёта, курс с датой и источником, срок оплаты, проведён |
| `Entries` | проводки: Дт/Кт, сумма, валютные суммы, количество, все субконто (jsonb) + контрагент/номенклатура/склад колонками, регистратор, дата по Ташкенту |
| `Balances` | оборотно-сальдовая ведомость 1С по месяцам: сальдо и обороты (суммы, валюта, количество) по счёту, субконто, валюте |
| `Changes` | журнал изменений: обновлено, удалено, восстановлено, отмена проведения, перепроведение — поля «было → стало» |
| `SyncRuns` (один Running — уникальный частичный индекс), `SyncCheckpoints`, `ImportBatches` (ключ идемпотентности), `SyncFailures` (очередь ошибок с данными), `HistoricalImports`, `WorkerCommands`, `WorkerStates` | состояние синхронизации |

У каждой записи 1С: `SourceSystem`, `SourceOrganizationId`, `SourceEntityType`, `SourceEntityId` (уникальный индекс), `SourceVersion`,
`SourceUpdatedAt`, `ImportedAt`, `UpdatedAt`, отпечаток, `IsDeleted`. Настройки — строка `onec` в существующей `public."Integrations"`
(ключ службы — только SHA-256).

## 5. Отчёты «Финансов» и AI

- P&L — по проводкам на счетах 90–98 (НСБУ №21), без закрытия на 9910 и переносов между счетами доходов и расходов; сравнение — с прошлым
  периодом той же длины, месяц к дате — с теми же днями прошлого месяца.
- Деньги — счета 50–57 по корреспондирующим счетам, без переводов между своими счетами и курсовых разниц.
- Расчёты — счета 40/60 по контрагентам из ведомости 1С; просрочка — оценка FIFO по документам и срокам оплаты (документ или договор).
- Отклонения — рост расходов, крупные разовые проводки (с учётом регулярных), исправления прошлых месяцев, двойные платежи, новые
  контрагенты с крупными суммами — как сигналы.
- В каждом ответе — источник («факт 1С» или демо), период, организация, синхронизация, «проводки по». Планы и бюджеты OneBase не смешиваются.
- AI: `finance_overview`, `finance_pnl`, `finance_compare`, `finance_cash_flow`, `finance_settlements`, `finance_accounts`,
  `finance_operations`, `finance_anomalies`, `finance_entries` — только чтение, право «Финансы», **доступ AI включает администратор**
  (по умолчанию выключен), субконто сотрудников и физлиц скрыты, в ответе — период, источник, синхронизация, отбор, ссылка в «Финансы».
  Живая проверка на платной модели не делалась (нужно ваше разрешение) — инструменты проверены тестом напрямую.

## 8. Безопасность

| Требование | Как выполнено |
|---|---|
| Только 1С → OneBase | все методы адаптера — GET; в 1С ничего не пишется |
| Только исходящие запросы | служба сама обращается к 1С и к OneBase; 1С в OneBase не ходит |
| Только HTTPS, проверка TLS | http не принимается в production; сертификат проверяется всегда (внутренний ЦС — явный доверенный корень); имя сервера проверяется; «принять любой» нет |
| Пароли и токены | пароль 1С — только в переменных службы, в OneBase и браузер не передаётся, в журнал не пишется; ключ службы — SHA-256, показывается один раз; ошибки 1С — без тел ответов и параметров |
| Внутренний API | ключ службы, сравнение за постоянное время, неверный ключ — 401 и аудит; nginx отвечает 404 на `/api/internal/` (все три сервера), запрос через nginx (`X-Real-IP`) отклоняется и в API |
| Права | финансы — `finance.read`, настройки 1С — `integrations.manage`, только GET у финансов; проверено тестом и в интерфейсе |
| Аудит | `integration.onec.updated / token_created / tested / test_sync / sync / paused / resumed / historical_started / historical_cancelled / failures_retried / failure_ignored / data_cleared / token_rejected` |
| AI | доступ выключен по умолчанию; только `finance.read`; персональные субконто скрыты; только чтение |
| Данные разных баз | смена базы 1С останавливает загрузку; очистка — только словом ОЧИСТИТЬ; тестовый источник в production выключен без явного разрешения |
| Миграции | только создание схемы `onec` и её таблиц; существующие таблицы не меняются |

## 9. Docker

Сервис `onec-worker` в `docker-compose.yml`, **профиль `onec`**: `deploy/update.sh` (`build api web`, `up -d`) его не собирает и не
запускает. Образ собран и проверен локально (371 МБ, пользователь `app`, без root): тестовый источник в production без разрешения не
стартует (код 2), healthcheck — `dotnet …Worker.dll health`. Порт наружу не публикуется; сертификат — `deploy/onec/` только для чтения.
При следующем обновлении nginx будет пересоздан (изменились `nginx.conf` и `docker-compose.yml`) — как обычно при изменении его конфигурации.

## 10. Что нужно от VENKON GROUP

Полный список — [ONEC_VENKON_QUESTIONS.md](docs/integrations/ONEC_VENKON_QUESTIONS.md). Главное:
1. Веб-сервер (IIS/Apache) и публикация HTTP-сервиса 1С по HTTPS; адрес публикации и порт.
2. Доступ к порту **только** с 192.168.9.168; причина текущего timeout (брандмауэр Windows, ESXi, нет веб-сервера).
3. Сертификат публикации (файл, если внутренний ЦС).
4. Пользователь 1С только для чтения (или токен).
5. Реализация API по спецификации или своя документация; план обмена для `/changes`; `totals` для сверки.
6. Названия документов конфигурации, виды субконто, срок оплаты (договор/документ), курсы, дата начала данных, состав организаций.
7. Что нельзя передавать (персональные данные, зарплата по сотрудникам).

## 11. Параметры для подключения реальной 1С

`ONEC_BASE_URL` (https-адрес публикации), `ONEC_USERNAME` + `ONEC_PASSWORD` (или `ONEC_TOKEN`), `ONEC_CA_CERT_PATH` (если внутренний ЦС),
`ONEC_INTEGRATION_TOKEN` (создаётся на странице 1С), `ONEC_PROVIDER=http`, `ONEC_ENABLED` (сначала false), при необходимости
`OneC__Paths__<метод>` — если VENKON назовёт методы иначе.

## 12. Запуск — по шагам

Подробно — [docs/finance.md, раздел «Запуск»](docs/finance.md). Коротко для рабочего сервера:
1. Резервная копия (`deploy/backup.sh`), обновление OneBase (`deploy/update.sh`) — применится миграция `Finance1_OneCImport`.
2. «Настройки → Интеграции → Финансы → 1С» → «Создать ключ».
3. Добавить в `.env` переменные ONEC_* (ничего не заменяя), `ONEC_ENABLED=false`.
4. `docker compose --profile onec up -d --build onec-worker` → на странице 1С все шаги диагностики зелёные → «Тестовая синхронизация».
5. `ONEC_ENABLED=true`, перезапустить службу → «Запустить историческую загрузку» (вне рабочих часов бухгалтерии).
6. Право «Финансы» — тем, кто должен видеть раздел; при желании — «AI-консультант может отвечать по данным 1С».

## 13. Ограничения и что осталось

- Реальная 1С не подключена (см. начало). Адаптер построен по нашей спецификации; при другом формате VENKON меняется только он.
- Бюджеты, планы и прогнозы финансов в OneBase не строились (не было в задании как модуль) — их отдельность от факта 1С обеспечена:
  факт живёт только в схеме `onec` и подписан в каждом отчёте.
- Доступ по организациям внутри «Финансов» — одним правом `finance.read` (OneBase однокомпанийный); изоляция организаций — в данных,
  отборе и записи пакетов.
- Просрочка — оценка FIFO, пока 1С не отдаёт сроки по документам расчётов.
- Карточка отдела «Финансы» на доске «Отделы» по-прежнему про платёжную дисциплину Linko; кнопка отдела ведёт в новый раздел.
- Узбекский перевод — основные подписи раздела и страницы 1С; остальное показывается по-русски.
- Локальная рабочая база: миграция `Finance1_OneCImport` применится при следующем перезапуске локального API (:5081) из общей сборки.
- Ничего не закоммичено и не выкачено — жду команды.
