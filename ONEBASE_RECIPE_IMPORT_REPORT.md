# Импорт техкарт из «Tex karta.xlsx» — финальный отчёт

Аудит и решения — [ONEBASE_RECIPE_IMPORT_AUDIT.md](ONEBASE_RECIPE_IMPORT_AUDIT.md). Инструкция технолога — [docs/guide/recipe-import.md](docs/guide/recipe-import.md).
В `supply-production.pdf` раздел 19 дополнен, из «Чего пока нет» импорт убран, PDF пересобран.

## 1. Что обнаружено в архитектуре

Модуль «Технолог» уже умеет всё, что нужно импортированной карте:
- версии с утверждением другим технологом или начальником производства;
- этапы, нормы на выход, замес, штуку, упаковку или коробку;
- карту **без этапов** («прежняя рецептура», нормы на выход);
- сравнение версий;
- расчёт потребности, задания со снимком расчёта, выдачу по FEFO, смены, закрытие со сверкой;
- оприходование выхода полуфабриката партией.

Импорта из Excel не было (он был в «Чего пока нет»).

Ограничения техкарты, которые импорт соблюдает:
- норма больше нуля и не больше 6 знаков после запятой;
- позиция — одна строка в карте без этапов;
- до 100 строк;
- код — до 32 знаков;
- одна неутверждённая версия на код.

## 2. Использованные сущности

- **Техкарты:** `ProductionRecipe` и `ProductionRecipeLine` (`production.Recipes` и `RecipeLines`). Черновики создаются существующими
  `ProductionRecipeService.CreateAsync` и `NewVersionFromAsync`. Последний — новая версия с составом из формы, одним сохранением; та же
  `ApplyAsync`-проверка и история.
- **Каталог склада** `procurement.Items`: сопоставление по `Sku`. Позиции не создаются и не меняются.
- **Linko** `linko.Products`: только `LinkoProductId` карты.
- **Задания, выдача, смены, выход полуфабриката** — без изменений.
- **История** — `ProcurementAuditLog`: у карт `recipe`, у загрузки `recipe_import`.

## 4. Добавленные API

`/api/production/recipe-imports`:

| Запрос | Что делает |
|---|---|
| `GET` | список загрузок |
| `POST` (multipart) | загрузить файл; тот же файл → `existing` |
| `GET {id}` | сводка и рецептуры |
| `GET {id}/recipes/{rid}` | построчная сверка, изменения в карте и в файле |
| `PUT {id}/recipes/{rid}` | код, Linko, «создавать» |
| `PUT {id}/lines/{lineId}` | позиция склада, решение, норма, причина |
| `POST {id}/map` | сопоставить артикул во всей загрузке |
| `GET {id}/missing` | артикулы без позиции склада |
| `POST {id}/rematch` | «Проверить заново» |
| `POST {id}/apply` | создать черновики |

Права — «Производство: рецептуры».

## 5. Миграции

`RecipeImport` — только 4 новые таблицы в схеме `production`:
- `RecipeImports` (уникальный SHA-256 файла);
- `RecipeImportRecipes`;
- `RecipeImportLines` (значения — `numeric` без ограничения разрядов);
- `RecipeImportItemMaps`.

Существующие таблицы не меняются, данные не удаляются.

сопоставления зависят от каталога: на сервере они будут другими, если каталог там полнее.

| Показатель | Значение |

| Листов | 16: рецептур — 11, без рецептур — 5 (скрытые выгрузки и заголовки) |
| Столбцов продуктов | 318; с составом — 312; пустых — 4; ещё 2 («Сечка» на «polufabrikati») — единственная норма записана текстом |
| Норм больше нуля | 6 205; нулей — 640; отрицательных («Отход Кекс», «Отход этикетка ва пакет») — 94 |
| **Рецептур обнаружено** | **318 (312 с составом)** |
| Готовы сразу | 6 |
| **Импортировано (черновики созданы)** | **6** — все готовые; проверено, что создаются точно по ячейкам |
| Нужна ручная проверка | 308 |
| **Компонентов сопоставлено** | **5 643 строки из 6 205 (90,9 %)** — точный артикул; артикулов 421 из 499 |
| Не найдено в каталоге | 78 артикулов, 562 строки; из них 28 — полуфабрикаты самого файла (глазури, начинки, киём 105-…, «РОЛЛЕР 89», сахарная пудра) |
| **Ошибки формул в книге** | **86:** #REF! 56, #DIV/0! 24, #VALUE! 4, #N/A 2 — все в строках итогов и цен (1–6), в нормах нет |
| Не числа в нормах | 12: 6 чисел текстом («25,542», «1 050,00», «0,15», «250», «0,86», «1 050»), 6 значений ИСТИНА («Маркировка помадка 476», «Pomadki») |
| Больше 6 знаков | 1: `=1000*1000/999` → 1001,001001001 («pudra» J9) |

**Почему 308 рецептур требуют ручной проверки** (рецептура может быть в нескольких строках):

| Причина | Рецептур |
|---|---|
| Компонента нет в каталоге склада | 277 — **271 только по этой причине** |
| Полуфабрикат не заведён позицией склада (для выхода) | 32 |
| Единица в Excel не указана (101-186 «Высоко олеиновое») | 15 |
| Текст или ИСТИНА вместо нормы | 11 |
| Один артикул в нескольких столбцах с разным составом или названием (105-048, 105-012, 101-005, 105-100, 069) | 10 |
| Норма больше 6 знаков, компонент дважды (101-123 на «polufabrikati» AD), продукт без артикула («СВЕТОШ ОК 270 гр») | по 1 |

Ещё не блокирует, но требует внимания:
- **Товар Linko:** 221 предложение по номеру артикула ждёт подтверждения; у 35 рецептур Linko не найден.
- **Названия:** у 151 рецептуры название в каталоге отличается от Excel (пробелы, «№ …») — для сведения.

Главное: когда полуфабрикаты и недостающие позиции будут заведены в каталоге склада (или сопоставлены вручную — это запоминается),
«Проверить заново» сделает готовыми до 271 рецептуры. Позиции импорт сам не создаёт — так требует задание.

## 12. Производственный цикл на импортированных картах

`Imported_cards_run_the_production_cycle_and_the_semi_finished_is_written_off_once`. Глазурь (полуфабрикат) и печенье с глазурью
импортированы из Excel, утверждены главным технологом. Дальше:

1. **Глазурь, 200 кг.**
   - Потребность по нормам на тонну: сахар 120, масло 80.
   - Выдача — сахар из партии с ближним сроком (FEFO).
   - Смена 198 кг, утверждена мастером; возврат 1 кг сахара в ту же партию.
   - Закрытие, «Оприходовать выход» — партия глазури 198 кг.
2. **Печенье, 500 кг.**
   - Потребность: мука 300, глазурь 150 (со склада, как сырьё), свой сахар 50, коробки 250 шт.
   - Сахара и масла глазури в задании нет.
   - Выдача, смена 500, закрытие — отклонений нет, перерасхода нет.
3. **Нехватка.** Задание на 1 000 кг печенья требует 300 кг глазури, на складе 48. Выпуск не запрещён.
4. **Движения склада.** Масло списано только в глазурь, сахар — 119 в глазурь и 50 в печенье. Глазурь: приход 198, выдача 150, остаток
   48. Двойного списания нет.
