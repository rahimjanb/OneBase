# OneBase — Universal Analytics Engine: аудит и план

Дата: 13.11.2026. Задание — «ONEBASE — UNIVERSAL ANALYTICS ENGINE». Итог работ — `ONEBASE_ANALYTICS_ENGINE_REPORT.md`.

## 1. Аудит: почему AI говорит «данных нет»

Данные есть построчно. У каждой строки заказа Linko есть:
- дата принятия (по ней считается продажа);
- филиал, агент, торговая точка;
- товар → тип Linko → категория отчёта.

Возвраты тоже построчные. Срез отсутствовал не в базе, а в инструментах:

| Инструмент | Что умеет | Чего не умеет | Почему |
|---|---|---|---|
| `get_sales_period`, `get_sales_days` | Дни, недели, месяцы; республика, направление, регион, агент | Товар, категория, точка | Читают объект месяца `SalesAnalytics` (`RouteSplit`): в нём нет разреза по товарам |
| `get_sku_sales` | Товар, категория, регион, ABC | Дни и недели | SQL `SalesHistoryReader.SkuSalesAsync` сворачивает строки до месяца (`date_trunc('month')`). Нет точек-каналов. Итоги — только по настроенным категориям |
| `get_sales`, `get_sales_by_branch`, `get_sales_trend`, `get_products` | Месяц по регионам, план, прогноз | Любой шаг меньше месяца | Кэш месяца `sales:{y}-{m}:Rop` |
| `analytik_query` (Аналитик) | Любые таблицы по плану | Правила вторички | Модель сама выбирает таблицы и колонки и не знает статусов, дат, возвратов, каналов и категорий |

**Регион считается по-разному.** `get_sales`, `get_sku_sales`, `analytik_query` относят продажу к филиалу заказа. `get_sales_period` — к «домашнему» региону агента (по наибольшей выручке).

**Права.** Для пользователя с областью (РМ, СВР, агент) инструменты продаж консультанта закрыты целиком (`UserPermissions.LimitSalesAsync`). Область учитывает только Аналитик (`AnalytikAccess`).

### Матрица возможностей

| Показатель | Источник | Детализация в базе | Доступность в AI до работ | Что требуется |
|---|---|---|---|---|
| Выручка (вторичка) | `linko.Orders` + `OrderLines` (статусы delivered/given, дата приёмки, сумма строки в сумах), минус `OrderReturnLines` (delivered, по дате создания) | Строка документа, день | Дни без товаров (`get_sales_period`); товары без дней (`get_sku_sales`) | Смысловой слой: показатель × любые измерения × шаг времени |
| Товарные группы | `linko.Products.TypeId` → `ProductTypes` (дерево) → категории отчёта `Sales:Categories` (`SalesCategories.Build`) | Строка | Только помесячно | Измерения `product_group` (категория отчёта) и `product_type` (тип Linko) |
| Регионы | `Orders.BranchId` → `sales.Regions.LinkoBranchId`. Старые филиалы — в текущем регионе. Точки-каналы (базар, сети) — виртуальные филиалы в закрытых месяцах. «Завод» — экспорт и опт, «К К Мерч» — вне продаж | Строка | Помесячно; разная привязка в разных инструментах | Одна привязка — по филиалу заказа, как на страницах продаж и в SKU |
| Продажи по дням | Дата приёмки (Ташкент) | День | Без товарных групп | Шаг day/week/month/quarter/year для любого среза |
| Остатки | `linko.ProductBalances` (шт, текущий снимок), склады `linko.Stocks` | Товар × склад, без истории | `get_outstock`, `analytik_warehouse` | Показатель «остаток» и дни запаса по скорости продаж. Истории остатков нет: `balances_by_date` Linko не загружается |
| Закупки | Сырьё — `procurement.*` (MRP `SupplyPlanner`); готовая продукция — Linko | Документ | `analytik_procurement_plan` | Готовая продукция: потребность «дни запаса × скорость − остаток». Сырьё — существующий план закупок |
| План продаж | `sales.RegionPlans` (Google Sheets / AI Data Manager, кг, регион × категория × месяц); `sales.StaffPlans` (Linko, агент × месяц, кг и сумма) | Месяц | `get_sales`, `get_region_plans` | План × факт × выполнение по регионам и категориям. По дням план не делится |
| Оплаты | `linko.Payments` | День, точка, агент | Аналитик (`analytik_finance`) | Показатель «оплаты» отдельно от выручки |
| Первичка | `linko.StockTransfers` + заказы «Завода» | День, склад | `get_primary_shipments` (месяц, регион по складу) | Остаётся у своего инструмента; в реестре — как доступная возможность |
| Производство, HR, снабжение | Свои схемы | — | Инструменты отделов | В реестре возможностей — с инструментом, который их отдаёт |

Источники:
- **Linko** — единственный источник фактов. Ключ строки — id Linko: повторная загрузка не дублирует, правка перезаписывает документ целиком, отмена — статус.
- **Google Sheets / AI Data Manager** — только планы регионов, P&L и дилерские реестры.
- **1С, Excel и CSV с фактами** — не подключены. Это фиксируется как отсутствующий источник, а не как «нет данных».

## 2. Архитектура

Новый слой встаёт над существующим «Аналитиком» и не дублирует его. Таблицы читаются через тот же `IAnalytikSql`: транзакция только на чтение, `statement_timeout`. Права — те же `AnalytikPrincipal` / `AnalytikAccess`. Журнал — тот же `analytik.Queries`.

```
вопрос → AI-аналитик (команда «Аналитик» или консультант)
       → analytics_capabilities (что есть: показатели, измерения, периоды, свежесть, какие инструменты отдают остальное)
       → analytics_query { metrics, dimensions, grain, period, filters, compare, sort, limit }
            SemanticEngine:
              QueryPlanner     — нормализация, имена → id (регион «Самарканд», группа «Кекс»), проверка совместимости
              SourceResolver   — показатель → факт (продажи / планы / оплаты / остатки) и источник по настройке
              SqlCompiler      — параметризованный SQL по белому списку измерений (модель SQL не пишет)
              IAnalytikSql     — READ ONLY, таймаут, лимиты; журнал analytik.Queries
              Normalizer       — id → названия, нулевые дни для графиков (по запросу), без интерполяции
              Calculator       — доля, средний чек, цена кг, выполнение плана, отклонение, сравнение периодов, рейтинг
              EvidenceValidator— период и данные по, шаг, несопоставленные регионы и товары, другая валюта, обрезка, итоги
       → ответ модели только по числам результата; ссылка «Открыть срез» → /analytik/explore
```

**Код:**
- `OneBase.Application/Analytik/Semantic`:
  - `AnalyticsQuery` — контракт;
  - `SemanticCatalog` — реестр показателей и измерений, он же статическая часть DataCapabilityRegistry;
  - `SalesFactSql` — факт продаж по правилам вторички;
  - `SemanticCompiler`, `SemanticEngine`, `EvidenceValidator`, `SemanticCalc`;
  - `CapabilityRegistry` — реестр плюс свежесть и диапазоны данных.
- `OneBase.AI/Analytik/SemanticTools.cs` — инструменты `analytics_query` и `analytics_capabilities`, новый источник знаний `analytics.slices`. Он есть у консультанта и у аналитиков.
- `OneBase.Api/Controllers/AnalytikExploreController.cs` — `/api/analytik/explore/*`: возможности, запрос, Excel.
- Фронтенд: `/analytik/explore` («Срезы») — конструктор, интерактивная таблица, график, сравнение, переход вглубь, CSV и Excel, источник и время синхронизации.

### Контракт `AnalyticsQuery`

```json
{ "metrics": ["revenue", "kg"], "dimensions": ["date", "product_group", "region"], "grain": "day",
  "dateFrom": "2026-08-01", "dateTo": "2026-11-11", "filters": [{ "dimension": "region", "op": "in", "values": ["Самарканд"] }],
  "compare": "previous", "sort": [{ "by": "revenue", "dir": "desc" }], "limit": 500, "includeTotals": true,
  "fillZeros": false, "segment": "secondary", "planKind": "rop", "tenant": "onebase" }
```

### Показатели (Metrics Engine)

| Факт | Показатели |
|---|---|
| Продажи (вторичка) | выручка нетто, валовая выручка, возвраты, скидки, кг нетто, кг заказов, кг возвратов, единицы, заказы, АКБ (точки с чистым весом > 0), средний чек, цена кг, доля, выручка в другой валюте (исключена) |
| План | план кг (регионы: Sheets/OneBase; агенты: Linko), план суммы (агенты, Linko), выполнение %, отклонение, прогноз выполнения (темп месяца) |
| Оплаты | оплаты (Linko, принятые, без удалённых, в сумах) |
| Остатки | остаток (шт, снимок), дни запаса, потребность до N дней запаса |

У каждого показателя в реестре:
- формула и источник;
- единица измерения;
- допустимые измерения и шаги;
- право доступа;
- ограничения качества.

Выручка, отгрузка (первичка) и оплаты — разные показатели и не смешиваются.

### Измерения

Время:
- `date` — шаг day, week, month, quarter, year.

Оргструктура:
- `region` — по филиалу заказа;
- `branch` — филиал Linko;
- `direction` — направление: РМ или канал;
- `manager` — РМ направления;
- `supervisor` — СВР региона;
- `dealer` — дилер, он же контрагент;
- `sales_channel` — регионы, каналы (базар, сети) или «Завод» (экспорт и опт).

Торговля:
- `agent`;
- `market` — торговая точка, она же клиент;
- `market_type`.

Товары:
- `product`, `sku`;
- `product_group` — категория отчёта;
- `product_type` — тип Linko;
- `stock` — склад.

Прочее:
- `source`.

Сочетания измерений любые — одним SQL, без отдельной точки доступа на каждое сочетание.

## 3. Источники и дедупликация

1. **Факты продаж и оплат — Linko.**
   - Ключ строки — id Linko. Повторная загрузка — upsert.
   - Правка документа: строки удаляются и вставляются заново в одной транзакции.
   - Отменённый документ — статус `cancelled`, в выручку не входит.
   - Удаления заказов Linko не присылает — это ограничение источника, оно записано в реестре.
2. **Планы.**
   - Регионы — `sales.RegionPlans`: Google Sheets / AI Data Manager, владелец поля — `FieldOwnership`.
   - Агенты — Linko `staff_balance`.
   - Какой план показывать — настройка `Analytik:Semantic:PlanSource`: auto (как в «Продажах»: есть план регионов на месяц — он, иначе сумма планов агентов), regions, agents.
   - План и факт не складываются: план — свой показатель, выполнение считает калькулятор.
3. **Происхождение.** У каждого результата:
   - источники (система, таблицы, время последней загрузки);
   - правила (статусы, даты, возвраты, валюта, каналы, исключённые филиалы);
   - журнал запроса (`analytik.Queries`).
4. **История загрузок Linko.**
   - Новая таблица `linko.SyncRuns`: режим, начало и конец, статус, строки и ошибки по шагам, самая ранняя изменённая дата.
   - Пишет её координатор синхронизации.
   - Хранится 90 дней.

Отдельные таблицы FactSales, FactSalesDaily и материализованные представления **не создаются**:
- `linko.*` — уже нормализованная копия источника с его ключами;
- самый тяжёлый срез (день × филиал × тип со счётом заказов и точек) на копии рабочей базы считается за 0,3 с на 3 месяца и за 1,1 с на 12 месяцев (EXPLAIN ANALYZE);
- копия данных означала бы второй источник правды и задержку обновления.

Если объём вырастет в разы — следующий шаг: дневная свёртка «день × филиал × агент × точка × товар», которую обновляет синхронизация.

## 4. Права и безопасность

- **Права показателей:** продажи — `sales.read`, оплаты — `finance.read`, остатки — `sales.read`.
- **Область пользователя** — предикатом в SQL, как в движке Аналитика:
  - регион — филиалы своих регионов со старыми;
  - агент — свой `AgentId`.
- **Консультант:** для пользователя с неполной областью продажи закрыты, как сейчас (`LimitSalesAsync`). Срезы с областью — у команды «Аналитик».
- **SQL** строит сервер из белого списка измерений и показателей; значения — только параметры; модель SQL не пишет.
- **Tenant:** база однопользовательская (одна компания). Запрос с чужим `tenant` отклоняется, `tenant` пишется в журнал.
