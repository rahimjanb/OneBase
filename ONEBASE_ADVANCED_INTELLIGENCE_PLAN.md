## 2. Gap Analysis по модулям

Обозначения: **Есть** — реализовано и проверено; **Частично** — работает, но не так, как требует ТЗ; **Нет** — отсутствует.

| № | Модуль | Есть | Частично | Нет | Доработка | Как проверим |
|---|---|---|---|---|---|---|
| 1 | Deep Reasoning | Маршрутизация вопроса между аналитиками, параллельный запуск | Один проход «аналитики → сводка»: нет плана, подзадач с зависимостями, промежуточных результатов, перепланирования | InvestigationPlan / Step / Context / Evidence / Status / Result, execution trace | Движок исследований поверх `AgentOrchestrator`: план (модель) → шаги волнами по зависимостям → противоречия → перепланирование → проверка → ответ. Трасса в `analytik.Investigations` | DB-тесты со сценарной моделью: план из N шагов, зависимости, повтор шага, перепланирование, трасса |
| 2 | Multi-Hypothesis | Поле «гипотезы» у находок и в ответе | Гипотезы — текст модели, статус не проверяется | Подтверждающие / опровергающие данные, влияние, уверенность, статус | Гипотеза = формулировка + проверка вычислением. Статус (Confirmed / PartiallyConfirmed / Rejected / Inconclusive) ставит **код** по результату теста, модель его не меняет | Юнит-тесты правил статуса; тест: «причина» без подтверждения в ответе → отклонено проверкой |
| 3 | Causal Intelligence | Граф зависимостей симулятора, разложение аномалий продаж по регионам | — | Driver / Contribution, лаг, до/после, когорты, контрольная группа (DiD), чувствительность; класс вывода | Детерминированные методы + класс каждого вывода: наблюдаемая зависимость / статистически подтверждённая / проверенная причинная гипотеза / предположение | Юнит-тесты на данных с известным ответом |
| 4 | Adaptive Tools | Параллельные вызовы, повтор упавшего инструмента, «уже вызвано», структурные сбои с советом | Повтор неудачного вызова с теми же аргументами выполняется заново; ошибка среза — текст без исправленного запроса | Граф зависимостей инструментов, исправление запроса, защита от зацикливания | Граф шагов исследования; Query Repair у `analytics_query` (исправленный запрос в ответе); память неудачных вызовов; лимит неудач одного инструмента | Тесты `AgentRunner`: повтор неудачного вызова не выполняется, третий сбой инструмента закрывает его |
| 5 | Computation Engine | Прогноз (6 методов), аномалии, MRP, страховой запас, точный калькулятор | Методы разбросаны, расчёт не сохраняется с входом и версией | Статистика, регрессия, ряды, ABC/XYZ, RFM, когорты, кластеры, оптимизация, EOQ / ROP, журнал расчётов | `Application/Analytik/Compute`: все методы чистым кодом; инструмент `analytik_compute` берёт данные только через движок срезов (с правами), сохраняет вход, алгоритм, параметры, версию, результат, период, источники, ограничения в `analytik.Computations` | Юнит-тесты каждого метода на эталонных числах; DB-тест: расчёт воспроизводится из записи |
| 6 | What-If | Движок сценариев, 40 параметров, базовый / оптимистичный / пессимистичный, сравнение, история | — | Матрица чувствительности, торнадо, точка безубыточности, Goal Seek, ограничения оптимизации, Монте-Карло | `ScenarioAnalysis` поверх чистого `ScenarioEngine.Run` (тот же снимок данных); инструмент и API; исходный сценарий не меняется | Юнит-тесты: безубыточность совпадает с формулой, Goal Seek попадает в цель, Монте-Карло воспроизводим (seed) |
| 7 | Reviewer | Проверка чисел кодом, одна попытка исправить, переход на сильную модель | Проверяются числа, но не период, источники, формулы, логика, причинные утверждения | Независимая проверка с возвратом на этап | Reviewer: правила кода (период, источники, пересчёт расчётов, причинный язык, альтернативные гипотезы, ограничения) + скептик-модель для сложных выводов. | 8 | Expert Analytics | Продажи, план, MRP, DSO, P&L дилеров, посещаемость | Методы есть не у всех отделов | RFM, ABC/XYZ, churn, unit economics, EOQ, оборачиваемость, aging, производительность | Реестр методов отделов с требованиями к данным; доступность — по реальным данным. ## 3. Архитектура (без дублей)

```
AnalytikEngine (чат «Аналитика»)
  ├─ простой вопрос → как сейчас: AiRouter → AgentOrchestrator → GroundedComposer           (без изменений)
  └─ сложный вопрос (InvestigationTriage) → InvestigationEngine
        Planner (модель, JSON)        → цель, подзадачи с зависимостями, гипотезы с проверкой
        шаги волнами                  → AgentOrchestrator / AgentRunner (те же аналитики, инструменты, права, проверка чисел)
        Statistician                  → analytik_compute (код) — гипотезы проверяет вычисление, статус ставит код
        Contradictions (код)          → одинаковый показатель за тот же период с разными значениями, конфликт статусов
        Replan (модель, ≤ 1 раза)     → альтернативные источники по реестру возможностей, проверочные шаги
        Skeptic (модель, только глубокое) → альтернативные объяснения и возражения → новые гипотезы на проверку
        Reviewer (код + модель)       → период, источники, пересчёт, причинный язык, ограничения → возврат на этап
        Decision Advisor (Chief Analyst) → ответ: вывод, гипотезы со статусами и классом вывода, рекомендации
        трасса                        → analytik.Investigations (план, шаги, гипотезы, противоречия, проверки, метрики)
Compute (Application/Analytik/Compute)   — статистика, регрессия, ряды, сегменты, причинные методы, запасы, оптимизация
ScenarioAnalysis (Simulation)            — чувствительность, безубыточность, Goal Seek, Монте-Карло поверх ScenarioEngine
RiskEngine → AutoInvestigator            — расследование находки кодом, история analytik.InsightEvents
Decisions                                — analytik.Decisions + оценка в срок (AnalytikWorker)
Benchmark                                — каталог сценариев, регрессия в тестах, живой прогон по разрешению
Quality                                  — сводка по трассам, журналу AI и журналу запросов
```

Правила:
- Все числа — из инструментов и кода; модель планирует, формулирует гипотезы и пишет текст, но не считает и не ставит статусы.
- Данные для расчётов — только через движок срезов и сервисы отделов с правами пользователя; модель не передаёт числа в расчёт сама.
- Простые вопросы идут прежним путём — ни одного лишнего вызова модели.
- Новые таблицы — только добавление; миграции идемпотентные; данные не удаляются.
- Платные вызовы при разработке — только сценарная модель в тестах.
