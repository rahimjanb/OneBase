# OneBase — закупка сырья: отдельный тип заявки и маршрут «аналитик / финансист» — аудит и план

Дата: 08.11.2026. Основа — `d88d1f4`.

## Что сейчас

- **Тип заявки не выбирается.** Маршрут сырья включается флажком «Маршрут закупки сырья» в «Настройки → Отделы → Снабжение» (по умолчанию
  выключен). При отправке он выбирается сам, если к закупке есть позиция категории «сырьё». Смешанная заявка тоже идёт маршрутом сырья.
- **Маршруты:**
  - сырьё — руководитель снабжения → директор, при любой сумме;
  - обычная закупка — руководитель отдела → финансист → директор, если сумма к закупке больше лимита.
- **Кто есть кто:**
  - финансист — один человек, выбранный в настройках снабжения;
  - аналитика нет ни как роли, ни как места в маршруте;
  - снабженцы — право «Снабжение: обработка заявок» (роль «Снабжение»).
- **Создавать заявки** может любой с правом «Свои заявки на закупку» — это почти все роли отделов.

## Решения (08.11.2026)

- **Два типа заявок**, выбирается при создании: «Обычная закупка» и «Закупка сырья». Это отдельные заявки.
- **Заявку на сырьё создают** только финансист (из настроек), аналитики (новая роль «Аналитик») и снабженцы.
- **Маршрут сырья — по автору, по умолчанию без директора.** После последнего шага заявка утверждена и уходит в снабжение («К закупке»).

| Автор | Шаги по умолчанию |
|---|---|
| Снабженец | аналитик → финансист |
| Аналитик | финансист |
| Финансист | аналитик |

- **Маршрут настраивается:**
  - где: «Настройки → Отделы → Снабжение → Маршрут закупки сырья»; меняют те, кто сейчас настраивает снабжение;
  - что: для каждого автора — свои шаги по порядку из «аналитик», «финансист», «директор», «директор, если сумма больше лимита»
    (лимит — тот же, что у обычных закупок);
  - заявки, которые уже в пути, идут маршрутом, с которым были отправлены.
- **Аналитик** — новая роль «Аналитик»: шаг согласует любой с этой ролью.
- **Обычные закупки** — без изменений (руководитель отдела → финансист → директор, если сумма больше лимита).

## Как сделаю, если не скажете иначе

- **Автор в нескольких группах** (например, снабженец с ролью «Аналитик») — берётся первая подходящая: финансист, затем аналитик, затем
  снабженец.
- **Свою заявку не согласует никто:**
  - в строке автора нельзя выбрать его собственный шаг (у аналитика — «аналитик», у финансиста — «финансист»), у строки — хотя бы один шаг;
  - если автор и с ролью «Аналитик», и снабженец, шаг аналитика решают другие аналитики; если их нет, заявка ждёт, а тем, кто
    настраивает снабжение, приходит предупреждение (как сейчас с руководителем снабжения);
  - если автор — директор маршрута, шаг директора пропускается.
- **Состав:** в заявке на сырьё — только позиции категорий с флажком «сырьё», в обычной — без них. Тип можно сменить, пока заявка в
  черновике или на доработке. Если закупать нечего (всё есть на складе), заявка на сырьё всё равно идёт своим маршрутом.
- **Настройки:** флажок «Маршрут закупки сырья» и выбор «руководителя снабжения» заменяет таблица шагов по авторам; маршрут сырья
  действует всегда, когда тип заявки — «Закупка сырья». Заявки сырья, уже отправленные по старому маршруту (ждут руководителя снабжения или
  директора), доходят по-старому.
- **Повторное согласование** после существенной правки утверждённой заявки сырья — с первого шага её маршрута.
- **Роль «Аналитик»** (создаётся при запуске):
  - свои заявки, в том числе на сырьё;
  - видит отправленные заявки на сырьё, «Заявки → Согласования» — свой шаг;
  - права «Снабжение: обработка заявок» у неё нет.
- **Уведомления:**
  - аналитикам — когда заявка на их шаге;
  - финансисту — когда на его шаге (раньше по сырью он получал только уведомление);
  - снабжению — об утверждённой заявке, как сейчас.
- **Миграция — только добавление:**
  - у заявки — тип (по умолчанию «обычная»; у отправленных маршрутом сырья — «сырьё») и шаги, с которыми её отправили;
  - в настройках снабжения — шаги маршрута сырья по авторам (по умолчанию — таблица выше).

  Применить её на локальной базе (перезапуск API) — только с вашего разрешения.

## Этапы

Каждый этап — отчёт, сборка, тесты и проверка.

1. **Сервер:**
   - тип заявки, роль «Аналитик», маршрут по автору из настроек (шаги запоминаются в заявке при отправке);
   - проверки: кто может создать заявку на сырьё, состав позиций;
   - уведомления, повторное согласование, статус «Ожидает аналитика» (в том числе в AI-инструменте заявок и аналитике производства);
   - миграция;
   - тесты: правила маршрута на все случаи из таблицы и крайние; сквозной тест на базе — от создания до утверждения.
2. **Интерфейс:**
   - выбор типа в «Новой заявке» (сырьё — только тем, кому можно), подбор позиций по типу;
   - «Ожидает аналитика» в маршруте заявки и в «Согласованиях»;
   - настройки снабжения — таблица шагов маршрута сырья по авторам вместо флажка;
   - узбекский;
   - инструкция `docs/guide/raw-materials.md` и `docs/procurement-materials.md`.
3. **Проверка** на локальной базе (только чтение до разрешения на миграцию) и итоговый отчёт.
