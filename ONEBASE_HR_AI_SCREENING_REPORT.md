# AI Candidate Screening (HR → Подбор → AI-скрининг) — итоговый отчёт

Задание — `prompt` «OneBase AI Candidate Screening — интеллектуальный анализ кандидатов HeadHunter» (14.11.2026). Модуль сделан на
существующем подборе OneBase (единая база кандидатов, HH.uz, разбор резюме, очередь заданий, собеседования), без отдельного приложения,
без второй системы AI (тот же шлюз `IAiGateway`) и без дублей сущностей.

## 1. Что реализовано

**Аудит существующего HR (было до задания):**
- вакансии, единая база кандидатов: дедупликация по `(Source, ExternalId)` и подтверждённым контактам, по имени — никогда;
- резюме в MinIO; текст из PDF/DOCX/DOC/RTF/ODT/TXT, OCR фото; разбор AI с проверкой цитат;
- оценка AI 0–100 (критерии вакансии по 10 баллов);
- собеседования, AI-рекрутер в Telegram, исключения HR;
- HH.uz: OAuth, синхронизация откликов, действия по отклику;
- очередь заданий в PostgreSQL (`recruitment.Jobs`; Hangfire/Quartz в OneBase нет);
- права «Подбор: просмотр / управление».

OneBase — одна компания на одну базу: арендаторов в схеме нет. Изоляция — права подбора и проверки в сервисах.

**AI Screener** (`CandidateScoring` — заменил прежнюю оценку, тот же интерфейс `ICandidateScorer`):
- шесть критериев с весами: опыт 25, навыки 25, требования вакансии 20, достижения 15, образование 10, преимущества 5;
- по каждому критерию: статус (`met` / `partial` / `not_met` / `not_stated`), баллы, объяснение, 1–3 дословные цитаты;
- баллы и итог считает сервер (`ScreeningRules`):
  - цитаты проверяются по тексту резюме, переписки, заметок и ответов на вопросы отбора;
  - нет подтверждённой цитаты — балл не выше половины веса: высокий рейтинг без фактов невозможен (без единого факта — максимум 50);
  - «Не указано в резюме» — нейтральная половина веса: отсутствие сведений — не минус;
- категории 90 / 80 / 70 / 50 и код рекомендации (`strong_match` … `low_match`) — из итога на сервере;
- сводка, «почему подходит», сильные и слабые стороны, недостающие требования, рекомендация AI, 5–10 вопросов для собеседования
  (технические, практические, по опыту, проверка достижений, по пробелам);
- уверенность модели (`confidence`) — отдельное поле, на оценку не влияет; рядом — «подтверждено фактами» (доля веса с цитатами);
- защищённые признаки (дата рождения, возраст, пол, семейное положение, дети, национальность, религия — ru/uz/en) скрываются в тексте
  до отправки модели; фото и пол из HH не берутся; модели прямо запрещено их учитывать;
- свои критерии вакансии — дополнительные требования к критерию «Соответствие требованиям вакансии»;
- каждый анализ — новая строка: версионирование и история рейтинга с изменением к прошлому.

**Карточка кандидата → «AI-анализ»:**
- кольцо рейтинга, категория, рекомендация, «почему подходит»;
- критерии полосами с доказательствами (подтверждённые — с галочкой, ненайденные — «не засчитано»);
- сильные и слабые стороны, недостающие требования, вопросы;
- история рейтинга, ссылка на профиль hh.uz, дата анализа;
- статус скрининга и «Проанализировать» — для HR.

Полное резюме, документы, контакты и история отклика — в той же карточке, как раньше. В истории видны и отметки скрининга.

**Статусы:** «Новый», «Анализируется», «Подходит», «Рекомендован», «На собеседовании», «Отказ», «Принят на работу», «В резерве».
- статус = этап отклика + отметка HR (`Applications.Mark`), расчёт — `ScreeningRules.Status`;
- «Анализируется» ставит очередь: анализ в очереди или резюме в обработке;
- отметки ставит только HR, AI статус не меняет (совет, не решение); любая смена этапа отметку снимает;
- «Отказ» — с обязательной причиной;
- «В резерве» — только с действующим согласием кандидата: отклик остаётся открытым, данные не удаляются по сроку хранения.

**Экран «AI-скрининг»** (`/hr/recruitment/screening`, новая кнопка в разделах подбора):
- полоса HH: подключение, синхронизация, бесплатные запросы и заблокированные платные операции за 30 дней, предохранитель;
- панель: кандидатов, проанализировано, подходящих (AI от 70), рекомендованных (отметка HR), ожидают анализа;
- вакансии: требования, найдено, подходящих, средний рейтинг, последняя синхронизация HH;
- кандидаты — карточками или таблицей:
  - сортировка: рейтинг, новые, стаж, имя;
  - фильтры: должность, стаж, навык, город, статус, рейтинг — в адресе страницы;
- импорт резюме: файлы (несколько сразу), текст, ссылка на профиль;
- «Проанализировать ожидающих»: очередь, до 50 за раз, с подтверждением — платные вызовы;
- выбор до 5 кандидатов одной вакансии → сравнение.

Раскладка — по ширине области содержимого; проверено на 1440, 900, 390.

**Сравнение** (`CandidateComparer`):
- таблица строится на сервере из анализов: опыт, навыки, достижения, образование, зарплата, сильные и слабые стороны, соответствие,
  рейтинг;
- AI даёт аргументированную рекомендацию, порядок и вывод по каждому;
- ID в ответе модели сверяются с выбранными;
- сохраняется (`CandidateComparisons`) и удаляется вместе с данными любого кандидата из сравнения.

**Ручной импорт:**
- PDF, DOCX, DOC, RTF, ODT, TXT, фото — тем же конвейером, что резюме из Telegram;
- текст;
- ссылка на профиль: HH — источник `hh` с ID резюме, другая — `other`;
- дедупликация: тот же файл (SHA-256) — тот же кандидат; тот же профиль HH — тот же кандидат; дальше — дубли по контактам, как раньше;
- по ссылке резюме не скачивается: HR загружает файл.

**Автоматизация:**
- синхронизация HH раз в 15 минут — как раньше, через Quota Guard;
- новые резюме разбираются и анализируются в фоне (очередь PostgreSQL: идемпотентный ключ, до 3 повторов с паузой, аренда, по 2 задания);
- анализ из очереди скрининга кандидату ничего не отправляет: без автоприглашения;
- ошибка видна в списке как «Анализ не выполнен» с причиной;
- остановить синхронизацию — кнопка на странице HH.uz.

## 2. Какие API HH бесплатны

Аудит 14.11.2026 по спецификации https://api.hh.ru/openapi/specification/public и статьям hh.ru/article/31102 (22.12.2022),
hh.ru/article/28570, условиям https://dev.hh.ru/admin/developer_agreement. Каталог — `HhOperations` (в интерфейсе — «HH.uz → Quota Guard»).

| Операция | Стоимость | Как вызывается |
|---|---|---|
| `POST /token` (вход, обновление токена) | бесплатно | авто и вручную |
| `GET /me` | бесплатно | авто и вручную |
| `GET /employers/{id}/vacancies/active` | бесплатно | авто и вручную |
| `GET /negotiations/response` (отклики на свои вакансии) | бесплатно: с декабря 2022 работа с откликами не требует покупки услуг | авто и вручную |
| действие по существующему отклику из `actions[]` (пригласить, отказать) | без списания | только кнопкой HR и без текста сообщения |

## 3. Какие API заблокированы

| Операция | Почему |
|---|---|
| `GET /resumes/{id}` — резюме откликнувшегося | контакт не списывается, но расходуется дневной лимит просмотров (500/сутки); для вакансий с оплатой за отклик стоимость не подтверждена |
| `GET /resumes` — поиск по базе | без услуги — лимит 50 просмотров в сутки, открытие контактов платное; бесплатного доступа ко всей базе нет |
| ссылки контактов из `resume.actions` | списание контакта |
| сообщение кандидату через HH (`message` в действии, `/negotiations/{id}/messages`) | запрещено правилом; методы переписки устарели |
| `POST /negotiations/phone_interview` — приглашение без отклика | списание контакта, нужен доступ к базе |
| `GET /resumes/{id}/negotiations_history` | требует платного доступа |
| остатки услуг и лимитов (`limits/resume`, `method_access`, `payable_api_actions`) | бесплатность прямо не подтверждена — не вызываются |
| всё, чего нет в каталоге | стоимость неизвестна |

Перед каждым запросом Quota Guard проверяет:
1. операция есть в каталоге и бесплатна;
2. разрешена этим способом (авто или кнопкой HR);
3. не стоит предохранитель;
4. не превышен суточный предел OneBase (2000 запросов, пауза 250 мс между запросами);
5. данные HH можно передавать AI — флаг `AiOnHhData`, см. п. 8.

Заблокированный запрос в HH не уходит и пишется в журнал (`HhApiCalls`). Ответ HH о деньгах или лимитах (`api_access_payment`,
`view_limit_exceeded` и т. п.) ставит предохранитель: автоматическая синхронизация в HH не ходит, пока HR не нажмёт «Проверить снова».

**Изменение поведения:** синхронизация раньше загружала резюме каждого нового отклика (расходовала лимит просмотров). Теперь кандидат
заводится по бесплатным полям списка откликов: имя, должность, город, зарплата, стаж, ссылка на hh.uz. HR открывает резюме на hh.uz и
загружает файлом.

## 4. Подтверждён ли нулевой расход платных лимитов

- **В коде — да:** каждый вызов HH идёт через Quota Guard. Методы, расходующие услуги или лимиты, не вызываются ни автоматически, ни
  кнопкой.
- **Тест на подставном HH:** запросов к `/resumes` нет, попытки записаны как заблокированные, сообщение в действии заблокировано до
  отправки, ответ «нужна оплата» останавливает синхронизацию.
- **На настоящем аккаунте HH не проверялось** (на стенде нет приложения dev.hh.ru и токена). Не подтверждено документацией:
  - отдают ли сейчас какие-то аккаунты `api_access_payment` на список откликов;
  - действуют ли условия hh.ru для hh.uz.

  Если HH так ответит — сработает предохранитель, ничего не спишется.

## 6. API endpoints

`/api/hr/recruitment/screening`:
- `GET /` — экран; фильтры: `vacancyId`, `status`, `minScore`, `city`, `skill`, `minExperience`, `position`, `search`, `sort`;
- `GET candidates/{id}` — анализы кандидата и история рейтинга;
- `POST applications/{id}/analyze` — анализ сейчас (лимит частоты `ai`);
- `POST queue` — в очередь: выбранные или ожидающие, до 50;
- `POST applications/{id}/status` — статус скрининга;
- `POST import/file` (multipart), `POST import/text`, `POST import/link`;
- `POST compare` — сравнение 2–5 кандидатов;
- `GET vacancies/{id}/comparisons`, `GET comparisons/{id}`.

`/api/hr/recruitment/hh`:
- `GET guard` — каталог, счётчики, журнал;
- `POST guard/reset` — снять предохранитель.

Права: смотреть — «Подбор: просмотр»; менять, анализировать, импортировать — «Подбор: управление».

## 8. Ограничения и открытые решения

- ⚠️ **Передача данных HH в AI.**
  - Соглашение разработчика HH, п. 4.6, запрещает передавать полученные через сервис данные третьим сервисам.
  - Поэтому резюме, полученные через API HH, по умолчанию не уходят AI. Флаг на странице HH.uz включайте после подтверждения юриста.
  - Тот же вопрос — для файлов с hh.uz, которые HR загружает сам. Нужна оценка юриста; раньше в плане уже стоял вопрос о передаче
    резюме в Claude.
- ⚠️ **Резюме откликов через API** не загружаются: просмотр расходует дневной лимит (500/сутки). Если компания решит, что дневной
  лимит расходовать можно, — это одна строка каталога (`resume.view`).
- ⚠️ **Серверы в РФ.** По статье hh.ru/article/31102 интеграция API hh.ru возможна только с ИТ-решениями, чьи серверы находятся в РФ.
  Для hh.uz не подтверждено — нужно уточнить у HH.
- **Фото кандидата** не показывается: из HH его отдаёт только просмотр резюме (заблокирован), из PDF не извлекается. В карточке —
  инициалы. На оценку фото не влияет в любом случае.
- **Анализ на стенде** проверен подставной моделью в тестах. Настоящий вызов Claude не делался: это платный вызов, нужно разрешение.
- **Аналитика эффективности подбора** (этап 2) — прежний раздел «Аналитика». Отдельные метрики скрининга (точность рейтинга против
  найма) — не делались.
- **Прежние оценки** (версия 1) видны с пометкой «Прежняя оценка — проанализируйте заново». Порог приглашения `InviteMinScore`
  теперь сравнивается с новым итогом: для того же кандидата он обычно ниже прежнего — проверьте пороги вакансий.
