# OneBase — права пользователя по разделам отделов и настройкам: план

Дата: 09.11.2026.

## Задача

При создании или изменении пользователя выбирать:
- какие **настройки** ему доступны;
- в каких **разделах внутри отдела** он работает — не только видит, но и выполняет действия.

## Что есть сейчас

- **Разделы пользователя** (`User.Sections`, `UserSections`) — девять галочек верхнего уровня: продажи, финансы, HR, задачи, файлы,
  консультант, Sales Base, AI Data Manager, рассылки.
- **Итоговые права** = права роли без прав разделов плюс права отмеченных разделов. По ним работают меню, страницы, API и AI.
- **Снабжение, склад, качество, производство и настройки** выдаются только ролью. Отдельному сотруднику их не выдать и не убрать, не
  меняя роль для всех.
- **В пяти местах** сервер ищет «кому уведомление» или «кого назначить» прямо по ролям, мимо персональных разделов:
  - снабжение и склад;
  - ответственные за заказы;
  - мастера производства;
  - Linko;
  - лимиты AI.

## Решение

### Права (`User.Rights`, `UserRights`)

Новый список галочек — права в разделах отделов и настройках. `null` — как у роли. Существующие персональные разделы не меняются.

**Снабжение и склад:**
- свои заявки;
- все заявки и снабжение (с остатками склада) — просмотр;
- закупки: «к закупке», «Куплено», тендеры, поставщики;
- склад: приход, выдача, приезд машин, приёмка;
- качество сырья.

**Производство:**
- просмотр;
- задания на выпуск;
- технолог;
- ввод смен.

**Настройки:**
- пользователи и роли;
- настройки снабжения;
- интеграции и источники данных;
- AI;
- Telegram;
- продажи: оргструктура и цели;
- журнал ошибок.

**Как считаются права:**
- **Зависимости.** «Закупки», «Задания», «Технолог» и «Ввод смен» включают свой «просмотр».
- **Настройки продаж** работают только вместе с разделом «Продажи».
- **Итоговые права** = итог разделов, затем права из галочек вместо прав роли из этого списка.
- **Ограничение выдачи.** Выдать можно только то право, которое есть у вас самих. Свои права изменить нельзя.
- **Совпало с ролью** — хранится как «как у роли».

### Где применяется

- **Права пользователя:** вход, кэш прав, `/api/auth/me`, файлы отделов, задачи.
- **Кому уведомления** — по итоговым правам, а не по роли:
  - снабжение;
  - склад;
  - лаборатория;
  - ответственные;
  - мастера;
  - Linko;
  - лимиты AI.

### Интерфейс

В окне пользователя под «Разделами» — блок «Действия в разделах отделов» по группам и блок «Настройки».
- Роль подставляет свои галочки.
- Значки «как у роли» и «настроены вручную», кнопка «Как у роли».
- Подсказки о зависимостях.
- Недоступное вам — серое.

### Миграция

`UserRights` — один столбец `Rights text[]`, по умолчанию пустой («как у роли»). Данные не меняются.

## Проверка

- **Тесты расчёта прав:** зависимости, «как у роли», настройки продаж без раздела «Продажи», старые сохранённые разделы.
- **Тесты на базе** — сохранение и запреты:
  - выдать чужое право;
  - изменить свои права;
  - неизвестный код.
- **В браузере на учебной базе:**
  - директор отмечает кладовщику «Качество сырья» и убирает «Склад»;
  - у кладовщика меняются меню и действия;
  - уведомления приходят по новым правам;
  - открываются выданные страницы настроек.
