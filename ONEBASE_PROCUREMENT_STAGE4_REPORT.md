## Что сделано

### Часть A. Приёмка товара
Вкладка «Снабжение → Приёмка» состоит из двух частей:
- **заказы, которые ждут поставки** — просроченные сверху;
- **журнал приёмок** — черновики, подтверждённые и с открытыми претензиями, с поиском.

**Кладовщик:**
1. выбирает заказ («Принять товар» в списке или в карточке заказа);
2. видит по каждой позиции: заказано, получено, закрыто, ждёт поставки;
3. вводит, сколько **фактически пришло**;
4. указывает **брак** (из пришедшего) и **недостачу** против накладной;
5. пишет комментарий к позиции и ко всей приёмке;
6. прикладывает накладную или акт — файлы загружаются сразу после сохранения;
7. **подтверждает поступление**.

**Черновик и подтверждение.**
- Черновик склад не меняет.
- Подтверждение записывает приход:
  - документ `RC-` и строки журнала движений по цене заказа;
  - в заказе и заявке — «получено»;
  - статус заказа: «Поставлен частично» или «Поставлен».
- Подтверждённую приёмку не правят и не удаляют. Черновик можно удалить.

**Правила приёмки:**
- **Частичная приёмка:** у одного заказа может быть сколько угодно приёмок.
- **Принято на склад = пришло − брак.** Принять больше, чем ждёт поставки, нельзя — лишнее не принимается.
- **Брак и недостача** остаются за поставщиком: заказ продолжает их ждать.
- **Позиция заявки без карточки склада:** при приёмке кладовщик выбирает карточку с той же единицей или создаёт новую — название и категория подставляются из заявки.

**Что происходит с товаром:**
- Поступивший товар резервируется под заявку и сразу появляется «К выдаче».
- Выдача инициатору проводит заявку в «Выполнена».
- Позиция заявки получает статус «Поступила на склад».

**Претензии:**
- Строка с браком или недостачей — открытая претензия поставщику.
- Снабжение закрывает её решением: замена, возврат денег, уценка.
- Претензии видны в приёмке, заказе и карточке поставщика.

**Закрытие заказа:**
- **«Закрыть остаток»** (снабжение, причина обязательна): поставщик не довезёт. Недопоставленное перестаёт занимать часть «к закупке» и снова доступно для нового заказа. Заказ — «Поставлен», задача ответственного — выполнена.
- **«Закрыть заказ»:** только поставленный и без открытых претензий. Условие «оплачен» добавится вместе с финансами.

**Рейтинг поставщика** получил две новые составляющие:
- **«Без претензий»** — доля строк приёмки без брака и недостачи;
- **«Полнота поставок»** — доля заказанного, что поставлено по завершённым заказам.

«Сроки» теперь считаются по фактической дате поставки: поставлен позже ожидаемой даты — опоздание.

### Часть D. Связи, история, защита
**Цепочка переходов в интерфейсе:**
- заявка → согласование → заказ поставщику → приёмка → движение склада → выдача;
- в журнале движений у прихода по заказу — ссылки на приёмку и заказ;
- у приёмки — «Движения склада по приёмке».

**История.** Пишется отдельно по каждой сущности:

| Где | Что пишется |
|---|---|
| Приёмка | черновик, изменения, подтверждение, претензии |
| Заказ | каждая приёмка, закрытие остатка, закрытие заказа, просрочка поставки |
| Заявка | поступление на склад, недопоставка |
| Склад | журнал движений |

**Защита от повторной регистрации:**
- **ключ формы:** повторная отправка возвращает ту же приёмку;
- **версии строк (xmin)** документа, заказа и остатка;
- **повтор операции по свежим данным** при одновременной записи:
  - две приёмки, которые обе помещаются в заказ, проходят обе;
  - если не помещаются — проходит одна, вторая получает понятную ошибку.

Нарушение уникального индекса (резерв под ту же позицию, тот же ключ формы) теперь тоже повторяется, а не отдаёт пользователю ошибку. Это нашёл тест одновременного подтверждения.

**Ещё уведомления этапа 4:**
- **брак или недостача (претензия)** — ответственному, директору и руководителю снабжения;
- **заказ поставлен полностью** — директору и руководителю снабжения;
- **заказ закрыт с недопоставкой** — инициаторам, ответственному, директору, руководителю снабжения и кладовщикам.

**Как работают напоминания** (поставка завтра, просрочка, остаток ниже минимума):
- идут тем же фоновым проходом, что и напоминания «Задач» (`WorkTaskReminderWorker`): раз в 15 минут после 09:00 по Ташкенту, без нового бесконечного цикла;
- каждое уходит **один раз**: отметка ставится условным обновлением в базе;
- если дату поставки перенесли — придёт новое напоминание;
- если остаток вернулся к минимуму — отметка снимается.

«Руководитель снабжения» — руководитель отдела «Снабжение» в «Задачах». Администратор (техническая роль со всеми правами) в получатели «по праву» не попадает.

## API (`/api/procurement`, новое)
| Метод и путь | Что делает |
|---|---|
| `GET receipts/expected` | заказы, которые ждут поставки |
| `GET receipts?status=draft\|posted\|claims&q=` | журнал приёмок |
| `GET receipts/form?order=` | строки заказа для приёмки |
| `GET receipts/{id}` | карточка приёмки |
| `POST receipts`, `PUT receipts/{id}` | черновик или сразу подтверждение (`post: true`), ключ формы, версия |
| `POST receipts/{id}/post`, `DELETE receipts/{id}` | подтвердить; удалить черновик |
| `POST claims/{id}/resolve` | закрыть претензию решением |
| `POST orders/{id}/close-remainder`, `POST orders/{id}/complete` | закрыть остаток; закрыть заказ |

Дополнительно появились данные в существующих ответах:
- **карточка заказа:** приёмки, претензии, «закрыто» по позициям, даты «поставлен» и «закрыт»;
- **заявка:** «поступило»;
- **журнал движений:** заказ;
- **рейтинг поставщика:** новые составляющие;
- **навигация:** счётчик «ждут приёмки».

## Интерфейс
- **«Снабжение»:** новая вкладка «Приёмка» со счётчиком для кладовщика. Страницы: список, новая приёмка, черновик (форма), подтверждённая (карточка).
- **Карточка заказа:**
  - кнопки «Принять товар», «Закрыть остаток», «Закрыть заказ»;
  - блоки «Приёмки» и «Претензии поставщику»;
  - в позициях — «закрыто»;
  - вид документа «Платёжное поручение».
- **Карточка поставщика:** рейтинг из пяти составляющих, блок «Претензии».
- **Заявка:** в позициях «поступило»; статус «Поступила на склад».
- **Журнал движений:** ссылки «приёмка» и «заказ».
- **Телефон:** нижний бар не изменился.
- **Узбекский:** 95 строк интерфейса и 70 шаблонов текстов сервера.

## Миграция
`Procurement4_Receipts` — только добавления:
- **новая таблица** `ReceiptLines`: строки приёмки, CHECK на количества, претензия;
- **новые столбцы:**

| Таблица | Столбцы |
|---|---|
| `StockDocuments` | `OrderId`, `Status`, `PostedAt` |
| `PurchaseOrders` | `DeliveredAt`, `CompletedAt`, `DueSoonNotifiedFor`, `OverdueNotifiedFor` |
| `PurchaseOrderItems` | `ClosedQty` |
| `RequestItems` | `ReceivedQty` |

Существующие складские документы получают `Status = 'Posted'` значением по умолчанию — это добавление столбца, не изменение данных. Сгенерированный SQL проверен: только `ADD` и `CREATE`, ни одного `DROP`, `DELETE` или `UPDATE`. Миграция применена к локальной базе при запуске API.

**Тесты снабжения.** Новые `ProcurementReceiptDbTests` (5 тестов, временная PostgreSQL) и правила приёмки в `ProcurementRulesTests`. Проверяется:
- **черновик и подтверждение:** черновик склад не меняет; подтверждает только кладовщик;
- **частичные поставки** 62 (2 брака) + 40: на складе и в резерве 100; заказ «Поставлен», задача выполнена;
- **лишнее** (41 при ожидании 40) не принимается;
- **повторная регистрация:**
  - повтор формы с тем же ключом — та же приёмка, склад не удваивается;
  - два одновременных подтверждения 60 + 60 при 100 — проходит одно;
  - 50 + 30 — проходят оба, в один резерв;
- **претензии:** закрывает только снабжение и с решением; закрыть заказ с открытой претензией нельзя;
- **выдача** 100 инициатору → заявка «Выполнена»;
- **закрытие остатка** освобождает 40 для нового заказа; приёмка по закрытому заказу невозможна;
- **карточка склада** с другой единицей не подходит; принять без карточки нельзя; приёмка только с недостачей — претензия без прихода;
- **рейтинг:** претензии 50, полнота 100;
- **уведомления:**
  - о приёмке — инициатору, кладовщику;
  - о претензии — директору и руководителю снабжения;
  - «поставлен полностью» и «недопоставка»;
  - «завтра поставка», «просрочена» и «ниже минимума» — по одному разу, повторный проход не дублирует; снятие отметки, когда остаток вернулся к минимуму.
